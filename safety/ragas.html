Ragas 是一个装在你自己项目里的评测库：它的产品主轴是把「凭感觉看一下输出」换成有名字、可复跑的指标——LLM 评判指标加传统非 LLM 指标，再配上测试数据生成；与同大类的两份相比，它交付的不是基准登记册也不是任务运行时，而是指标与数据集这两件工件。

适合与不适合When to use it, when not to

适合：已经有 RAG 或 agent 应用、想在代码里对每次改动打分并留住结果、手上没有评测数据要先造测试集、需要把指标接进 LangChain / LlamaIndex 一类现有栈或接观测工具。 不适合：指望一条命令跑完公开基准并把结果当结论、需要沙箱与工具审批来约束模型行为、不愿为 LLM 评判付出额外的 API 调用与时间。

适合什么任务Best for

适合：给 RAG 或 agent 应用配 LLM 评判指标、没有测试数据要先造测试集、要在自己代码与 CI 里建「改动—评测—观察—迭代」的循环。 不适合：想要一条 CLI 批量跑公开基准登记册、要沙箱与工具审批这类运行时边界、不愿为评判模型付出 API 调用成本。

Fits: attaching LLM-judged metrics to a RAG or agent application, generating a test set when you have none, and building a change-evaluate-observe-iterate loop inside your own code and CI. Not a fit: expecting one command to run a public benchmark registry and treating its output as a conclusion, needing sandboxing or tool approval as runtime boundaries, or refusing the API-call cost of judge models.

  1. Settle the judging model first: the README example needs OPENAI_API_KEY, and before switching provider read the docs pages on LLM Providers and Customise models.
  2. pip install ragas; to start from a template, use ragas quickstart rag_eval -o ./my-project.
