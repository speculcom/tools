模型与开放条件Model & openness

守的是你在 Bedrock 上调的模型。官方支持页在册：护栏作用于 bedrock-runtime 的 InvokeModel / InvokeModelWithResponseStream / Converse / ConverseStream 调用；bedrock-mantle 端点不支持。 目录中多数模型可挂，嵌入、重排、语音与个别文本模型（页内列了具体清单）不行，挂了会报 ValidationException。 ApplyGuardrail 可脱离模型单独评内容，因此也能守 Bedrock 之外的应用。

It guards the models you invoke on Bedrock. The support page records that a guardrail applies to InvokeModel / InvokeModelWithResponseStream / Converse / ConverseStream on the bedrock-runtime endpoint, and that the bedrock-mantle endpoint does not support guardrails. Most catalogue models work; embeddings, rerankers, speech and a few text models listed on that page do not, and attaching a guardrail to them fails with ValidationException. ApplyGuardrail evaluates content on its own, so it also works for applications outside Bedrock.

运行位置Where it runs

托管云：区域 API + Bedrock 控制台。检测在 AWS 侧执行，Standard tier 使用跨区域推理。 官方页未在册任何本机/离线形态，护栏策略是云端资源（draft + version）。

Hosted cloud: regional APIs plus the Bedrock console. Detection executes on AWS's side, and the Standard tier uses cross-Region inference. No local or offline form is recorded on the official pages; a guardrail is a cloud resource with a working draft and versions.

本地文件Local files

不读写你的工作区文件：内容通过 API 或控制台测试窗口提交。官方 data-protection 页提示 不要把机密信息写进标签或 Name 等自由文本字段，因为那些可能进计费与诊断日志。

It does not touch your workspace files: content is submitted through the API or the console test window. The data-protection page warns against putting confidential information into tags or free-form Name fields, because those may end up in billing and diagnostic logs.

工具与扩展Tools & extensions

策略面在册：content filters（Hate / Insults / Sexual / Violence / Misconduct / Prompt Attack）、 denied topics、word filters、sensitive-information（PII 阻断或掩码，支持自定义 regex）、 contextual grounding checks、Automated Reasoning checks；还能用标签只评估用户输入的片段（该能力只在 SDK/API 侧）。

Policy surface on record: content filters (Hate / Insults / Sexual / Violence / Misconduct / Prompt Attack), denied topics, word filters, sensitive-information filters (PII blocked or masked, with custom regex), contextual grounding checks and Automated Reasoning checks. Tagging lets only part of the user input be evaluated, and that capability is exposed through the SDK / API rather than the console.

权限与限制Permissions & limits

数据保留是显式模式：none / default / aws_review /（legacy）provider_data_share / inherit， 按 project → account → model 默认解析。官方在册：模型提供方拿不到客户 prompt 与 completion； 被保留的内容最长 30 天且在 AWS 边界内；要求人工复核的模型在 none / default 下直接不可用。 IAM / SCP 可强制组织级 ZDR。合规证书明细本次未逐条核验，记为未知。

Retention is an explicit mode: none / default / aws_review / (legacy) provider_data_share / inherit, resolved as project then account then the model default. Recorded on the official pages: model providers get no access to customer prompts and completions; retained content is held inside the AWS boundary for up to 30 days; models requiring human review are simply unavailable under none or default. IAM and SCPs can enforce organisation-wide zero retention. Compliance certificate details were not verified item by item and are recorded as unknown.

适合什么任务Best for

适合模型主要就在 Bedrock 上、要把护栏挂进推理调用、又要有零保留与人工复核开关可治理的团队。 不适合需要自托管护栏（走本地库那条线）、要跨云统一护栏策略，或依赖中国区可用的场景。

Fits: teams whose models mostly live on Bedrock, who want the guardrail attached to the inference call itself, and who need governance switches for zero retention versus human review. Not a fit: teams needing self-hosted rails (the local-library line), one policy spanning several clouds, or anything depending on a mainland-China region.

能力边界Capability boundaries

档位差异是实质的：Standard tier 才支持代码内容里的危害检测、跨区域推理与 prompt leakage 检测， denied topics 的字符上限也从 200 提到 1000（tier 页在册）。Classic 只保英法西。 contextual grounding 的 Standard 档只在区域子集可用，在其他区域请求会直接校验失败。 Automated Reasoning checks 是另一套东西：拿逻辑规则校验模型回答，不等同于内容过滤。

The tier difference is substantive: only the Standard tier covers harm hidden inside code elements, cross-Region inference and prompt-leakage detection, and it raises the denied-topic limit from 200 to 1,000 characters (tier page on record). Classic keeps English, French and Spanish. Standard contextual grounding works in a region subset and fails validation elsewhere. Automated Reasoning checks are a separate thing: they validate model answers against logical rules, which is not the same as content filtering.
