适合与不适合When to use it, when not to

适合：凭据与非人身份已经成规模（多仓库 + CI + 容器 + 协作工具 + AI 助手），需要的是持续监测与事件闭环而不是扫一次； 需要 pre-commit/pre-push 与 IDE 侧的即时拦截；网络边界要求高时可以走 self-hosting 甚至 air-gapped 形态。 不适合：目标是「个人数据进模型前的算子必须跑在自己机器上」（那是 Presidio 那条约束）；只要一次性红队扫描留工程证据； 期望用密钥扫描器替代模型评测。

模型与开放条件Model & openness

它不守模型，也不接模型档位：主轴是凭据（secrets）与身份。与被测模型的关系只有两条在册面——官方文档导航列出 「GitGuardian MCP Server」，其页描述是把凭据安全能力带进 AI 编码助手；另一条是 ggshield 覆盖 IDE 与 pre-commit/pre-push 这些「代码写出来的地方」。可换的检测模型：不适用（它做的是模式匹配 + 有效性校验，不是模型评测）。

It neither guards a model nor offers model tiers: its main axis is credentials (secrets) and identity. Its relation to models under test has only two surfaces on record — the docs navigation lists a "GitGuardian MCP Server", whose page describes bringing secret security into your AI coding assistant, and ggshield, which covers the IDE and pre-commit/pre-push places "wherever code is written". Swappable detection models: not applicable, since it does pattern matching plus validity checks rather than model evaluation.

运行位置Where it runs

浏览器里的平台是主交互面（文档导航含 Platform / Secrets Detection / Internal Monitoring / Public Monitoring / NHI Governance / Endpoint Protection / Honeytoken，登录入口指向 dashboard.gitguardian.com），扫描与编排在 SaaS 侧； 同时存在两类本机面：ggshield「Scans run locally」（官方文档在册），以及 Self-Hosting 文档口径 「set up and run the GitGuardian platform on your infrastructure」，并明确列出 air-gapped 环境与 Kubernetes 两种安装形态。

The browser platform is the main interaction surface (the docs navigation covers Platform / Secrets Detection / Internal Monitoring / Public Monitoring / NHI Governance / Endpoint Protection / Honeytoken, and the login entry points at dashboard.gitguardian.com), with scanning and orchestration on the SaaS side. Two local surfaces also exist: ggshield — "Scans run locally" per the docs — and Self-Hosting, worded "set up and run the GitGuardian platform on your infrastructure", which explicitly lists air-gapped environments and two Kubernetes install shapes.

本地文件Local files

ggshield 在你机器上扫仓库、目录与 diff，输出格式文档在册（json / gitlab / sarif），命令面含 secret scan、diagnose、 ignore-display；平台侧接的是你的仓库、CI/CD、容器镜像仓库与协作工具（内部监测文档口径 「code repositories to container registries and collaboration tools」）。扫过的代码内容在厂商侧留存多久： 公开条款未逐条说明，进 unknowns。

ggshield scans repositories, directories and diffs on your machine, with documented output formats (json / gitlab / sarif) and commands secret scan, diagnose and ignore-display; the platform side connects your repositories, CI/CD, container registries and collaboration tools (internal monitoring docs: "code repositories to container registries and collaboration tools"). How long scanned code content is retained vendor-side: not addressed clause by clause in the public terms, moved to unknowns.

关机后的任务Tasks after shutdown

后台面是它的强项之一，但归属不同：平台侧持续监测（含公开 GitHub 监测与 incident 生命周期）， 本机侧则是提交前/推送前的即时拦截。SaaS 更新的节奏可在文档的 SaaS Releases 逐日回看 （当日在册最新为 2026-10-29 的团队同步条目）。

Background work is one of its strengths, but ownership differs: the platform monitors continuously (public GitHub monitoring plus the incident lifecycle), while the local side is the instant pre-commit/pre-push interception. SaaS change cadence can be re-read day by day in the docs' SaaS Releases (latest on record the same day: the 2026-10-29 team-sync entry).

Clause by clause with sources: the readable entry for account and data terms is the privacy policy on the site, where the retention sentence reads "Data collected when you request information or when you contact us is kept for two (2) years from our last contact.", and the transfer sentence reads "We may share your Personal Data with our US office, which is located outside of the EEA, in the US."; whether customer code or matched content is used for training is not mentioned, and the policy does not state the storage scope of customer code — both go to unknowns. Red line: the vendor's "600+ types of hardcoded secrets" is a count of secret types; this site never converts it into a blocking or coverage rate and never ranks it against PII tooling — the "Secrets never leave your perimeter" phrasing is only read in the self-hosted/perimeter context.

适合什么任务Best for

适合：凭据与非人身份已成规模（多仓库 + CI + 容器 + 协作工具 + AI 编码助手），要的是持续监测与事件闭环， 而不是扫一次；需要 pre-commit/pre-push 与 IDE 侧即时拦截；网络边界要求高时可以走 self-hosting 甚至 air-gapped。 不适合：目标是「个人数据进模型前的脱敏算子在自己机器上跑」（那是 Presidio 那条约束）；只要一次性红队扫描留证据； 期望用凭据扫描器替代模型评测。

Fits: credentials and non-human identities already at scale (many repositories plus CI plus containers plus collaboration tools plus AI coding assistants), where the need is continuous monitoring with an incident loop rather than one scan; needing instant interception at pre-commit/pre-push and in the IDE; and when the network-boundary requirement is high, self-hosting or even air-gapped is available. Not a fit: when the constraint is "PII operators must run on my own machine before data reaches a model" (that is the Presidio constraint); when you only want a one-off red-team scan for evidence; or when a secret scanner is expected to replace model evaluation.

能力边界

  • 对象边界：凭据、密钥、非人身份与它们的流动面；不含模型行为评测、不含个人数据脱敏算子。
  • 检测语义边界：官方 FAQ 把引擎写成「Pre-Validation → Matching → Post-Validation」三段，并对命中的凭据做有效性校验； 官网标称的「600+ types of hardcoded secrets」是类型计数，本站不把它换算成拦截率、也不与别的工具排名。
  • 误报语义：官方 FAQ 自己给的定义是「a false positive occurs when our detection engine raises an alert for a secret that is not one and has never been one」——这是定义，不是指标。
  • 边界面：ggshield 的扫描在本机跑（官方在册），平台侧扫描在厂商侧跑；「Secrets never leave your perimeter」这类表述 只在自托管/边界面语境下读，本档案不把它当条款引用。

部署建议

  1. 先分清约束：能接受托管扫描 → 走 SaaS；不能 → 读 Self-Hosting 文档（Kubernetes 与 air-gapped 两种口径在册）再评估人力。
  2. 接入顺序建议「先只读后阻断」：先做仓库与 CI 的监测与事件分诊，再把 ggshield 的 pre-commit/pre-push 开成阻断。
  3. 有效性校验会向 issuing 服务发起调用（官方 FAQ 口径），接入前确认出网白名单与限流。
  4. AI 编码助手那面如果要接官方 MCP Server，先把 read-only 与 secret redaction 这两条约束验证一遍再给权限。
