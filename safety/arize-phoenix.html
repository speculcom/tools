适合与不适合When to use it, when not to

适合已经把 OpenTelemetry 当地图、要在 notebook 里跑批量对照实验的团队： trace 先进来，再沉淀成数据集，评估器随实验自动跑，分数与来源调用可回溯。 不适合两类需求——只要厂商托管控制台的，以及想把 Phoenix 包成服务对外卖的 （ELv2 明文禁止把软件作为托管或管理服务提供，当日 LICENSE 在册）。 本站只记它支持哪些评测类型，不记评测出来的分数。

模型与开放条件Model & openness

平台不绑模型厂商，评测面分三层：LLM-as-judge、自定义 Python 与 TypeScript 评估器、 确定性检查（server-evals 文档当日直抓在册）。内置确定性评估器 contains、exact_match、regex、 levenshtein_distance、json_distance 不需要 LLM 与 API key（同日直抓在册）。 judge 侧支持的厂商适配器全清单本次未逐条核验，记为未知。

The platform is not tied to model vendors; the evaluation surface has three layers — LLM-as-judge, custom Python and TypeScript evaluators, and deterministic checks (server-evals doc direct-fetched today). The built-in deterministic evaluators contains, exact_match, regex, levenshtein_distance and json_distance need no LLM and no API key (fetched the same day). The full list of judge-side vendor adapters supported was not verified item by item — recorded as unknown.

Running the service on your own machine is the main route: pip install arize-phoenix or Docker (repo README and PyPI fetched today; requires-python ≥3.11), with a web UI served locally; the repository also ships helm and kustomize directories for your own clusters. The vendor-hosted line is Arize AX, not Phoenix itself (README fetched today).

适合什么任务Best for

适合已把 OpenTelemetry 当观测底座、要在 notebook 或自有集群里跑评测、需要「评估器挂数据集」 这种批量对照的团队。不适合只要托管控制台、打算把 Phoenix 包一层对外售卖（ELv2 限制这条）， 或要现成红队与合规审计面的场景；本站不测分也不排名。

Fits teams already standardizing on OpenTelemetry who want batch comparisons in a notebook or on their own cluster: traces come in first, become datasets, evaluators run with the experiment, and each score links back to its source call. Not a fit for those who only want a hosted console, or who intend to resell Phoenix wrapped as a service (ELv2 forbids that explicitly), or who need a ready-made red-team or compliance-audit surface. This site does not measure scores and does not rank.

实测建议（三条，都指向仓内文档正文没抓全的东西）：

  • 数据集版本与实验比对：同一数据集换 judge 模型，历史分数是否可对齐比较
  • 确定性评估器与 LLM judge 的分工边界：哪些质量判断本质上只能用规则挡
  • 自托管外部依赖成本：接自有 PostgreSQL 与对象存储后的运维负担与备份口径

This site has not completed measured runs; conclusions cover the capability and license surfaces only.

Suggested measurements (three, each pointing at doc bodies we could not fetch):

  • Dataset versioning and experiment comparison: with the same dataset and a different judge model, can historical scores still be lined up
  • The division of labour between deterministic evaluators and LLM judges: which quality checks can only be blocked by rules
  • Self-hosted dependency cost: operational load and backup semantics once an external PostgreSQL and object storage are attached
