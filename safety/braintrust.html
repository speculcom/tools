Braintrust 是把评测当发布闸门的观测平台。 当日在册的官方自我定位是「主动式观测平台」，评测、人工反馈与生产打分在同一个面板里。

适合与不适合When to use it, when not to

适合要在 PR 和 CI 里跑实验对照、又想把观测栈托管出去的团队： 数据集喂实验、代码与 judge 与 autoevals 三类 scorer 并行、生产 trace 走在线打分。 数据必须留在自己环境时，它提供「客户侧数据面 + 厂商侧控制面」的混合部署， 但控制面仍在厂商侧，整机自托管不是它的口径。 本站只写它支持什么评测，不写分数，也不做同类排名。

By default the data sits vendor-side; with the customer-side data plane, PostgreSQL, Redis, object storage and Brainstore run in your own environment (fetched today), while the control plane keeps only authentication and metadata. The platform does not read your local codebase; the bt CLI reads and writes local eval configuration and syncs data (on record today).

适合什么任务Best for

适合把评测当发布闸门、要在 PR 与 CI 里跑实验对照，又不想自运维整套观测栈的团队。 不适合要整机自托管（控制面仍在厂商侧）、或想把平台再分发对外提供的团队； 本站只记支持的评测类型，不记分数也不排名。

Fits teams that treat evaluation as a release gate — running experiments on PRs and in CI — and would rather not operate the whole observability stack. When data must stay in your own environment there is a hybrid "customer data plane plus vendor control plane" deployment, but the control plane remains vendor-side, so full self-hosting is not its model. Not a fit for teams intending to redistribute the platform. This site records supported evaluation types, not scores, and does not rank.

This site has not completed measured runs; conclusions cover the capability, deployment and compliance surfaces only.

Suggested measurements (three, each pointing at what the readable official pages leave open):

  • End-to-end latency and miss rate of online scoring: how long one production trace takes to get a score, and what the sampling rule is
  • Hybrid upgrade cost: migration risk for Brainstore and object storage when following the data-plane v2.21.0 line
  • Who owns judge credentials: when models are called through the gateway, whose account carries the cost and quota
