模型与开放条件Model & openness

它不给模型，只给护栏。官方 Foundry 护栏页在册：护栏用 Azure AI Content Safety 的分类模型， 适用于所有「Azure 出售的 Foundry Models」（音频转写除外），agent 侧 tool call / tool response 为 preview。 也可以完全脱离 Foundry，用独立 REST API 守任意平台的模型输出。

It supplies guardrails, not models. The Foundry guardrails page records that the controls use Azure AI Content Safety classification models and apply to every Foundry Model sold by Azure except audio transcription, with tool call / tool response intervention points in preview for agents. It can also run completely outside Foundry, guarding models on any platform through the standalone REST API.

运行位置Where it runs

托管云 API + 网页工作台（contentsafety.cognitive.azure.com 在册）。检测在 Azure 侧执行。 官方容器页在册 own-environment 选项只有 Analyze text / Analyze image / Prompt Shields， 且 connected 与 disconnected 容器于 2027-04-30 退役，容器仍需回连 Azure 计量。

Hosted cloud API plus a web studio (contentsafety.cognitive.azure.com is on record). Detection executes on Azure's side. The official container page records only Analyze text, Analyze image and Prompt Shields for your own environment, retires connected and disconnected containers on 2027-04-30, and states containers must stay connected to Azure for metering.

本地文件Local files

不读写你的工作区文件：内容通过 REST / SDK 提交，或在工作台里上传样本与数据集。 数据页在册的唯一留存项是 blocklist：条目存 Azure Storage、同区域、微软托管密钥加密，可用 DELETE API 删。

It neither reads nor writes your workspace: content is submitted over REST / SDK, or uploaded as samples and datasets in the studio. The only retention item recorded on the data page is the blocklist - items live in Azure Storage, encrypted at rest with Microsoft-managed keys, in the same region as the resource, deletable through the DELETE API.

关机后的任务Tasks after shutdown

同步请求—响应为主。官方 FAQ 在册「异步过滤」：过滤与流式返回并行、内容不缓冲， 代价是「不安全内容可能在过滤完成前短暂露出」。这是延迟取舍，不是关机后续跑的托管任务。

Request-response is the main shape. The FAQ records asynchronous filtering: the filter runs in parallel with streaming, nothing is buffered, at the cost of 'unsafe content might be briefly exposed before filtering is complete'. That is a latency trade-off, not a task that survives your shutdown.

SDKs cover C# / Python / Java / JavaScript, and the studio can export the calling code.

上下文与记忆Context & memory

按单次请求判定，不做长上下文或记忆。官方 limits 页在册输入上限：文本 10K 字符、 图像 4MB、Prompt Shields 10K 字符、groundedness 源 55K 字符、task adherence 100K 字符等。 多轮与会话管理由调用方自己负责。

It judges one request at a time; there is no long context or memory. The limits page records input ceilings: 10K characters of text, 4 MB images, 10K characters for Prompt Shields, 55K characters of grounding sources, 100K characters for task adherence. Multi-turn handling belongs to the caller.

权限与限制Permissions & limits

数据页在册三条硬陈述：检测时不存储输入文本与图像、不用客户数据训练或改进模型、 Azure OpenAI 的 Abuse Monitoring 不适用（内容不做人工复核）。区域页在册：数据留在你所选区域。 鉴权支持 Microsoft Entra ID / 托管身份，支持 CMK / BYOK。档位 F0 / S0，F0 有月度免费额度（数字见定价页）。

Three hard statements are on the data page: inputs are not stored during detection, customer data is not used to train or improve the models, and Azure OpenAI Abuse Monitoring does not apply (no human review). The region page says data stays in the region you chose. Authentication supports Microsoft Entra ID and managed identity; CMK / BYOK is supported. Tiers are F0 and S0, with a monthly free quota on F0 (numbers live on the pricing page).

适合什么任务Best for

适合已经把工作负载放在 Azure 上、要多模态分级严重度与提示攻击检测、并要求区域驻留与「不训练」承诺的团队。 不适合需要离线长期跑护栏的场景（容器即将退役），也不适合要自己掌握 rail 代码与模型端点的团队——那类需求看本地线。

Fits: teams already running workloads on Azure that need graded severity across text and images plus prompt-attack detection, and that want region residency and a no-training commitment on record. Not a fit: long-term offline filtering (the containers are being retired) or teams that want to own the rail code and the model endpoint - that is the local-library line.

能力边界Capability boundaries

在册的判定对象有四类干预点：用户输入、工具调用（preview）、工具响应（preview）、输出。 Foundry 侧模型默认挂 Microsoft.DefaultV2；输出侧的内容危害关掉需要走审批表单， 输入侧人人可关。agent 护栏会整体覆盖模型护栏，官方页给了示例说明这种覆盖的实际后果。 另有一条硬边界写在 Overview：本服务不得用于检测非法儿童性虐待图像。

Four intervention points are recorded: user input, tool call (preview), tool response (preview) and output. On the Foundry side models get Microsoft.DefaultV2 by default; turning content harms off for inputs is available to everyone, while turning them off for outputs requires an approved customer form. An agent guardrail fully overrides the model guardrail, and the official page walks through what that means for tool calls and responses. One hard boundary sits in the Overview: the service must not be used to detect illegal child-exploitation images.
