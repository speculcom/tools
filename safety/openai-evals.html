本地文件Local files

评测定义是仓库内 YAML（evals/registry/evals、evals/registry/eval_sets），实现代码在 evals/elsuite； 数据集走 Git-LFS 取到 evals/registry/data。默认日志写本机 tmp/evallogs 的 JSONL，--record_path 可改路径。 按 README，用 JSON 数据 + YAML 模板即可写评测，不必写代码。

Eval definitions are YAML in the repo (evals/registry/evals, evals/registry/eval_sets) with implementations under evals/elsuite; dataset files come through Git-LFS into evals/registry/data. Logs default to local JSONL in tmp/evallogs, overridable with --record_path. Per the FAQ, a template-based or model-graded eval needs JSON data plus YAML and no evaluation code.

关机后的任务Tasks after shutdown

本机长跑，不是托管队列。官方文档写明 oaievalset 把已完成的评测记在 /tmp/oaievalset/{model}.{eval_set}.progress.txt， 中断或崩溃后重跑可接着来；单个 eval 不能从中间续，只能重头跑。并发靠 EVALS_THREADS / EVALS_THREAD_TIMEOUT（默认 10 线程、40 秒超时）。 关机后由谁续跑：官方未说明。

A local long run, not a hosted queue. The official docs state oaievalset records finished evals in /tmp/oaievalset/{model}.{eval_set}.progress.txt, so a rerun picks up where it stopped; a single eval cannot be resumed mid-way and must restart. Concurrency is EVALS_THREADS / EVALS_THREAD_TIMEOUT (default 10 threads, 40-second timeout). What happens after the machine shuts down: not stated officially.

第一次怎么用First run

  1. 先决定是走开源框架还是走 Dashboard 的托管 Evals——README 首行指的是后者，本档案讲的是前者。
  2. 设置 OPENAI_API_KEY（README：运行评测必需），并知道官方提醒这会按 API 计费。
  3. 只想跑现成评测：pip install evals；评测数据在 Git-LFS 里，按 README 的 git lfs fetch / git lfs pull 取。
  4. 终端跑 oaieval <模型或完成函数> <eval 名>；评测名取自 evals/registry/evals 下的 YAML，批量用 oaievalset。
  5. 结果先在 tmp/evallogs 的 JSONL 里自查，再考虑是否配 Snowflake 日志。
  6. 想接自己的系统就实现 CompletionFn，但别把自定义代码直接提进 registry——README 目前不收。
  1. First decide which line you want: the open-source framework described here, or hosted Evals in the Dashboard (the README's first line points to the latter).
  2. Set OPENAI_API_KEY (required by the README to run evals) and note the official warning that API use is billed.
  3. To run existing evals only: pip install evals; registry data lives in Git-LFS, fetched with the git lfs fetch / git lfs pull steps in the README.
  4. In the terminal run oaieval <model or completion function> <eval name>; eval names come from the YAML under evals/registry/evals, batches via oaievalset.
  5. Read the local JSONL logs under tmp/evallogs before considering Snowflake logging.
  6. To attach your own system, implement a CompletionFn - but do not submit custom-code evals as contributions, which the README says are not accepted.
