AI 安全与评测AI safety & evaluation

给 AI 系统做约束、度量与追责的产品：护栏与内容过滤、评测与观测、红队与审计、机密计算与访问控制、数据合规与脱敏、内容溯源与标识。本大类只收四条形态（网页 / 云服务 / 本机应用 / CLI）。安全与护栏的模型本体不收（「模型不是产品」）；六条线在不同层，按你的约束挑一个就好。Products that constrain, measure and make AI systems accountable: guardrails and content filtering, evaluation and observability, red teaming and audit, confidential compute and access control, data compliance and de-identification, provenance and labeling. This category files four forms only (web / cloud / local app / CLI). Safety and guardrail models themselves are out — same "a model is not a product" rule as everywhere else. The six lines live at different layers; pick one by the constraint you are under.

挑工具时，可以看这几件事What to look at when choosing

每个工具都按同一组问题拆开，方便你横向比较。Every tool is broken down by the same questions, so you can compare them side by side. 点开任一条，能看到官网原话和链接；不认同可以自己回去查。Open any entry to see the official wording and link; disagree and check it yourself.

01

模型与开放条件Model & openness

用谁的模型？能不能换第三方？多模型路由怎么配？Whose model does it use? Can you switch to a third party? How is multi-model routing configured?

02

运行位置Where it runs

本地 / 云端 / 混合？索引在本地还是云端？远程控制不等于云端执行。Local, cloud or hybrid? Is the index local or remote? Remote control is not the same as cloud execution.

03

本地文件Local files

能访问多大范围？未打开的大文件怎么读？符号级能力如何？How wide an area can it reach? How does it read large files you have not opened? How capable is it at the symbol level?

04

关机后的任务Tasks after shutdown

电脑关了还能继续跑吗？这是本地形态最常见的误解来源。Does it keep running once the computer is off? This is the most common misconception about local forms.

05

工具与扩展Tools & extensions

工具链有多宽：MCP · LSP · 插件 · Hooks · 自定义指令。How wide is the toolchain: MCP · LSP · plugins · hooks · custom instructions?

06

上下文与记忆Context & memory

索引算法、上下文窗口、会话恢复与分叉、跨会话记忆边界。Indexing algorithm, context window, session resume and fork, and the boundary of cross-session memory.

07

权限与限制Permissions & limits

沙箱与审批边界、凭据管理、数据是否出境、额度如何计算。Sandbox and approval boundaries, credential handling, whether data leaves your machine, and how quota is charged.

08

适合什么任务Best for

最擅长什么任务？什么情况下别用它？What tasks is it best at? When should you not use it?

为什么这里不给总分排名Why there is no overall ranking

这不是省略，是方法上的明确取舍。This is not an omission but a deliberate methodological choice.

  • 缺统一实测，就不给分。跨工具的跑分口径不同——题目、预算、执行环境都不一样，A 的 90 分和 B 的 88 分不可比。No shared measurement, no score. Benchmarks across tools use different rules — different questions, budgets and environments. A 90 and a B 88 are not comparable.
  • 「未知」是合法答案。查不到就写「未知」并说明为什么，不用推测填充。缺信息本身也是信息。"Unknown" is a legitimate answer. If it cannot be found, we write "unknown" and explain why, instead of filling the gap with guesses. Missing information is itself information.
  • 每个字段旁边都有来源链接，可以点回去看原文。Every field carries a source link, so you can go back to the original.
  • 刚查过，不代表一直有效。上游归档或改版后，这里会标成 active / maintenance / archived。A recent check does not mean it stays valid. When upstream archives or changes, the entry is marked active / maintenance / archived.
  • 不同族不混排。找现成的、自己搭的、接上与跑起来的是三种角色，判断方式不同；硬合成一张总表只会制造假的可比性。Families are not mixed. Ready-made tools, things you build yourself, and plug-in-and-run components are three different roles with different ways of judging them; forcing them into one master table would manufacture false comparability.
