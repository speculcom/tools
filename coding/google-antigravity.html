Google Antigravity is Google's agent-first development platform: desktop command center / CLI / IDE extensions / Python SDK — four surfaces on one harness, with command-execution policy and workspace boundaries as three explicit control switches in the official docs.

运行位置Where it runs

四个官方面（overview 页原文口径）：Antigravity App（桌面端，v2.5+，从 Agent Manager 演进的 独立指挥中心）、Antigravity CLI（终端客户端，本地 shell/远程云环境/SSH 都能跑）、 Editor extensions（5 个 IDE 的扩展）、Antigravity SDK（Python 编程运行时）。 App/CLI/IDE 扩展的执行都在你本机环境；SDK 是「几行 Python 跑 agent harness」。

Four official surfaces (overview page wording): Antigravity App (desktop, v2.5+, a standalone command center evolved from the Agent Manager), Antigravity CLI (a terminal client that runs on local shell / remote cloud environments / SSH), Editor extensions (extensions for 5 IDEs), Antigravity SDK (a Python programming runtime). App/CLI/IDE-extension execution all happen in your local environment; the SDK is "run an agent harness in a few lines of Python".

The official settings docs state the boundary explicitly: by default the agent can only access the active project folder and ~/.gemini/antigravity-ide/ (artifacts, knowledge items and configuration all live in this local directory); "non-workspace file access" is an explicit toggle, off by default.

头号误解Top misconception

  • 四个面（App/CLI/IDE 扩展/SDK）是同一 harness 的不同入口，不是四个独立产品——别按 Gemini Code Assist 或 Firebase Studio 的旧认知套它（官方文档有 Firebase Studio 迁移页，那条线并入本平台叙事）The four surfaces (App/CLI/IDE extensions/SDK) are one harness with four entry points, not four separate products — don't map old Gemini Code Assist or Firebase Studio notions onto it (the official docs carry a Firebase Studio migration page; that line folds into this platform's narrative)
  • 「始终继续」模式=agent 自动执行 shell 命令（官方原文标注自主性高、风险高）——默认是请求审查，别顺手改完就忘'Always continue' mode = the agent auto-executes shell commands (official wording flags it: high autonomy, high risk) — the default is review-on-request; don't flip the switch and forget
