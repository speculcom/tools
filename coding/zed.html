不是「又一个 AI 编码工具」，而是三种 agent path 的编排层 —— 能在同一个编辑器里用 Zed 原生 Agent，也能挂 Claude / Codex / OpenCode / Copilot / Cursor。

Not "yet another AI coding tool" but an orchestration layer for three agent paths — use Zed's native agent in the same editor, or attach Claude / Codex / OpenCode / Copilot / Cursor.

适合与不适合When to use it, when not to

适合重视编辑器性能（Rust）、解析准确度（Tree-sitter）与多人协作的场景。

也适合想在一个编辑器里混用原生 Agent 与外部 CLI Agent 的用户。 这是它最独特的价值。

不适合把「编辑器自带 AI」当唯一卖点去找的用户。 Zed 的定位是 agent 的编排层，不是「我自带一个模型」。

也不适合需要实测才知道大仓库表现的人 —— 索引策略官方未公开说明。

Scenarios where editor performance (Rust), syntactic parsing accuracy (Tree-sitter) and multi-user collaboration matter. Users who want to mix the native agent with external CLI agents in one editor — this is its most distinctive value.

Not a fit for people looking for an editor whose only selling point is built-in AI — Zed positions itself as an orchestration layer for agents, not as "I ship my own model". Also not a fit if you need hands-on measurements of large-repository behaviour — the indexing strategy is not publicly documented.

The official docs list 5 model-access paths (docs/src/ai/llm-providers.md):

  • Zed-Hosted Models — billed through Zed
  • API Access — your own provider quota, including Anthropic-compatible and OpenAI-compatible
  • Existing Subscription — reuse a paid ChatGPT / Claude / Copilot etc.
  • Gateway — routed via gateways like OpenRouter / Bedrock / Vercel
  • Local Model — running locally or self-hosted

Path choice is up to the user, not a bound single provider. llm-providers.md lists these five item by item.

The official self-description: from the creators of Atom and Tree-sitter, leading with performance and multiplayer collaboration.

本地文件Local files

直接读写工作区，支持多根目录（multi-root）。

也可经 SSH / WSL 打开远端文件夹，即 remote development。

文件树扫描由 file_scan_exclusions 与 project_panel.hide_gitignore 控制。 符号能力来自 Tree-sitter 解析与语言服务器（LSP）。 编辑预测另有独立 provider。

Agent 内置检索是四种：grep（正则）、find_path（glob）、list_directory、read_file。

官方未见代码库向量化语义索引（已查 Tools 页）。

大仓库的限制官方有明说： 一次打开 >100,000 文件的超大目录表现不佳。 官方建议只开具体项目或子目录（remote development 页）。

Reads and writes the workspace directly, with multi-root support.

Can also open remote folders via SSH / WSL, i.e. remote development.

File-tree scanning is controlled by file_scan_exclusions and project_panel.hide_gitignore. Symbol capability comes from Tree-sitter parsing and language servers (LSP). Edit prediction has its own separate provider.

The agent's built-in retrieval has four kinds: grep (regex), find_path (glob), list_directory, read_file.

No codebase vectorized semantic index found officially (Tools page checked).

The official docs state the large-repo limit explicitly: huge directories with >100,000 files open at once perform poorly. The official advice is to open only specific projects or subdirectories (remote development page).

关机后的任务Tasks after shutdown

本地桌面应用。agent 线程在本地进程内跑。 远端主机可以是自建的 SSH / WSL 主机。

绑定客户端在线。 线程运行时，Zed 会请求系统不要休眠。 这样可以保住长回合（agent.prevent_idle_sleep）。

remote development 把语言服务器、任务与终端放到你自己的远端服务器。 官方注明 v0.157 起不再经 Zed 服务器中转。

官方未见「关机后续跑 / 厂商托管后台任务」类能力（已查 Agent Panel 页）。

A local desktop app; agent threads run inside the local process. Remote hosts can be your own SSH / WSL hosts.

Bound to the client being online. While a thread runs, Zed asks the system not to sleep. This preserves long turns (agent.prevent_idle_sleep).

Remote development puts language servers, tasks and terminals on your own remote server. The official docs note since v0.157 it no longer relays through Zed servers.

No "keeps running after shutdown / vendor-hosted background task" capability found officially (Agent Panel page checked).

MCP support is explicit.

The official docs mcp.md states Tools and Prompts are the two supported protocol features. Discovery / Sampling / Elicitation are not yet covered; the official docs welcome contributions.

It also handles notifications/tools/list_changed — when a server adds/removes/changes tools at runtime, Zed reloads the list automatically without restarting the server.

MCP has two integration paths:

  • install as an extension
  • add local / remote servers under Settings → AI → MCP Servers

Popular extension servers listed officially: Context7, GitHub, Puppeteer, Gem, Brave Search, Framelink Figma, Resend and more.

上下文与记忆Context & memory

Zed Agent 的上下文由 instructions + skills + MCP 组合而成（见 agents.md 的 Zed Agent 行）。

压缩策略：官方称线程接近阈值时自动 compact。 默认 90% 触发（agent.auto_compact）。 它把较早消息摘要后替换进模型上下文。 线程显示 "Context Compacted"，可展开。

也可 /compact 手动压缩。 阈值可配：百分比 / 正 token / 负剩余 token。

模型窗口太小（<80000 tokens）时自动压缩失效。 官方提示用 New From Summary 新开线程。

@-mention 可加文件、目录、符号、历史线程、skills、diagnostics、分支 diff 与 URL。

另支持并行多线程（各自上下文窗口）与 Checkpoints 逐消息回滚。

Zed Agent's context is composed of instructions + skills + MCP (see the Zed Agent row in agents.md).

Compaction policy: officially, threads auto-compact when approaching the threshold. Default trigger at 90% (agent.auto_compact). It summarizes earlier messages and replaces them in the model context. The thread shows "Context Compacted", expandable.

/compact also compacts manually. The threshold is configurable: percentage / positive tokens / negative remaining tokens.

When the model window is too small (<80000 tokens) auto-compaction is disabled. The official hint is to start a new thread via New From Summary.

@-mention can add files, directories, symbols, past threads, skills, diagnostics, branch diffs and URLs.

Parallel multi-threads (each with its own context window) and Checkpoints per-message rollback are also supported.

权限与限制Permissions & limits

工具权限由 Zed 官方配置控制（tool-permissions 页，v0.224.0+ 起由 agent.tool_permissions.default 控制）。

三档取值是 "allow" / "deny" / "confirm"，default 默认 confirm。 可按工具配正则模式：always_allow / always_deny / always_confirm。

优先级：always_deny > always_confirm > always_allow > 工具 default > 全局 default。

另有硬编码安全规则（rm -rf /、rm -rf ~ 等），不可覆盖。

受管控工具含：

  • terminal、edit_file、write_file
  • delete_path、move_path、copy_path、create_directory
  • fetch、search_web、skill
  • MCP（mcp:<server>:<tool>）

另有 OS 级沙箱（sandboxing 页）：仅 Zed Agent，覆盖 terminal 与 fetch， 默认限制项目外写入与出网。

权限边界跟随 agent path（agents.md）：

  • Zed Agent —— 用 Zed 配置的 provider 与原生工具
  • External Agents —— 用 ACP agent 进程自己的 auth/config
  • Terminal Threads —— 用原生 CLI 的 auth/config

隐私：官方称 Zed 不存 prompt 与代码上下文，遥测可关。

Tool permissions are controlled by Zed's official config (tool-permissions page; since v0.224.0 by agent.tool_permissions.default).

Three values: "allow" / "deny" / "confirm", with default set to confirm. Per-tool regex patterns can be configured: always_allow / always_deny / always_confirm.

Precedence: always_deny > always_confirm > always_allow > tool default > global default.

There are also hardcoded safety rules (rm -rf /, rm -rf ~ etc.), not overridable.

Managed tools include:

  • terminal, edit_file, write_file
  • delete_path, move_path, copy_path, create_directory
  • fetch, search_web, skill
  • MCP (mcp:<server>:<tool>)

There is also an OS-level sandbox (sandboxing page): Zed Agent only, covering terminal and fetch, restricting writes outside the project and outbound network by default.

Permission boundaries follow the agent path (agents.md):

  • Zed Agent — uses Zed-configured providers and native tools
  • External Agents — use the ACP agent process's own auth/config
  • Terminal Threads — use the native CLI's auth/config

Privacy: officially Zed states it does not store prompts or code context; telemetry can be turned off.
