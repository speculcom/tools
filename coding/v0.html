v0 是 Vercel 的提示词到全栈应用平台：聊天生成 Next.js 应用，VM 沙箱内跑真终端与预装 agent （claude 可直接用），GitHub 同步进你的仓库，publish 走 Vercel 部署链——权限三档 Ask/Auto/Full， 自定义模型是 Enterprise 面。

v0 is Vercel's prompt-to-full-stack platform: chats generate Next.js apps, a VM sandbox runs a real terminal with pre-installed agents (claude is ready to use), GitHub sync moves code into your repo, and publishing runs through the Vercel deployment chain — Ask/Auto/Full permission tiers, custom models are Enterprise-side.

适合与不适合When to use it, when not to

适合：Next.js/Vercel 栈团队、要沙箱终端与预装 agent、企业席位并入 Vercel 账号体系。 不适合：栈不在 Vercel 生态、非 Enterprise 要自定义模型。

Fits: Next.js/Vercel-stack teams (the deployment chain is natively wired), wanting a real terminal and pre-installed agents in a sandbox, enterprise seats unified with the Vercel account system. Not a fit: stacks outside the Next.js/Vercel ecosystem (the deployment chain is part of the product semantics); non-Enterprise teams wanting custom models.

模型与开放条件Model & openness

官方「Choosing models」页：聊天内模型选择器选 v0 模型或从 AI Gateway 目录加自定义模型； 更新版选择器与自定义模型面向 Enterprise 团队（自定义模型需团队 owner 批准）。 会话内模型跟随最近一次响应，直到你换。应用内 AI 功能另有 ai-models 集成页（Grok/fal/Deep Infra 等）。

运行位置Where it runs

网页形态（v0.app）；VM-backed 聊天跑在 Vercel Sandbox 隔离虚拟机里（官方 sandbox 页： 托管项目文件/跑预览/执行命令，聊天间状态互不泄漏；取代旧的浏览器内环境）。 沙箱内预装编码 agent（官方页：终端里直接跑 claude 等 CLI，与 v0 内置助手同项目并用）。

本地文件Local files

项目在 v0 平台；GitHub 集成官方成页：代码进你的仓库、分支隔离、PR 与 CI 走标准流； 可导入现有 GitHub 仓库（git-import 页）。官方明示 GitHub sync 只搬代码， 不等于授予经 GitHub 部署的权限（部署权限看 Vercel 角色）。

关机后的任务Tasks after shutdown

部署线常驻：preview 部署按分支构建、publish 更新 Vercel 生产部署（官方 deployments 页）； 部署报错可「Fix with v0」读日志诊断修复（agentic-features 页）。 构建任务关闭页面后是否续跑未核验到官方声明。

agent 能力官方成页：web 搜索、浏览器使用、终端命令、错误修复、外部工具集成，全部在沙箱内； MCP 两条线（自带 MCP 服务器含预设清单/Marketplace 集成的 Remote MCP）； 数据库集成 Supabase/Blob/Neon/Upstash；Figma 导入；v0 自身也可作为 MCP server 被别的 agent 调。

权限与限制Permissions & limits

工具调用三档权限模式（Ask/Auto/Full）+ Agent Permissions 规则（MCP 页与 agentic-features 页口径）； 企业面走 Vercel Enterprise：席位/v0 角色（Builder 等）与 Vercel 团队角色分离管理（enterprise 页）； 安全页官方口径：不信任 LLM 生成代码——执行前安全分析、沙箱隔离、输入校验、对抗测试。

适合什么任务Best for

适合：Next.js/Vercel 栈团队（部署链原生打通）、要沙箱内跑真终端与预装 agent、 企业席位与 Vercel 账号体系统一。 不适合：栈不在 Next.js/Vercel 生态（部署线是产品语义一部分）、非 Enterprise 要自定义模型。

头号误解Top misconception

  • 部署链绑 Vercel：publish 走 Vercel 项目与域名（官方 deployments 页）——GitHub 同步只搬代码，
  • 经 GitHub/Vercel CLI 的部署权限看 Vercel 角色，两套权限别混（官方页专门警告）
  • 自定义模型（AI Gateway 目录）是 Enterprise 团队功能且需 owner 批准——普通计划的模型选择面比官方文档读感窄
  • 沙箱有 VM-backed 与旧浏览器内两代（官方 sandbox 页明示取代关系）——旧教程里「浏览器内跑」的行为描述可能已过时
