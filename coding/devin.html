Devin 是「工单进、草稿 PR 出」的云异步软件工程师（Cognition）：会话在厂商云工作区跑， 自带 shell/IDE/浏览器，Slack/Linear/Jira 直接派单，并行处理积压任务。

Devin is the 'ticket in, draft PR out' cloud async software engineer (Cognition): sessions run in the vendor's cloud workspace with its own shell/IDE/browser trio, dispatch work straight from Slack/Linear/Jira, and grind through backlogs in parallel.

适合与不适合When to use it, when not to

适合：批量委派工单、并行多任务、草稿 PR 再接管。 不适合：要选模型、要全程本机执行、仓库里带密钥。

Fits: delegating backlog tickets in bulk, parallel multi-task work, @-dispatching from Slack, 'give me a draft PR then I take over'. Not a fit: picking your own models; everything running on your machine (Terminal only covers light tasks); repos carrying secrets.

运行位置Where it runs

会话跑在 Devin 的云工作区：网页端（app.devin.ai）内嵌三件套——Shell（看命令执行）、 嵌入式 IDE（可实时接管改代码）、Browser（看它查文档/测应用）。另有 Devin for Terminal （cli.devin.ai 安装）在你本机跑，长任务用 /handoff 交给云端 Devin；还有 Devin API。

Sessions run in Devin's cloud workspace: the web app (app.devin.ai) embeds a three-piece set — Shell (watch commands execute), an embedded IDE (take over and edit code live), and a Browser (watch it read docs / test the app). There is also Devin for Terminal (installed from cli.devin.ai) running on your machine, with /handoff sending long tasks to the cloud Devin; plus the Devin API.

本地文件Local files

云端会话不碰你本机文件——它在你授权的仓库上 clone、改、提 PR；仓库可见范围由集成授权决定。 Terminal 形态是例外：它直接在你本机环境跑，接管的是本地代码库。

Cloud sessions do not touch your local files — it clones, edits and opens PRs on repositories you authorize; repo visibility is set by integration grants. The Terminal form is the exception: it runs directly in your local environment, taking over the local codebase.

关机后的任务Tasks after shutdown

主轴就是异步：官方按「自主 AI 软件工程师」定义它，适合并行处理多个任务——Linear/Jira 工单、 整段新功能、bug 复现修复、迁移重构。官方经验法则原文：「if you can do it in three hours, Devin can most likely do it」（可验证性高的任务成功率高）。

The main axis is asynchrony: the official defines it as an "autonomous AI software engineer", suited to handling multiple tasks in parallel — Linear/Jira issues, whole new features, bug reproduction and fixes, migrations and refactors. The official rule of thumb (original wording): "if you can do it in three hours, Devin can most likely do it" (tasks with high verifiability have higher success rates).

权限与限制Permissions & limits

账号+组织体系：企业管理员分配权限；仓库访问经集成授权（GitHub 等）划定范围；API 访问单独配。 云端环境有联网能力（Browser 工具是产品语义的一部分），官方要求按对待公共计算面的标准看待它。

Account + organization system: enterprise admins assign permissions; repository access is scoped by integration grants (GitHub etc.); API access is configured separately. The cloud environment has internet access (the Browser tool is part of the product semantics) — the official asks you to treat it by the standard you would apply to a public compute surface.

适合什么任务Best for

适合：把积压工单批量委派出去、并行跑多个任务、在 Slack 里随手 @ 派单、要「先给个草稿 PR 再接管」。 不适合：要选模型、要全程本机执行（Terminal 只覆盖轻任务）、要把密钥放进被 clone 的仓库。

Good fit: delegating backlogged issues in bulk, running multiple tasks in parallel, @-dispatching casually in Slack, wanting "a draft PR first, then take over".

Not a fit: wanting model choice, wanting fully local execution end to end (Terminal only covers light tasks), keeping secrets inside the cloned repositories.

头号误解Top misconception

  • 「三小时法则」是官方经验法则不是保证——官方自己强调任务要「容易验证」（CI 能过/能自动部署验证）The 'three-hour rule' is the vendor's rule of thumb, not a guarantee — the official docs themselves stress tasks must be easy to verify (CI passes / auto-deploy checks)
  • Terminal 在本机跑、/handoff 把任务送去云端——同一工具里数据边界会切换，交接前先想清楚代码去哪Terminal runs on your machine, /handoff sends tasks to the cloud — the data boundary switches inside one tool; decide where your code goes before handing off
