AWS 出的 agentic 工程环境：一套 harness 同时撑起 IDE / CLI / Web / Mobile 四个端。

两个招牌：

  • Spec 驱动 —— 先出 requirements / design / tasks 三段式，再写代码
  • Cloud Session —— 关掉笔记本，任务还在云上跑

Kiro is a desktop IDE — officially "a desktop development environment built on a VS Code foundation" — but it is framed as one agent, every surface: the IDE, CLI, Web and Mobile apps are all front ends to the same unified agent harness, connected over the open Agent Client Protocol (ACP). Its headline workflow is spec-driven development, turning a prompt into "requirements, architectural designs, and sequenced tasks", and its cloud sandbox sessions keep working "whether or not you're connected".

适合与不适合When to use it, when not to

在 AWS 生态里做正式工程交付、习惯「先出 spec 再实现」的团队。 需要云端会话在关机后继续跑的人（Cloud sessions，最多 10 并发）。 想把 steering 与权限规则随仓库分发的团队（.kiro/ 可提交）。

不适合想接自有 API Key 或跑本地模型的人。官方 models 与 pricing 两页都没有 BYOK 说明。 也不适合要求额度口径透明的重度用户。credit 按模型倍数消耗，官方未给固定请求数换算。

Teams doing formal engineering delivery in the AWS ecosystem who want specs before implementation. People who need a cloud session that keeps running after they close the laptop (Cloud Sessions, up to 10 concurrent). Teams that want steering and permission rules shipped with the repository (.kiro/ is committable and consistent across surfaces). Free tier suits low-volume trials (50 credits/month, limited to open-weight models and Claude Sonnet 4.5).

Not a fit for anyone who needs their own API key or local models — neither the official models page nor the pricing page documents BYOK; nor for heavy users who need a transparent quota figure, since credits are consumed by model multiplier (up to 4.4x) with no fixed request-count equivalent.

运行位置Where it runs

独立桌面 IDE，官方原文明说「a desktop development environment built on a VS Code foundation」， 不是装进别人编辑器的扩展。但官方把它定位为「one agent, every surface」： IDE / CLI / Web / Mobile 都是同一个 unified agent harness 的前端，本地客户端经 stdio 走 Agent Client Protocol（ACP），Web / Mobile 经 WebSocket 连云端沙箱。 IDE 与 CLI 默认在本机运行 harness。工具操作本地文件与 shell。 两者也可创建并接入云端 sandbox 里的 Cloud Session。 因为边界是标准 ACP。官方称 JetBrains IDE 与 Zed 也能把 Kiro 当 agent 用。

A standalone desktop IDE; the official wording explicitly says "a desktop development environment built on a VS Code foundation" — not an extension inside someone else's editor. But the official positioning is "one agent, every surface": IDE / CLI / Web / Mobile are all front ends of one unified agent harness; local clients go over stdio via the Agent Client Protocol (ACP), while Web / Mobile connect over WebSocket to cloud sandboxes. The IDE and CLI run the harness locally by default, with tools operating on local files and shell. Both can also create and attach Cloud Sessions inside cloud sandboxes. Because the boundary is standard ACP, the official pages say JetBrains IDEs and Zed can also use Kiro as their agent.

本地文件Local files

它通过 IDE 访问你的工作区文件。

代码理解分两层。 第一层是内置的 Tree-sitter，覆盖 18 种语言， 提供符号模糊搜索、文档大纲、AST 结构搜索与改写、代码库概览。 这些能力跨 surface 都能用。 第二层是 LSP（可选），能做查引用、跳定义、重命名、诊断、悬停文档 —— 但只在 IDE 与 CLI 里，而且要自己装语言服务器。

索引有专页说明：打开项目就自动索引源码、文档、配置与依赖； 文件变更或外部改动会增量重索引。也可以手动 Force Re-Index / Rebuild。 想让 agent 别碰某些文件，用 .kiroignore（gitignore 风格）排除。

索引会不会上传到云端：官方未说明。 （已查 codebase indexing 与 how-kiro-works 两页。）

It reaches your workspace files through the IDE.

Code understanding has two layers. The first is built-in Tree-sitter, covering 18 languages, providing fuzzy symbol search, document outlines, AST structural search and rewrite, and codebase overviews. These work across surfaces. The second layer is LSP (optional): find references, go to definition, rename, diagnostics, hover docs — but only in the IDE and CLI, and you install the language servers yourself.

Indexing has its own page: opening a project automatically indexes source, docs, configuration and dependencies; file changes or external edits trigger incremental re-indexing. Manual Force Re-Index / Rebuild is also available. To keep the agent off certain files, exclude them with .kiroignore (gitignore style).

Whether the index is uploaded to the cloud: not stated officially.

(codebase indexing and how-kiro-works pages checked.)

关机后的任务Tasks after shutdown

关掉笔记本，任务还在跑 —— 这是它最特别的一点。

会话跑在厂商托管的云端 sandbox 里，属于账号而不是某个 app。 所以 IDE / CLI / Web / Mobile 都能接入同一个会话， 你合上电脑、改用手机或终端回来接着看都行。

官方给出的硬数字：

  • 最多 10 个并发 Cloud Session
  • 云端算力不额外收费（含在现有套餐里）
  • 从 IDE 创建需 IDE v1.0.293+；从 CLI 需 CLI v2.17+

不过，跑在本机的那套 harness 仍然依赖你自己的机器，退出就停。

官方 Cloud sessions 页原文：「The agent keeps working in the sandbox whether or not you're connected」

Close the laptop and the task keeps running — that is its most distinctive point.

Sessions run in vendor-hosted cloud sandboxes and belong to the account, not to one app. So IDE / CLI / Web / Mobile can all attach to the same session; you can close the lid and pick it up from your phone or a terminal.

Hard numbers given officially:

  • Up to 10 concurrent Cloud Sessions
  • Cloud compute carries no extra charge (included in existing plans)
  • Creating from the IDE needs IDE v1.0.293+; from the CLI needs CLI v2.17+

However, the harness running locally still depends on your own machine and stops when you exit.

Official Cloud sessions page wording: "The agent keeps working in the sandbox whether or not you're connected"

内置四类工具：文件、shell、web、code。

扩展机制成体系，一共六种：

  • Powers —— 打包了知识的 MCP server，按需加载
  • Skills —— 开放标准的可移植指令包
  • Custom agents 与 sub-agents
  • Specs
  • Hooks

Hook 的触发点官方列全了：Prompt Submit、Agent Stop、Session Start、 Session End（CLI V3）、Agent Spawn、Pre / Post Tool Use、 File Create / Save / Delete、Pre / Post Task Execution、Manual。

CLI 另有 headless 模式（--no-interactive，配 API key），可以放进 CI/CD。

⚠ Mobile 端不支持 MCP 与本地文件工具。

Four built-in tool classes: files, shell, web, code.

The extension mechanisms form a system, six in total:

  • MCP — local stdio and remote HTTP/SSE; supports server-provided prompts / resources and elicitation; kiro:// one-click install links
  • Powers — MCP servers packaged with knowledge, loaded on demand
  • Skills — open-standard portable instruction packs
  • Custom agents and sub-agents
  • Specs
  • Hooks

The Hook trigger points are fully listed officially: Prompt Submit, Agent Stop, Session Start, Session End (CLI V3), Agent Spawn, Pre / Post Tool Use, File Create / Save / Delete, Pre / Post Task Execution, Manual.

The CLI also has headless mode (--no-interactive, with an API key) for CI/CD.

⚠ The Mobile surface does not support MCP or local file tools.

上下文与记忆Context & memory

Specs 是它的招牌。 每个 spec 生成三份文件，走「需求 → 设计 → 任务」：

  • requirements.md（或 bugfix.md）
  • design.md
  • tasks.md —— 支持按依赖图分波并行执行

Steering 提供持久的项目上下文。它放在两个位置：工作区 .kiro/steering/、 全局 ~/.kiro/steering/。内置 product / tech / structure 三份基础文件。 支持 always / fileMatch / manual / auto 四种 inclusion 模式，并兼容 AGENTS.md。

其它上下文相关能力：subagents（各自独立上下文窗口）。 另有 compaction。 （自动摘要旧历史，单向不可回滚）· checkpoints / rewind · /sessions 做会话管理。CLI 里另有实验性的 knowledge 库（语义检索）。

上下文窗口的具体数值，官方 docs 没有单列。 （已查 compaction 与 models 两页。）

Specs are its signature. Each spec generates three files, following "requirements → design → tasks":

  • requirements.md (or bugfix.md)
  • design.md
  • tasks.md — supports wave-parallel execution along the dependency graph

Steering provides persistent project context. It lives in two places: workspace .kiro/steering/, global ~/.kiro/steering/. Three base files ship built in: product / tech / structure. Four inclusion modes are supported — always / fileMatch / manual / auto — and AGENTS.md is compatible.

Other context-related capabilities: subagents (each with its own context window). There is also compaction (auto-summarizing older history, one-way and not reversible) · checkpoints / rewind · /sessions for session management. The CLI additionally has an experimental knowledge base (semantic retrieval).

Concrete context-window numbers are not broken out in the official docs. (compaction and models pages checked.)

权限与限制Permissions & limits

它是能力制权限，不是「信任 / 不信任」两档。 规则写 YAML， 按 capability 配 match / exclude，effect 取 deny / ask / allow， 优先级 deny > ask > allow。

官方列出的 capability：

  • 文件：fs_read / fs_write
  • 执行：shell / sandbox_network
  • 联网：web_fetch / web_search
  • 扩展：mcp / subagent / skill / power
  • 其它：context / diagnostics

作用域共六个：Kiro 硬编码、administration、user、workspace、agent、session。

IDE 另有 Agent Autonomy 的 Autopilot / Supervised 两档。 工作区默认不被信任。信任之前不加载仓库内的 agents、steering、MCP、Skills。 headless 模式下，每个 ask 都按 deny 处理。

官方 permissions 页原文：capability-based，"replacing older binary trust models"

Permissions are capability-based, not a two-state trust/untrust model. Rules are written in YAML, configured per capability with match / exclude, effect taking deny / ask / allow, with precedence deny > ask > allow.

Capabilities listed officially:

  • Files: fs_read / fs_write
  • Execution: shell / sandbox_network
  • Networking: web_fetch / web_search
  • Extensions: mcp / subagent / skill / power
  • Other: context / diagnostics

Six scopes in total: Kiro hardcoded, administration, user, workspace, agent, session.

The IDE additionally has Agent Autonomy with Autopilot / Supervised tiers. Workspaces are untrusted by default. Before trust, repo-local agents, steering, MCP and Skills are not loaded. In headless mode, every ask is treated as deny.

Official permissions page wording: capability-based, "replacing older binary trust models"
