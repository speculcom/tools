Stanford NLP / Databricks
开源Open source MITMIT 提示优化Prompt optimisation 编程式LMProgrammatic LM 学术出身Academic origins partial lifecycle: active 核验Checked 2026-10-30

DSPy 把「调提示词」变成编程问题（MIT，Stanford NLP/Databricks）：签名声明输入输出， 优化器把提示当参数训练。用它的分水岭一句话：有没有评估指标——有指标它是杠杆，没指标它无从下手。

DSPy turns 'tuning prompts' into a programming problem (MIT, Stanford NLP/Databricks): signatures declare inputs/outputs, optimizers train prompts as parameters. The dividing line in one sentence: do you have an evaluation metric — with one it is a lever, without one it has nothing to optimize.

适合与不适合When to use it, when not to

适合：可复现的提示优化流程、多模型可换管线、有 metric 的成熟任务。 不适合：开箱 agent 运行时；无指标的探索期任务。

Fits: reproducible prompt-optimization flows, multi-model swappable pipelines, mature tasks with metrics. Not a fit: out-of-the-box agent runtimes; exploratory tasks without metrics.

No account system; the permission surface is whatever vendors' API keys you connect. The optimization process calls models heavily (a token-cost surface); budget-control parameters are in the official docs line, details not verified item by item.

适合什么任务Best for

适合：把「调提示词」变成可复现的优化流程（有指标、有训练集）、多模型可换的管线。 不适合：要开箱 agent 运行时；小样本没指标时（优化器吃指标，没指标没意义）。

Fits: turning "prompt tuning" into a reproducible optimization process (with metrics, with a training set); pipelines where models are swappable. Does not fit: wanting an out-of-the-box agent runtime; small samples without metrics (optimizers consume metrics — without metrics there is nothing to optimize).

头号误解Top misconception

  • 把 DSPy 当「又一个 prompt 模板库」——它的核心是优化器（把提示当参数训练），不用优化器等于白用Treating DSPy as 'yet another prompt template library' — the core is the optimizer (prompts trained as parameters); skipping it wastes the tool
  • 没有评估指标就上优化器——优化器需要 metric，没指标时它无从优化Running optimizers without an evaluation metric — optimizers need a metric; without one there is nothing to optimize
  • 优化期 token 成本不设上限——先设预算参数再跑（官方文档有控制面）Leaving optimizer token budgets uncapped — set budget parameters before running (the official docs have controls)
