模型与开放条件Model & openness

Drake 本身不是模型产品。官方文档未列模型 provider 清单。策略或模型接入经用户代码、LCM/ROS 2 集成或外部训练框架完成。官方定位是 C++/Python 工具箱。

用于机器人动力学分析与控制系统构建。模型层由用户自带（2026-11-21）。

Drake is not a model product and the official docs list no model-provider catalogue; policies or models enter through user code, LCM/ROS 2 integrations or external training frameworks. Its official positioning is a C++/Python toolbox for robot dynamics analysis and control design, with the model layer supplied by the user (2026-11-21).

运行位置Where it runs

Drake 以 C++/Python 库在本机进程内运行。官方支持 Ubuntu 24.04/26.04、macOS Tahoe/Golden Gate 与 Amazon Linux 2023。

提供 pip、APT、二进制包和源码构建四种方式。不是托管云服务，也不提供浏览器端运行面（官方 Installation 页，2026-11-21）。

Drake runs as a C++/Python library inside a local process. Official support covers Ubuntu 24.04/26.04, macOS Tahoe/Golden Gate and Amazon Linux 2023, with pip, APT, binary packages and source builds; it is not a hosted cloud service and has no browser runtime (Installation page, 2026-11-21).

本地文件Local files

Drake 读写本地场景、模型、配置与数据资产。安装内容默认落在 /opt/drake 或 Python 虚拟环境。文件权限与资产许可由用户核对。

它不替用户管理训练数据版权、机器人工作区安全或云存储同步（官方安装文档，2026-11-21）。

Drake reads and writes local scenes, models, configuration and data assets; installs default to /opt/drake or a Python virtual environment. Users remain responsible for file permissions and asset licences; Drake does not manage training-data copyright, robot-workspace safety or cloud sync (official installation docs, 2026-11-21).

关机后的任务Tasks after shutdown

Drake 不提供托管调度、作业队列或服务端常驻进程。仿真、求解与可视化都在用户启动的 Python/C++ 进程内运行。后台执行取决于操作系统与用户自己的进程管理。

官方文档只描述库的构建与调用。未列断点续跑、分布式调度或作业恢复服务（2026-11-21）。

Drake provides no hosted scheduler, job queue or resident server process: simulation, solving and visualisation run inside the Python/C++ process the user starts, and background execution depends on the OS and the user’s process manager. Official docs describe library build and invocation only, with no resume, distributed scheduling or job-recovery service (2026-11-21).

工具与扩展Tools & extensions

Drake 以 C++/Python API 为主。配套 pydrake、MathematicalProgram 求解器、Meshcat 可视化、LCM 与 ROS 2 集成。

官方文档列 Python、LCM、ROS 2（unsupported）、Julia（unsupported）四类集成。未列 MCP 服务器或 agent 工具协议（2026-11-21）。

Drake centres on C++/Python APIs, with pydrake, MathematicalProgram solvers, Meshcat visualisation, LCM and ROS 2 integration. Official docs list four integration surfaces — Python, LCM, ROS 2 (unsupported) and Julia (unsupported) — and no MCP server or agent tool protocol (2026-11-21).

上下文与记忆Context & memory

不适用：Drake 不是对话模型，没有 LLM 上下文窗口。状态由场景文件、配置、节点状态或用户代码中的 checkpoint 承载。

Not applicable: Drake is not a chat model and has no LLM context window. State is carried by scene files, configuration, node state or checkpoints in user code; cross-session memory, prompt context and multi-turn dialogue management are outside its capability surface (2026-11-21).

权限与限制Permissions & limits

权限完全跟随操作系统与宿主进程。Drake 不引入账号、角色或云端 ACL。读取模型/场景、访问机器人设备与网络均按进程权限执行。涉及实机时，急停、设备访问和网络隔离由用户配置。

官方安装文档只列平台与依赖。未定义统一权限模型（2026-11-21）。

Permissions follow the OS and host process: Drake introduces no account, role or cloud ACL, and model/scene reads plus robot-device and network access inherit process permissions. On real hardware, emergency stop, device access and network isolation are user-configured; official installation docs list platforms and dependencies but define no unified permission model (2026-11-21).

适合什么任务Best for

适合：机器人动力学建模。接触/摩擦仿真。轨迹优化。控制设计与验证，以及需要暴露方程结构（稀疏性、解析梯度、多项式结构）的规划算法研究。

不适合：开箱即用的 ROS 导航栈。云端仿真服务或通用游戏引擎式内容制作（2026-11-21）。

Fit: robot dynamics modelling, contact/friction simulation, trajectory optimisation, control design and verification, and planning research that needs exposed equation structure (sparsity, analytical gradients, polynomial structure). Not fit: an out-of-the-box ROS navigation stack, a hosted simulation service or game-engine-style content production (2026-11-21).
