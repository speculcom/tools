LangGraph 是一个低层编排框架，专门用来构建有状态的 agent。

官方自述很克制，注意那个 low-level：

Low-level orchestration framework for building stateful agents.

它自认不是开箱即用的高层封装。 它打的是「长时间运行、有状态」这件事的地基。

LangGraph is a low-level orchestration framework for building stateful agents.

The official description is deliberately modest — note that word, low-level:

Low-level orchestration framework for building stateful agents.

It does not claim to be a batteries-included high-level wrapper. It lays the groundwork for long-running, stateful work.

适合与不适合When to use it, when not to

适合：agent 流程要跑很久且必须能从中断处精确恢复；要人工在流程中间介入并改状态； 要分开管理工作记忆与跨会话记忆；需要显式图结构（分支、循环、子图）。

不适合：需要内建沙箱或文件级权限边界（官方未提供此类机制，2026-10-08 核验）； 想要开箱即用的文件系统与子代理（走 Deep Agents）；不想额外依赖 LangChain 生态。

Fits: agent flows that run long and must resume precisely from an interruption; a human stepping into the middle of a flow to change state; managing working memory and cross-session memory separately; an explicit graph structure (branches, loops, subgraphs); teams on Python. Not a fit: needing built-in sandboxing or file-level permission boundaries (official docs do not provide such a mechanism — checked the README and the interrupts page); wanting a filesystem and sub-agents out of the box (go with Deep Agents, the higher-level package built on LangGraph); not wanting an extra dependency on the LangChain ecosystem — model access usually goes through it.

落盘粒度就是 superstep（图的一个步进）——

不是「会话结束时」，也不是「每轮对话后」

  • SqliteSaver —— 本地文件，开发用
  • PostgresSaver —— 生产，原文 "In production, use a checkpointer backed by a database"

另有 langgraph-checkpoint-* 的 MongoDB / Redis / Oracle 实现。

跨进程恢复靠数据库 + 同一 thread_id。 官方 durable-execution 页说可以 官方原文："resume workflows from the last successful checkpoint"

langgraph>=1.2 还给了 SIGTERM 的 graceful shutdown （drain 后存下可续跑的 checkpoint）。

未知：多进程并发写同一 thread 的冲突语义官方未说明。 ⚠ persistence 与 checkpointers 两页都没有写这一点。

This is its strongest dimension, with explicit official wording.

The first feature, Durable execution, reads verbatim:

The companion is the standalone subpackage langgraph-checkpoint. Check libs/checkpoint — the first paragraph of that subpackage's page:

The persistence granularity is the superstep (one graph step) —

not "at session end", not "after each turn"

上下文与记忆Context & memory

第三条特性 Comprehensive memory 官方原文是：

Create truly stateful agents with both short-term working memory for ongoing reasoning and long-term persistent memory across sessions.

短期记忆：官方 add-memory 页给了三条裁剪手段 —— Trim messages / Delete messages / Summarize messages。 这三条就是短上下文的管法：裁剪、删除、摘要。 该页对它们的定位是：

官方原文："techniques to manually remove or forget stale information"

长期记忆：用 store 存 JSON 文档。 官方称它支持语义搜索与内容过滤：

官方原文："supports both semantic search and filtering by content"

它可跨 thread 召回。

未知：「大工具输出落盘」官方未说明 LangGraph 提供。 ⚠ memory 与 add-memory 两页都没有 —— 那是上层 Deep Agents 的 context management 能力。

LangGraph splits "state" and "memory" into two mechanisms, both with official wording.

The third feature, Comprehensive memory, reads verbatim:

Create truly stateful agents with both short-term working memory for ongoing reasoning and long-term persistent memory across sessions.

Short-term memory: the official add-memory page gives three trimming techniques — Trim messages / Delete messages / Summarize messages. These three are how short context is managed: trim, delete, summarize. The page positions them as:

Official wording: "techniques to manually remove or forget stale information"

权限与限制Permissions & limits

官方给的是 human-in-the-loop。 它是「检查并修改状态」级别，不只是确认。

第二条特性 Human-in-the-loop 官方原文是：

Seamlessly incorporate human oversight by inspecting and modifying agent state at any point during execution.

文档在 langgraph/interrupts。

与其它对象对比，这一点有实质差别。 三者的介入层次递进，用行内列举是因为本解析器不支持嵌套块内的列表写法：

  • OpenAI Agents SDK 的 guardrail 是校验内容（输入/输出合不合规）
  • Google ADK 的 Tool Confirmation 是拦执行（这个工具要不要跑）
  • LangGraph 的 interrupts 是改状态（在任意执行点检查并修改图的状态）

⚠ 但要说清：它明确给的不是沙箱或权限边界。 官方文档未提及文件系统权限模型、网络访问控制、工具级白名单。 与本站收录的 OpenHands 对照。它有明确的 Docker 沙箱 + API key 机制。 也与 Codex SDK（源码里三档 SandboxMode 枚举）对照。 LangGraph 在这一维度上目前查不到官方机制。

What the official docs give is human-in-the-loop. It is at the "inspect and modify state" level, not just confirmation.

The second feature, Human-in-the-loop, reads verbatim:

Seamlessly incorporate human oversight by inspecting and modifying agent state at any point during execution.

The docs are at langgraph/interrupts.

Compared with other listed objects, this point differs substantively. The three intervention levels escalate; listed inline because this parser does not support lists inside nested blocks:

  • OpenAI Agents SDK guardrails validate content (are inputs/outputs compliant)
  • Google ADK Tool Confirmation intercepts execution (should this tool run)
  • LangGraph interrupts modify state (inspect and modify graph state at any execution point)

⚠ But say clearly: what it explicitly does not give is a sandbox or permission boundary. The official docs mention no file-system permission model, network access control, or tool-level allowlist. Contrast with OpenHands on our site, which has an explicit Docker sandbox + API-key mechanism. Also contrast with the Codex SDK (three SandboxMode enum values in source). On this dimension, no official mechanism can currently be found for LangGraph.

适合什么任务Best for

适合四类场景。

  • agent 流程要跑很久，且必须能从中断处精确恢复
  • 需要人工在流程中间介入并修改状态
  • 要把「工作记忆」与「跨会话长期记忆」分开管理
  • 需要显式图结构（分支、循环、子图）；团队用 Python

不适合三类场景。

  • 需要内建沙箱或文件级权限边界 —— 官方未提供此类机制（已查 README 与 interrupts 页）
  • 想要开箱即用的文件系统与子代理 —— 走 Deep Agents，它是 LangGraph 上的高层包
  • 不想额外依赖 LangChain 生态 —— 模型接入通常要经它

Four scenarios it fits.

  • Agent flows that run long and must resume precisely from the interruption point
  • Human intervention mid-flow that modifies state
  • Managing "working memory" and "cross-session long-term memory" separately
  • You need an explicit graph structure (branches, loops, subgraphs); your team uses Python

Three scenarios it does not fit.

  • You need a built-in sandbox or file-level permission boundary — the official docs provide no such mechanism (README and interrupts page checked)
  • You want batteries-included file system and subagents — go to Deep Agents, the higher-level package on LangGraph
  • You don't want an extra dependency on the LangChain ecosystem — model access usually goes through it

未知项清单Known unknowns

  • checkpoint 在跨机器 / 多进程并发下的写冲突与恢复语义
  • superstep 级落盘的性能与写入量代价
  • 长期记忆的具体存储后端（官方只给 store 抽象，未指明后端）
  • interrupts 修改状态后的重入边界
  • LangSmith 配套的免费额度与商业条款（报价按 D9 口径本站不采），以及不用它时 LangGraph 是否完整可用
  • Python 与 JS/TS 版的能力对齐度
  • Write-conflict and recovery semantics of checkpoints across machines / multi-process concurrency
  • Performance and write-volume cost of superstep-level persistence
  • The concrete storage backend of long-term memory (the official docs give only the store abstraction, no named backend)
  • The re-entry boundary after interrupts modify state
  • Free quota and commercial terms of the LangSmith companion (quotes not recorded per our D9 rule), and whether LangGraph is fully usable without it
  • Capability parity between the Python and JS/TS versions
