Firecrawl's official MCP server (MIT): the full web-context kit — search, scrape, PDF parsing, site-level crawl/map, real-browser interact, page monitoring. Three hard facts: the keyless free tier exposes only 3 tools; the release line is npm, not GitHub releases; the API key must never go into the server URL or the agent chat (explicit in the README). The repo moved from mendableai/ to the firecrawl/ org (301 confirmed).

适合与不适合When to use it, when not to

适合：要「搜索→抓取→结构化→浏览器交互→监控」全链一面包齐；keyless 起步再升 key。 不适合：要逐步驱动的长浏览器会话（README 明写不是它的模型）；只要单页读取的极简场景。

Fits: agents wanting the whole chain — search → scrape → structured JSON → browser interact → monitor — in one package; keyless start then upgrade to a key. Not a fit: long browser sessions driven step-by-step (the README says that is not its model); minimal single-page reading (the fetch reference is lighter).

模型与开放条件Model & openness

它自己不调模型——被 MCP 客户端调用的接口实现。它把 Firecrawl（「AI agent 的 context API」）的搜索/抓取/解析/浏览器交互包装成工具给 agent 用。

本地文件Local files

不读写本机文件——输出网页正文（markdown/结构化 JSON）与解析产物（PDF 等文档）。

Reads and writes no local files — it outputs web page text (markdown/structured JSON) and parsed artifacts (PDF and other documents).

关机后的任务Tasks after shutdown

托管线在 Firecrawl 侧；monitor 工具族可在 Firecrawl 侧按日程盯页面变更并出 diff/告警—— 这是「服务端任务」不是本机后台。

The hosted line lives on Firecrawl's side; the monitor tool family can watch page changes on a schedule on Firecrawl's side and emit diffs/alerts — that is a "server-side task", not a local background process.

The hosted keyless endpoint exposes only 3 (scrape/search/parse); the search-only endpoint is fixed at 9.

上下文与记忆Context & memory

无 server 侧跨会话记忆；interact 会话可经 scrapeId 跨调用续接（官方 README： 不能从客户端单调用内逐步驱动，每调用跑完一个 prompt/code 回合即交还控制权）。

No server-side cross-session memory; interact sessions can continue across calls via scrapeId (official README: you cannot drive it step by step from within a single client call — each call runs one prompt/code round and hands control back).

权限与限制Permissions & limits

keyless 免费档可用（scrape/search/parse 三工具，限流）；其余工具要 API key。 官方 README 三条硬口径：key 绝不进 server URL、绝不进 agent 聊天、 只配在客户端或 secret manager。OAuth 端点（/v2/mcp-oauth）走交互式账户连接。

The keyless free tier works (scrape/search/parse three tools, rate-limited); the other tools need an API key. Three hard rules from the official README: the key never goes into the server URL, never into the agent chat, only into the client or a secret manager. The OAuth endpoint (/v2/mcp-oauth) uses interactive account connection.

适合什么任务Best for

适合：要「搜索→抓正文→结构化 JSON→浏览器交互→站点级 crawl/map→页面监控」全链一面包齐的 agent； 要 keyless 起步再升 key 的渐进接入。 不适合：要长期持有浏览器会话逐步驱动（README 明写这不是它的交互模型）； 只要单页读取的极简场景（fetch reference 更轻）。

Fits: agents that want the full chain covered in one package — "search→fetch text→structured JSON→browser interaction→site-level crawl/map→page monitoring"; gradual onboarding that starts keyless and upgrades to a key. Not a fit: holding a browser session long-term and driving it step by step (the README states plainly this is not its interaction model); minimal scenarios that only need single-page reading (the fetch reference is lighter).

认证机制Authentication

keyless 免费档（限流）→ API key（Authorization Bearer，配客户端/secret manager） → OAuth 交互式连接（/v2/mcp-oauth）。本地 npx 线用 FIRECRAWL_API_KEY 环境变量。

Keyless free tier (rate-limited) → API key (Authorization Bearer, configured in the client/secret manager) → OAuth interactive connection (/v2/mcp-oauth). The local npx line uses the FIRECRAWL_API_KEY env var.

权限范围Permission scope

读面为主（搜索/抓取/解析/监控）；interact 能在真实浏览器里点击填表—— 「读」与「在网页上动手」的分界要按目标站点的授权边界自己把关。无本机写面。

Mostly read (search/fetch/parse/monitor); interact can click and fill forms in a real browser — the boundary between "reading" and "touching things on a web page" must be gated yourself against the target site's authorization boundaries. No local write surface.
