The browser session lives on Browserbase's cloud (start creates/reuses a session, end closes it); no local background process. The session lifecycle is managed explicitly by tool calls, not persistent.

6 个工具（README 口径，托管与自托管同工具集）：start（创建/复用会话）/ end（关闭会话）/ navigate（导航到 URL）/ act（按自然语言指令对页面动手）/ observe（观察可操作元素）/ extract（按指令抽取页面数据）。act/observe/extract 三件套由 Stagehand 的 act-and-observe 范式驱动。

6 tools (README wording; hosted and self-hosted share the same set): start (create/reuse a session) / end (close the session) / navigate (go to a URL) / act (manipulate the page from a natural-language instruction) / observe (observe actionable elements) / extract (extract page data per instruction). The act/observe/extract trio is driven by Stagehand's act-and-observe paradigm.

上下文与记忆Context & memory

无 server 侧跨会话记忆；上下文=当前 Browserbase 浏览器会话（start 可复用既有会话）。 会话内页面状态自然连续，跨会话不保。

No server-side cross-session memory; the context is the current Browserbase browser session (start can reuse an existing one). In-session page state is naturally continuous; nothing persists across sessions.

The hosted line needs a Browserbase account (API key + project id, configured in the client); the self-hosted line needs the BROWSERBASE_API_KEY/BROWSERBASE_PROJECT_ID/GEMINI_API_KEY environment variables. act manipulates real web pages (clicks/form filling) — gate the authorization boundary per target site; cloud session content is retained on Browserbase's side, so sensitive flows need your own assessment.
