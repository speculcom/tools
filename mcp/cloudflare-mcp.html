Cloudflare's official MCP server (Apache-2.0): agents write Workers, deploy, manage D1/R2/DNS, search official docs. It has the finest restricted-token granularity in its class — but remember 'can deploy = can run arbitrary code'; scope tokens to the minimum.

适合与不适合When to use it, when not to

适合：Cloudflare 栈的部署-调试闭环接 agent。 不适合：要「只读配置」硬边界（能收窄但要仔细配 token）。

Fits: deploy-debug loops on the Cloudflare stack plugged into agents. Not a fit: a hard 'config only, no deploy' boundary (narrowable, but token config must be careful).

权限与限制Permissions & limits

API token 权限=agent 权限：Cloudflare token 可细粒度限定资源与操作面—— 官方推荐用受限 token 接 MCP。这是同类里凭据粒度做得最细的一条线， 但「能部署代码到 Workers」意味着能跑任意代码——按此最坏面设防。

适合什么任务Best for

适合：Cloudflare 栈的 agent 部署流（写 Worker→部署→查日志）、docs 检索。 不适合：要「只配置不部署」的硬边界（token 粒度能收窄但要仔细配）。

传输方式Transport

远程 Streamable HTTP（官方托管端点）+ 本地 stdio 两线； 端点矩阵按产品分组（每产品一个远程 server URL）——以仓 README 为准。 核验：仓与 developers.cloudflare.com/changelog（2026-10-21）。

认证机制Authentication

Cloudflare API token（建议受限 token：限定账户/资源/操作）； OAuth 线支持状态未逐条核验。

权限范围Permission scope

读面：docs 检索、资源查询；写面：部署 Workers、建/改 D1/R2/KV、DNS 记录变更。 token 粒度是主收紧手段；无工具级审批机制的官方说明。

头号误解Top misconception

  • 用全权限全局 API key 接 agent——官方推荐受限 token，粒度差别巨大Plugging a full-scope global API key into an agent — the official recommendation is restricted tokens; the granularity difference is huge
  • 把「部署 Worker」当配置操作——那是往边缘跑任意代码的写面Treating 'deploy a Worker' as a config operation — that is pushing arbitrary code to the edge
  • 工具分组裁剪当审批层——裁剪是收窄暴露面，不是逐操作确认Reading tool-group trimming as an approval layer — trimming narrows exposure; it is not per-operation confirmation
