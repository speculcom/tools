先回答一件事：你到底缺什么能力Answer one question first: what capability are you actually missing

MCP 不是「让 AI 更聪明」，是给 AI 接上它本来够不到的东西。如果你要的只是聊天和写代码，你不需要它。你装，它调——这一大类收的 server 分四种出身：MCP 官方 reference server、由各自官方团队维护的（Playwright / Context7）、厂商官方自营的（GitHub 自己的 github-mcp-server），以及本站按收录标准纳入的社区 server。每份档案的出身与权限范围写在 scope 维里。MCP is not "making AI smarter" — it is giving AI access to what it could not otherwise reach. If all you want is chat and writing code, you do not need it. You install it, the AI calls it — 10 entries: 7 are the MCP org's reference servers, 2 are maintained by their own official teams (Playwright / Context7), and 1 is vendor-official (GitHub's own github-mcp-server).

    filesystem、gitfilesystem, git两个都是读写权限，git 那一类值得先看 scope 里能限制到哪些目录。Both have read and write permissions; for the git category it is worth checking what directories the scope can be limited to.

  3. 3我要让 AI 上网拿资料I need AI to reach the web for material
    context7、fetchcontext7, fetch风险最高的一类是 fetch：档案里引了官方警告——可访问本地与内网 IP，无地址白名单、无审批机制。fetch carries the highest risk: the entry quotes an official warning — it can reach local and internal IPs, with no address allowlist and no approval mechanism.
  4. 4我要控制真实浏览器I need to drive a real browser
    playwrightplaywright注意官方明确声明来源限制不是安全边界，需要真隔离得用 --isolated 或容器化网络策略。Note the official explicit statement that source restrictions are not a security boundary; real isolation requires `--isolated` or a containerised network policy.
  5. 5我要点时间 / 拆解推理 / 跨平台搜文件I want time / decomposition / cross-platform file search
    time、sequential-thinking、everythingtime, sequential-thinking, everything三个都是只读，风险最低。All three are read-only, so risk is lowest.
  6. 6我要操作 GitHub（仓库 / Issue / PR / Actions）I need to work with GitHub (repos / issues / PRs / Actions)
    看 github-mcpSee github-mcpGitHub 官方自营的 MCP server，与归档的旧参考 server 不是同一条线；权限由 GitHub token 决定，可收紧到只读。GitHub's own MCP server — not the same line as the archived reference server; permissions follow the GitHub token and can be tightened to read-only.

⚠ 一个容易忽略的维度：数据出境。Context7 默认以远程服务交付，查询内容会发到 Upstash 服务器；GitHub MCP Server 提供远程托管与本地 Docker 两种形态；其余八个都是本地 stdio 进程。另外——装 MCP 需要你手动做，调用不需要：server 启动后自动把工具清单报给你的客户端，之后调不调、什么时候调，由 agent 自己判断，你只在审批环节介入。⚠ An easily overlooked dimension: data leaving the country. Context7 is delivered as a remote service by default — queries go to Upstash's servers; GitHub MCP Server offers both a remote hosted and a local Docker form; the other eight are local stdio processes. And — installing an MCP server is manual; calling it is not: once running, the server reports its tool list to your client automatically, and after that the agent decides whether and when to call it. You only get involved at the approval step.

为什么这里不给总分排名Why there is no overall ranking

这不是省略，是方法上的明确取舍。This is not an omission but a deliberate methodological choice.

  • 缺统一实测，就不给分。跨工具的跑分口径不同——题目、预算、执行环境都不一样，A 的 90 分和 B 的 88 分不可比。No shared measurement, no score. Benchmarks across tools use different rules — different questions, budgets and environments. A 90 and a B 88 are not comparable.
  • 「未知」是合法答案。查不到就写「未知」并说明为什么，不用推测填充。缺信息本身也是信息。"Unknown" is a legitimate answer. If it cannot be found, we write "unknown" and explain why, instead of filling the gap with guesses. Missing information is itself information.
  • 来源链接、类型与核验日都在详情页里，可以逐条回去复核。The source link, its kind and the checked date are all on the detail page, so you can walk any of them back and re-check.
  • lifecycle 单独标注。核验日新不等于数据有效——上游归档后数据会失效，所以单独标 active / maintenance / archived。lifecycle is marked separately. A recent check date does not mean the data is still valid — it goes stale when upstream archives the repo, so active / maintenance / archived are tracked separately.
  • 不同族不混排。找现成的、自己搭的、接上与跑起来的是三种角色，坐标系不同；硬合成一张总表只会制造假的可比性。Families are not mixed. Ready-made tools, things you build yourself, and plug-in-and-run components are three different roles with different coordinate systems; forcing them into one master table would manufacture false comparability.
