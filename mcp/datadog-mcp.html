Datadog's self-run official MCP server (mcp.datadoghq.com/v1/mcp): agents query live production logs, metrics, traces and incidents while debugging. Three hard facts: credentials are passed through — RBAC applies as-is, the server cannot exceed the user; tools are grouped into toolsets, enable on demand; GovCloud is not compatible (stated outright). Honest note: no open-source repo; a separate local Code Security MCP Server exists — don't conflate them.

模型与开放条件Model & openness

它自己不调模型——被 MCP 客户端调用的接口实现。它把 Datadog 可观测数据 （logs/metrics/traces/dashboards/monitors/incidents/security signals 等）包装成工具给 agent 用。 官方文档口径：多数工具直查 Datadog 后端不经模型；少数语义检索/自然语言转查询类工具 会用 Datadog 的 AI 供应商托管的模型，可整组织关闭。

It calls no model itself — an interface implementation called by MCP clients. It wraps Datadog observability data (logs/metrics/traces/dashboards/monitors/incidents/security signals, etc.) as tools for agents. The official docs' position: most tools query the Datadog backend directly without a model; a few semantic-search / natural-language-to-query tools do use models hosted by Datadog's AI providers, and can be disabled org-wide.

An official hosted remote server (mcp.datadoghq.com/v1/mcp — direct fetch 401 = exists, auth required); there is also a local-binary line (the coterm.datadoghq.com install script installs datadog_mcp_cli, stdio connecting to remote tools). The official docs state plainly not GovCloud compatible; HIPAA-eligible.

服务在 Datadog 侧；会话请求-响应，无后台监听语义。 官方声明会收集 MCP 使用信息（工具名/参数/错误/用户标识，不含 prompt 与模型推理），存 120 天。

The service lives on Datadog's side; session request-response, no background-listening semantics. The official docs state that MCP usage information is collected (tool names/parameters/errors/user identifiers, excluding prompts and model reasoning), stored for 120 days.

No server-side cross-session memory — state lives on the Datadog platform itself; the official docs recommend trimming tools via toolsets to save context window.

权限与限制Permissions & limits

权限面是这条目的核心：官方明写 server 把已认证用户自己的凭据转发给 Datadog API—— RBAC/Data Access Control/日志限制查询原样生效，server 不能给用户越权。 写动作要对应权限（如 monitors_write），每次工具调用都检查；只读用户调写工具会被拒。 组织管理员可在 Organization Settings 管全局 MCP 访问与写能力，可开 IP allowlist。

The permission surface is the core of this entry: the official docs state plainly that the server forwards the authenticated user's own credentials to the Datadog API — RBAC / Data Access Control / log restrictions apply unchanged; the server cannot grant a user anything beyond their own access. Write actions require the corresponding permission (e.g. monitors_write), checked on every tool call; read-only users calling write tools get rejected. Org admins can manage global MCP access and write capability in Organization Settings, and can enable an IP allowlist.

认证机制Authentication

OAuth 2.0（推荐，客户端自动走流程；自定义子域要加 ?subdomain= 参数）； 或 PAT/SAT Bearer 头；或 DD_API_KEY + DD_APPLICATION_KEY 头（官方建议用带 scope 的 服务账号 key）。端点直抓 401=存在需鉴权。

OAuth 2.0 (recommended, clients run the flow automatically; custom subdomains need a ?subdomain= parameter); or a PAT/SAT Bearer header; or DD_API_KEY + DD_APPLICATION_KEY headers (the official docs recommend a scoped service-account key). The endpoint's direct-fetch 401 = exists, auth required.

权限范围Permission scope

读面大（logs/metrics/traces/dashboards/monitors/incidents 等按 toolsets 分组）； 写动作（建 monitor、改 case 等）要对应写权限、逐调用检查。 官方口径：MCP 工具调用全部进 Audit Trail（工具名/参数/用户/客户端）， 另有 datadog.mcp.session.starts 与 datadog.mcp.tool.calls 两个标准指标。

A large read surface (logs/metrics/traces/dashboards/monitors/incidents etc., grouped by toolsets); write actions (creating monitors, modifying cases, etc.) require the corresponding write permission, checked per call. The official position: all MCP tool calls go into the Audit Trail (tool name/parameters/user/client), plus two standard metrics, datadog.mcp.session.starts and datadog.mcp.tool.calls.
