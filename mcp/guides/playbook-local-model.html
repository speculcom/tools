任务：在自己的机器上跑一个模型Playbook: running a model on your own machine

规划Planning

显存、量化档、runtime、评估、监控五步；含体积算式、量化索引、失败模式与验收单。

Five steps — VRAM, quantization tier, runtime, evaluation, monitoring — with a size formula, the quantization index, failure modes and an acceptance list.

English summaries and interface labels are available. The guide body below is currently in Chinese.

显存：先算再下VRAM: calculate before downloading

权重体积 GB ≈ 参数量(B) × bpw / 8
KV 缓存 ≈ 2 × 层数 × 注意力头 × 头维度 × 上下文长度 × 字节数
总显存 ≈ 权重 + KV 缓存 + 运行时开销(约 10–20%)
  • 7B 模型 Q4 约 3.5–4 GB 权重；上下文越长，KV 缓存越吃显存。
  • 先定上下文长度，再定量化档；只按参数量算会低估。
  • 留出 10–20% 余量给运行时与碎片。

量化档：按索引选Quantization: use the index

本站 models 站快照（2026-10-30）：129 个量化仓、1,262 个量化档、1,337 个 GGUF 文件。

1. 按显存选档位：Q4 附近通常是平衡点。 2. 按量化者选仓：同模型不同人做的档，质量差别很大。 3. 按文件核对：同档多文件时看 bpw 与体积。 4. 不确定就下两个档，实测后再删。

Runtime：按硬件选Runtime: match the hardware

硬件首选备选
Apple 硅LM Studio（MLX）或 mlx-lmllama.cpp
单张 NVIDIALM Studio 或 llama.cppExLlamaV3（EXL3）
多卡 / 并发vLLMTensorRT-LLM
CPU / 边缘llama.cppOpenVINO
  • 桌面自用优先图形化；服务化优先 vLLM。
  • 注意工具许可证与权重许可证是两份文件。

评估：三类任务各 20 条Evaluate: 20 cases per task

1. 准备 60 条真实任务：问答、摘要、代码各 20 条，带标准答案。 2. 跑三档：Q4、Q5、Q8（或模型提供的相邻档），记录质量与速度。 3. 看四个指标：正确率、幻觉率、首 token 延迟、tokens/s。 4. 选档结论：写清「为什么这个档够用」，不要只写「感觉不错」。

失败模式：只测一个 prompt；真实任务一上就崩。

监控：上线后看什么Monitor after launch

  • 显存峰值、tokens/s、首 token 延迟、错误率。
  • 日志不要存原文输入；存哈希与长度，避免隐私风险。
  • 模型或量化档更新时，重跑评估集再切换。

成本算式Cost formula

一次性：硬件 + 下载流量 + 调试时间
持续：电费 + 维护 + 评估复跑
对比云端：月调用量 × 云端单价

不写具体电价与单价；按本地电价与官方定价页计算。调用量小的时候，云端通常更省。

验收单Acceptance checklist

  • [ ] 显存算式写清，含 KV 缓存与 10–20% 余量
  • [ ] 量化档与量化仓有版本记录
  • [ ] runtime 许可证与模型许可证分别核对
  • [ ] 60 条评估集跑完，四指标有记录
  • [ ] 选定档位写出理由
  • [ ] 监控指标与告警阈值就绪
  • [ ] 更新模型时的回滚方案就绪

常见失败模式Failure modes

  • 只算权重：忘了 KV 缓存，长上下文直接 OOM。
  • 只看参数量：没看激活参数与 MoE 结构，速度判断错。
  • 许可混淆：工具 MIT，权重却是非商用。
  • 无评估集：换档后质量下降没人发现。
  • 无监控：上线后显存峰值把机器拖死。
