Copy these four blocks for procurement and project records. Replace project fields. The permission matrix is an example risk policy, not a universal approval requirement.

1. Agent permissions

Operation | Example access | Approval | Record
Read repo files | Read | As authorized | As needed
Edit code | Write | As authorized | Yes
Run tests | Read/write test output | As authorized | Yes
Install dependencies | Write | Check project scope | Yes
Push remote | Write | Explicit authorization | Yes
Delete files | Delete | Appropriate authorization | Yes
Read production DB | Read | Restricted | Yes
Write production DB | Write | Higher-risk review | Yes

Use least privilege and define approval/recovery from actual risk and authority.

2. Model licensing

- [ ] Actual weight license: MIT/Apache-2.0/CC-BY/custom/etc.
- [ ] Commercial use and self-hosting
- [ ] Attribution and derivative obligations
- [ ] Restrictions on training other models with outputs
- [ ] User/revenue thresholds
- [ ] Terms inherited by quantized variants
- [ ] Tool license and weight license checked separately
- [ ] Source URL, version and checking date recorded

4. Cost calculation

Model: input tokens × input rate + output tokens × output rate
Retrieval: queries × query rate
Tools: calls × applicable fee
Labor: labeling/review/maintenance hours × relevant rates
Local deployment if applicable: hardware, kWh × electricity rate, transfer
Total: [ ] per month

Record source dates for rates and the exchange-rate basis.

常见误用Common misuses

  • 权限矩阵还应写明执行条件、确认方式和记录要求；只写“允许”不足以说明边界。
  • 许可只看工具：权重许可才是商用与否的关键。
  • 权利表事后补：素材来源记不清，只能重做。
  • 成本还需纳入检索、复核与维护；各项占比取决于实际项目。
  • “Allowed” alone leaves execution conditions and records unspecified.
  • Check actual weight terms as well as tool licensing.
  • Keep asset provenance while working; reconstructing it later is harder.
  • Calculate retrieval, review and maintenance alongside tokens; their shares vary by project.
