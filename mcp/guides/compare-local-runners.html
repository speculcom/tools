本地跑模型：Ollama / LM Studio / llama.cpp / vLLM 怎么选Local runners: Ollama vs LM Studio vs llama.cpp vs vLLM

规划Planning

按硬件、量化格式、并发与服务化四面选 runtime；桌面图形、单机脚本、生产服务是三条不同路线。

Choose by hardware, quantization format, concurrency and serving needs; desktop GUI, single-machine scripting and production serving are three different routes.

先问三件事Three questions first

  1. 你在什么硬件上跑：Mac 统一内存、单张 NVIDIA、多卡服务器，路线不同。
  2. 你要图形界面还是脚本：桌面应用与 CLI / server 是两种使用方式。
  3. 你要一个人用，还是多人并发：并发会改变 runtime 与服务配置的需求。
  1. What hardware will you use? Mac unified memory, one NVIDIA GPU and a multi-GPU server require different paths.
  2. Do you want a GUI or scripts? A desktop application and a CLI/server are different ways of working.
  3. Is this for one user or concurrent users? Concurrency changes runtime and serving requirements.

逐个适用条件When each fits

Ollama：适合快速把开源模型跑起来、给本地应用接 OpenAI 兼容端点。能力边界：工具是 MIT，但权重许可跟着模型走，商用前要单独查模型许可。什么情况下选另一个：要图形界面与 MLX 加速，选 LM Studio。

LM Studio：适合不写代码、要在应用内下载并起本地服务器的人；MLX + llama.cpp 双运行时是它的差异点。能力边界：应用闭源，条款全文未能直抓，商用前要读官网条款。什么情况下选另一个：要脚本化与可嵌入，选 Ollama 或 llama.cpp。

llama.cpp：适合要 CPU 运行、或要自己调量化与上下文的场景；GGUF 格式由它定义，models 站的量化索引按它的口径建。什么情况下选另一个：要图形化或一条命令，选 Ollama / LM Studio。

vLLM：适合要把模型做成多人并发服务的人；PagedAttention 管显存，OpenAI 兼容 server 直接对接现有客户端。能力边界：以 NVIDIA GPU 为主，不是单机开箱工具。什么情况下选另一个：只是本机自用，先看桌面或 CLI 运行器是否符合需求。

Ollama: a candidate for starting an open-weight model and connecting a local application to an OpenAI-compatible endpoint. The tool's MIT licence does not determine model rights; check each model's licence separately before commercial use. Consider LM Studio if you need a GUI and MLX.

LM Studio: a candidate for downloading models and starting a local server through an application without writing code. It offers MLX and llama.cpp runtimes. The application is closed-source; the full terms were not directly retrieved in this snapshot. Read the official terms before commercial use. Consider Ollama or llama.cpp for scripting and embedding.

llama.cpp: a candidate when you need CPU execution or control over quantisation and context configuration. It defines GGUF, whose conventions inform this site's model index. Consider Ollama or LM Studio when you prefer their startup or GUI workflow.

vLLM: a candidate for serving a model to concurrent users, with PagedAttention and an OpenAI-compatible server. This snapshot focuses on NVIDIA GPU serving, rather than a desktop GUI. For local personal use, examine a desktop or CLI runtime first.

量化档怎么选Picking a quantization tier

本站 models 站的快照（2026-10-30）是：129 个量化仓、1,262 个量化档、1,337 个 GGUF 文件。选档顺序：

  1. 先预算可用内存，包括上下文与运行器开销，再定档位。
  2. 再核对量化者使用的基座、方法、版本与说明；不能只凭量化者名字判断质量。
  3. 最后看文件：同档可能有多个 GGUF 文件，按 bpw、总体积与是否需要全部分片核对。

不写「某档一定最好」；模型、任务与硬件三者一起决定。

The model site's 2026-10-30 snapshot lists 129 quantisation repositories, 1,262 variants and 1,337 GGUF files. Work through:

  1. Budget available memory, including context and runtime overhead, before selecting a tier.
  2. Check the quantiser's source model, method, version and documentation. A quantiser name alone does not establish quality.
  3. Check the actual files: one tier can contain several GGUF files; verify bits per weight, total size and whether all shards are required.

There is no tier that is always best. Model, task and hardware constraints must be considered together.

常见误判Common misreads

  • 把「工具开源」当成「模型可商用」：许可证是两份文件。
  • 把「能跑」当成「跑得快」：显存、量化与并发三者一起决定吞吐。
  • 把「桌面应用」当成「生产服务」：并发与稳定性不是同一目标。
  • 把「GGUF 通用」当成「所有 runtime 都支持」：不同 runtime 的算子覆盖不同。
  • An open-source tool does not establish commercial rights for a model; the licences are separate.
  • Being able to load a model does not establish its speed. Memory, quantisation and concurrency affect throughput.
  • A desktop application and a production service have different concurrency and reliability requirements.
  • GGUF does not imply universal runtime support. Architecture and operator coverage vary by runtime and version.
