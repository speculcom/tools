先分清两类Choose the level you need

先写清需要控制的部分，再选 SDK。四个项目的抽象层不同，不宜把“低层”解释成能力少，也不能把某一种工具的执行方式推广到整个 SDK。

需求对应检查点
流程步骤与分支由应用明确控制图、状态、节点与中断恢复
多个 Agent 协作工具、handoff、调度与职责边界
跨轮保留上下文Session 后端、保留范围与恢复方法
工具接触文件、命令或网络执行进程、权限与隔离方式

Write down what your application needs to control before choosing an SDK. Their abstraction levels differ. Low-level does not mean fewer capabilities, and one kind of tool's execution model does not describe the whole SDK.

逐个适用条件When each fits

LangGraph：当你需要明确控制图、状态与恢复过程时，对照其持久执行与中断机制。开始前先写一个失败后如何恢复的流程，不只画成功路径。

OpenAI Agents SDK：当你需要 Agent 循环、工具和 handoff 时，对照其运行机制；需要跨轮上下文时检查 Sessions，不能笼统写成“没有状态管理”。模型兼容性按实际工具调用与响应能力确认。

Google ADK：当任务需要图、顺序、循环或并行工作流时，对照对应机制；官方也提供 Agent Runtime，不能把它概括为“只管图、不跑 Agent”。

Claude Agent SDK：当你要将 Claude Code 能力接入应用并定义工具时，对照 Python/TypeScript 版本。create_sdk_mcp_server() 创建的工具服务在 Python 应用进程内；这不表示整个 SDK 没有 CLI 子进程，也不能据此承诺端到端“无 IPC 开销”。

LangGraph: examine durable execution and interruption mechanisms when you need explicit graph, state and recovery control. Describe recovery from failure as well as the success path.

OpenAI Agents SDK: examine its runtime when you need an agent loop, tools and handoffs. For cross-turn context, inspect Sessions rather than describing it as having no state management. Check model compatibility against the tool-call and response capabilities you actually need.

Google ADK: examine graph, sequential, loop or parallel workflows for the appropriate task. Its documentation also provides an Agent Runtime; it is not merely a graph layer that cannot run agents.

Claude Agent SDK: examine the Python or TypeScript version when embedding Claude Code capabilities and custom tools. create_sdk_mcp_server() creates a tool server inside the Python application. That does not mean the whole SDK has no CLI subprocess or guarantee zero end-to-end IPC overhead.

核验事实Verification scope

2026-11-04 复核了四份官方文档中与本页机制对照有关的内容：LangGraph 概览、OpenAI Agents SDK 概览、Google ADK 文档入口与 Claude Agent SDK Python 参考。

重点修正三处边界：OpenAI Agents SDK 有 Sessions 与人在回路机制；ADK 有 Agent Runtime；Claude 的进程内 MCP 工具不等于整个 SDK 单进程。这里没有运行 SDK、做吞吐测试或核验所有版本的兼容性。

On 2026-11-04, this page's mechanism comparison was checked against four official documents: the LangGraph overview, OpenAI Agents SDK introduction, Google ADK documentation and Claude Agent SDK Python reference.

Three boundaries were corrected: OpenAI Agents SDK has Sessions and human-in-the-loop mechanisms; ADK has an Agent Runtime; Claude's in-process MCP tools do not make the entire SDK single-process. No SDK was executed, no throughput was measured, and compatibility across all versions was not verified.

常见误判Common misreads

  • 把框架提供持久化机制当成已经完成数据备份；需要核对后端、保留与恢复。
  • 把支持多个模型当成无成本替换；提示词、工具 schema 和评估要重新检查。
  • 把人在回路当成自动安全；审批点必须覆盖真正会产生影响的动作。
  • 把进程内工具当成不用隔离；文件、命令与网络权限仍需明确。
  • 只按功能名对照，不检查所用语言、版本与部署环境。
  • A persistence mechanism does not establish a working backup; check backend, retention and recovery.
  • Multiple-model support does not make substitution free; recheck prompts, tool schemas and evaluations.
  • Human-in-the-loop is not automatic safety; approval points must cover consequential actions.
  • In-process tools still need explicit file, command and network boundaries.
  • Feature names alone are insufficient; check language, version and deployment environment.
