Agent 框架：LangGraph / OpenAI Agents SDK / Google ADK / Claude Agent SDK 怎么选Agent frameworks: how to choose

规划Planning

按状态与持久化、人在回路、模型绑定与部署形态四面选；低层编排与开箱 harness 是两类东西。

Choose by state and persistence, human-in-the-loop, model binding and deployment; low-level orchestration and batteries-included harnesses are different classes.

English summaries and interface labels are available. The guide body below is currently in Chinese.

先分清两类Two classes

类别代表它替你做什么不管什么
低层编排LangGraph状态、图、持久化钩子文件系统、规划、记忆策略
多 agent harnessOpenAI Agents SDK多 agent 原语、handoff不替你做规划与记忆
图执行引擎Google ADK路由、扇出、循环、重试、状态、HITL不替你跑单个 agent
进程内 SDKClaude Agent SDK工具调用无 IPC、类型安全不绑定某个模型家族外的能力

一句话：要自己定流程，选低层；要少写胶水，选 harness；要图执行，选 ADK。

逐个适用条件When each fits

LangGraph：适合流程明确、要自己控制状态与中断恢复的团队；官方自述是 low-level orchestration，不替你做开箱封装。什么情况下选另一个：不想自己写状态机，选 OpenAI Agents SDK 或 ADK。

OpenAI Agents SDK：适合要多 agent 协作、又要 provider-agnostic 的团队；官方首段写明支持 OpenAI Responses / Chat Completions 与 100+ 其他 LLM。什么情况下选另一个：全栈在 Gemini 或 Claude，选对应 SDK 更少摩擦。

Google ADK：适合要图执行引擎、路由、扇出、循环、重试与 HITL 的团队；这些是官方 README 明列的第一项特性。什么情况下选另一个：只要轻量多 agent 原语，选 OpenAI Agents SDK。

Claude Agent SDK：适合要进程内工具、类型提示、少 IPC 开销的 Python 应用；外部 MCP server 照样支持，两者可混用。什么情况下选另一个：要跨模型供应商，选 LangGraph 或 OpenAI Agents SDK。

核验事实Dated facts

1. LangGraph 官方自述为 low-level orchestration framework for stateful agents（官方文档，2026-10 快照）。 2. OpenAI Agents SDK 官方首段写明 provider-agnostic，支持 100+ LLMs（官方文档，2026-10 快照）。 3. Google ADK 的图执行引擎支持 routing、fan-out/fan-in、loops、retry、state management 与 HITL（官方文档，2026-10 快照）。 4. Claude Agent SDK 的工具与应用同进程，无子进程管理，带类型提示；外部 MCP server 可混用（官方文档，2026-10 快照）。

常见误判Common misreads

  • 把「低层编排」当成「功能少」：它把决定权留给你，代价是你要写状态与持久化。
  • 把「provider-agnostic」当成「零成本换模型」：提示词、工具 schema 与评测都要重跑。
  • 把「有 HITL」当成「自动安全」：审批点设计错，照样会放过危险操作。
  • 把「SDK 同进程」当成「不用沙箱」：工具权限与文件边界仍要自己划。
