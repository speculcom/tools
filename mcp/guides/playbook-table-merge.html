Practice text keys, duplicates, conflicting amounts, ambiguous dates and unmatched records; deliver clean data, exceptions and reproducible checks.

先写合并规则Write the merge rules first

order_id 是订单主键，customer_id 是文本外键；保留 001 这样的前导零。只删除所有业务字段完全相同的重复订单，保留两个来源位置。相同主键但金额不同归入异常，不按文件名或读取顺序覆盖。

日期只接受已明确的 YYYY-MM-DD。03/11/2026 没有地区约定，不能擅自判断日月。客户主键不存在时留异常，不用名字猜配。两份输出是“通过规则的订单”和“待处理的订单 ID”，不能把异常单写成零金额订单。

order_id is the order key; customer_id is a text foreign key, including leading zeros. Deduplicate only orders with identical business fields, retaining both source locations. A shared key with different amounts is an exception, never a last-file-wins update.

Accept explicitly established YYYY-MM-DD dates. Without a locale, 03/11/2026 is ambiguous. An absent customer key is an exception; do not guess a match by name. Deliver accepted orders and unresolved order IDs separately, not zero-value replacements for exceptions.

处理步骤Processing steps

  1. 记录文件名、编码、分隔符、列名、行数。三个输入分别有 3、3、3 条数据行；其中订单共 6 条，客户表不计进订单总数。
  2. 以文本读取 ID，以十进制定点口径处理金额；保留原日期文字和来源文件行号。CSV 的引号和分隔符可能不同，先解析再判断，不按逗号硬拆。
  3. 先合并两份订单，再按 order_id 分组检查完全重复和冲突。A02 完全重复只算一次；A03 金额不同，不能静默丢一份。
  4. 检查客户表主键唯一后再连接。A04 的 009 没有客户映射，留下异常。
  5. 生成干净表、异常表和规则记录，重新导入输出检查，不覆盖输入。
  1. Record filenames, encoding, delimiter, columns and row counts. Each input has three data rows: six orders plus a separate three-row customer table.
  2. Read IDs as text and use decimal money arithmetic. Retain raw dates and source file line numbers. CSV quoting/delimiters vary; parse rather than splitting blindly on commas.
  3. Union the order inputs, then group by order_id to distinguish identical duplicates from conflicts. Count identical A02 once. Keep conflicting A03 unresolved.
  4. Verify customer-key uniqueness before joining. Customer 009 for A04 is unmapped.
  5. Export accepted rows, exceptions and a rules record; reimport the outputs without overwriting inputs.

可复制的任务说明Reusable task instruction

仅移除完全重复记录；同一 order_id 字段冲突不覆盖。

Treat IDs as text and money as decimal; retain source filename/line.
Remove only identical duplicates. Never overwrite conflicts for one order_id.
Quarantine ambiguous dates and missing customer mappings with reasons. Do not guess.
Return clean.csv, exceptions.csv, rules and row-count reconciliation.

验收与参考结果Acceptance and reference

  • 6 条原始订单变成 4 个不同 order_id；A02 的两个来源均保留。
  • 干净表仅 A01、A02，共 2 行，金额为 25.00 + 12.00 = CNY 37.00。
  • 异常表按订单 ID 计 2 行：A03 同时有金额冲突与日期歧义；A04 缺客户映射。原因可以拆成多行，但不得漏订单。
  • 所有输出 customer_id 仍为三位文本；无意外一对多扩张；无未说明的行消失。
  • A03 不进入已接受小计；异常金额没有被改成零。

对照参考 CSV 时先看主键集合和原因，再看数值，不能只比较总金额。新业务必须先约定更新优先级和日期口径，不能照搬本练习规则。

  • Six input orders become four distinct order IDs; retain both A02 sources.
  • Accepted rows are A01 and A02 only: two rows totaling CNY 37.00.
  • Two exception IDs: A03 has both amount conflict and date ambiguity; A04 lacks a customer mapping. Multiple reason rows are acceptable if no order disappears.
  • customer_id remains three-character text. No unexplained join expansion or dropped records.
  • Exclude A03 from the accepted subtotal without turning exception amounts into zero.

Compare key sets and reasons before totals. A different business must establish its own update precedence and date rules.

失败后查哪里When it fails

  • 行数突然增加：查连接键是否唯一、是否发生多对多连接。
  • 编号变 1：回原始文件重读文本列，不能在已丢失前导零的表里猜补。
  • 金额能对上但漏单：核对主键集合和异常清单，而非只算总和。
  • 输出列错位或无法读取：查看 文件排查；模型生成了额外列时看 工具参数排查。
  • Expanded row counts: check key uniqueness and many-to-many joins.
  • ID becomes 1: reread text IDs from the original; do not guess missing zeros after loss.
  • Correct total but missing orders: reconcile key sets and exceptions, not just sums.
  • Shifted/unreadable columns: see file troubleshooting; for invented columns, see tool-input troubleshooting.
