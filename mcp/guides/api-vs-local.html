这一篇讲什么What this guide covers

「API 还是本地跑」不是技术偏好，是四个约束的取舍：成本结构、数据与合规、延迟与吞吐、模型能力与更新。 四条轴里只要有一条是硬约束，路线基本就定了。 本篇不报具体价格；token 单价与硬件价格以官方页为准。

<!-- EN -->

"API or local" is not a technical preference but a trade-off across four constraints: cost structure, data and compliance, latency and throughput, model capability and updates. If any one of them is a hard constraint, the route is largely decided. This guide quotes no specific prices; per-token and hardware prices follow the official pages.

第一条：成本结构One: cost structure

路线主要成本什么情况下更省
API按 token / 按次计费，随用量线性增长低频、波动大、不想买卡
本地显卡 / 内存 / 电费 / 运维，前期固定高频、长期、已有硬件
混合本地兜底 + API 峰值有明显波峰波谷，且数据可分流

判断方法：把「每月输入 token + 输出 token」估出来，乘官方单价；再和「显卡折旧 + 电费 + 运维时间」比。 不要只比单价，要把闲置率算进去——本地显卡在低负载时也在折旧。

第二条：数据与合规Two: data and compliance

  • 数据不出域：本地或私有部署是唯一能承诺「原始数据不离开」的路线。
  • API 的数据条款：要读训练用途、留存周期、跨境传输与子处理者清单，不只看「不训练」一句。
  • 合规义务：面向公众提供服务时，备案、内容标识、生成内容安全评估可能是独立义务；本地跑不等于免除。

<!-- EN -->

- Data stays in-domain: local or private deployment is the only route that can promise raw data never leaves. - API data terms: read training use, retention, cross-border transfer and sub-processor lists, not just the "no training" line. - Compliance duties: serving the public may trigger filing, content labelling and safety evaluation duties; running locally does not exempt you.
  • Data stays in-domain: local or private deployment is the only route that can promise raw data never leaves.
  • API data terms: read training use, retention, cross-border transfer and sub-processor lists, not just the "no training" line.
  • Compliance duties: serving the public may trigger filing, content labelling and safety evaluation duties; running locally does not exempt you.

第三条：延迟与吞吐Three: latency and throughput

  • API：延迟由网络与供应商排队决定；高峰期可能限流。
  • 本地：延迟由显卡、量化档与并发决定；吞吐可以用批处理与张量并行提高。
  • 交互式：首 token 延迟比总吞吐更重要。
  • 批处理：总吞吐与单位成本更重要，可以排队。

<!-- EN -->

- API: latency depends on the network and provider queues; peak hours may be rate-limited. - Local: latency depends on the GPU, quantisation tier and concurrency; throughput improves with batching and tensor parallelism. - Interactive: time-to-first-token matters more than total throughput. - Batch: total throughput and unit cost matter more; queuing is acceptable.
  • API: latency depends on the network and provider queues; peak hours may be rate-limited.
  • Local: latency depends on the GPU, quantisation tier and concurrency; throughput improves with batching and tensor parallelism.
  • Interactive: time-to-first-token matters more than total throughput.
  • Batch: total throughput and unit cost matter more; queuing is acceptable.

第四条：模型能力与更新Four: model capability and updates

  • 前沿能力：闭源 API 通常先拿到新模型与新产品面（Deep Research、Agent、图像线等）。
  • 可控与可复现：本地权重可以固定版本、固定量化档，适合回归测试与离线环境。
  • 更新成本：API 升级通常无感；本地升级要重新下载、重新量化、重新测显存。

<!-- EN -->

- Frontier capability: closed APIs usually get new models and product surfaces first (Deep Research, agents, image lines). - Control and reproducibility: local weights can pin a version and quantisation tier, which suits regression tests and offline environments. - Upgrade cost: API upgrades are usually invisible; local upgrades mean re-downloading, re-quantising and re-testing VRAM.
  • Frontier capability: closed APIs usually get new models and product surfaces first (Deep Research, agents, image lines).
  • Control and reproducibility: local weights can pin a version and quantisation tier, which suits regression tests and offline environments.
  • Upgrade cost: API upgrades are usually invisible; local upgrades mean re-downloading, re-quantising and re-testing VRAM.

常见误判Common misreads

  • 把「本地」当成「便宜」：低频场景下，显卡折旧与运维通常比 API 贵。
  • 把「API 不训练」当成「数据不出境」：训练与跨境传输是两条条款。
  • 把「能跑」当成「能扛并发」：单机 demo 与生产吞吐是两件事。
  • 忽略量化损失：本地为了装下显卡常降档，质量与上下文长度都会变。

<!-- EN -->

- Mistaking "local" for "cheap": at low volume, GPU depreciation and operations usually cost more than API calls. - Mistaking "API does not train" for "data does not leave the country": training and cross-border transfer are separate clauses. - Mistaking "it runs" for "it handles concurrency": a single-machine demo and production throughput are different things. - Ignoring quantisation loss: local deployments often drop tiers to fit VRAM, changing quality and context length.
