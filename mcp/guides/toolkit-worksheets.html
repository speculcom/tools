怎么用这页How to use

模板内的比例、样本数、阈值和权限策略是示例。请按任务、授权与风险确定实际条件；填完表格不等于已经通过验收。

四张表用于评审会与上线前检查；复制到你的仓库，按项目填。

1. 项目立项检查表

- [ ] 目标一句话：要解决谁的什么问题
- [ ] 不做清单：明确不做什么
- [ ] 数据来源与许可：能否使用、能否留存
- [ ] 模型与工具：主选、备选、许可证
- [ ] 成本上限：月调用/硬件/人力
- [ ] 验收指标：三条可量化
- [ ] 失败回滚：谁负责、怎么退
- [ ] 时间盒：到哪天必须评审

2. 内容发布前检查表

- [ ] 事实：每条结论有来源与日期
- [ ] 引文：单条不超过 100 字符或一句
- [ ] 权利：图片/音乐/字体/数字人许可已登记
- [ ] 隐私：无客户姓名、订单号、密钥
- [ ] 标注：需要 AI 生成标注的平台已标注
- [ ] 版本：模型版本与生成参数已存档
- [ ] 可访问性：字幕、对比度、替代文本
- [ ] 回滚：发布后 24 小时内可撤

Copy these worksheets for project review and pre-release checks. Fill them for the actual project; their sample counts and thresholds are not universal standards.

1. Project kickoff

- [ ] One-sentence goal: whose problem is being solved
- [ ] Excluded work: explicit scope
- [ ] Data sources and rights to use/retain
- [ ] Model/tool primary, fallback and licenses
- [ ] Cost ceiling: calls, hardware and labor
- [ ] Three measurable acceptance conditions
- [ ] Failure recovery: owner and method
- [ ] Review date

2. Before publishing

- [ ] Facts have sources and dates
- [ ] Quotations respect this site's short-excerpt rule
- [ ] Image/music/font/likeness permissions recorded
- [ ] No customer names, order IDs or secrets exposed
- [ ] Required AI-content labels checked for the platform
- [ ] Model version and generation settings recorded
- [ ] Captions, contrast and alternative text checked
- [ ] Withdrawal/recovery procedure defined for the release

常见误用Common misuses

  • 目标之外也要写明不做什么，避免范围含糊。
  • 发布表只查事实：不查权利，最容易返工。
  • 单条迁移样本不足以覆盖多种任务，应按实际范围补充。
  • 泄露表只填一半：第三方子处理者最常被漏。
  • A goal without exclusions can leave scope unclear.
  • Check rights as well as factual accuracy before release.
  • A single migration example does not cover a varied workload.
  • Include subprocessors and all data paths, not just the chat interface.

已填示例：内部资料问答的立项记录Filled example: an internal document-Q&A project

这是虚构项目，用来演示如何填写，不是产品推荐或已完成部署。

字段已填内容
目标从已批准的内部说明中回答报销问题，并标出依据段落
范围不接生产系统，不修改订单，不替员工审批
数据先用虚构政策与问题；真实文档另核权限与使用范围
工具约束只能读取指定资料；不能执行材料中的指令
验收答案有依据；规则例外不漏；无答案时明确说明
失败处理引用不支持答案时停止发布该回答，保留问题与证据记录
成本分别记录输入、输出、检索、重试和维护；单价由负责人填当前来源

验收问题至少覆盖正常报销、例外条款和资料中没有答案三类。样本数量按任务范围确定，不能因为表格已填满就判断项目可以上线。

This fictional project demonstrates the worksheet; it is neither a product recommendation nor a completed deployment.

FieldFilled entry
GoalAnswer reimbursement questions from approved documents, citing paragraphs
ScopeNo production-system access, order edits or employee approvals
DataStart with fictional policies/questions; authorize actual documents separately
Tool limitsRead specified material only; do not execute instructions embedded in it
AcceptanceSupported answers, preserved exceptions and explicit no-answer handling
Failure handlingWithhold an unsupported answer and retain the question/evidence record
CostTrack input, output, retrieval, retries and maintenance separately; obtain current rates from their sources

Cover normal reimbursement, exceptions and absent answers. Select sample size from task scope; a completed form is not launch approval.

Then use the data-flow worksheet to record what the application, model API, logs and backups retain.
