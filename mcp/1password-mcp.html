1Password 官方 Environments MCP server（本地 stdio，随桌面应用）：凭据类 MCP 的安全边界判例—— agent 能建环境、列变量名、加变量、挂本机 .env，但 by design 密钥值永不回传给 agent； 敏感操作按 Environment 粒度弹桌面授权窗，企业可策略级开关。beta 阶段； 配套插件仓（Claude/Codex/Kiro）活跃（推送 2026-10-29）。 与社区「读 secret 值」那批 1Password MCP 是本质不同的两回事。

1Password official Environments MCP server (local stdio, rides the desktop app): the security-boundary precedent for credential-class MCPs — the agent can create environments, list variable names, add variables, mount local .env files, but by design secret values are never returned to the agent; sensitive operations pop a desktop authorization window per Environment, and enterprises can toggle it by policy. Beta stage; the companion plugin repos (Claude/Codex/Kiro) are active (pushed 2026-10-29). It is an entirely different thing from the community "read a secret value" 1Password MCPs.

适合与不适合When to use it, when not to

适合：让编码 agent 管开发密钥的环境侧（建/加/挂）而永远不接触明文；企业治理场景。 不适合：要 agent 运行时读密钥值；remote-only MCP 客户端；不用 1Password 生态。

Fits: coding agents managing the environment side of dev secrets (create/add/mount) while never touching plaintext; enterprise-governed scenarios. Not a fit: agents reading secret values at runtime; remote-only MCP clients; outside the 1Password ecosystem.

模型与开放条件Model & openness

它自己不调模型——被 MCP 客户端调用的本地 server（stdio，随 1Password 桌面应用跑）。 它的独特设计是安全边界在 server 侧：agent 管理 Environments（密钥托管容器）， 但 server 按设计永远不会把密钥值返回给客户端——agent 只见变量名与环境名。

It calls no model itself — a local server (stdio, running inside the 1Password desktop app) called by MCP clients. Its distinctive design is that the security boundary sits on the server side: the agent manages Environments (the secrets-holding containers), but by design the server never returns secret values to the client — the agent only ever sees variable names and environment names.

A local stdio server riding inside the 1Password desktop app (official docs: it runs locally as part of the 1Password desktop app); launch command 1password-mcp (client configuration) or registration via the official plugins (Claude Code /plugin install, the Cursor plugin marketplace, Codex/Kiro lines of their own). 本地文件Local files

能创建本机挂载的 .env 文件（locally mounted .env）——密钥按需对进程可用但不写盘 （官方口径：without writing them to disk）；这是它唯一的「本机面」，且是受控挂载不是自由读写。

It can create locally mounted .env files — secrets become available to processes on demand without writing them to disk (official wording); this is its only "local surface", and it is a controlled mount rather than free read/write.

关机后的任务Tasks after shutdown

无独立后台——server 进程随 1Password 桌面应用与 MCP 客户端会话；1Password 锁定时 授权窗口关闭（批准一次后「until 1Password locks」前不再弹授权）。

No standalone background process — the server rides the 1Password desktop app and the MCP client session; when 1Password locks, the authorization window closes (an approval stays valid "until 1Password locks" without re-prompting).

工具与扩展Tools & extensions

能力清单（官方文档口径）：创建/列出/重命名 Environments；列出 Environment 里的变量名 （不含值）；向 Environment 添加变量；创建本机挂载 .env；列挂载。没有「读取密钥值」工具 ——by design 拿不到值，这是它与一切「凭据读取型」社区 server 的本质分界。

Capability list (official docs wording): create/list/rename Environments; list the variable names in an Environment (never values); add variables to an Environment; create locally mounted .env files; list the mounts. There is no "read a secret value" tool — by design it cannot fetch values, which is the essential divide between it and every "credential-reading" community server.

上下文与记忆Context & memory

无 server 侧跨会话记忆；状态在 1Password 云端 Environments（跨设备同步是 1Password 账户能力， 不是 MCP server 的记忆）。授权按 Environment 粒度批准。

No server-side cross-session memory; state lives in 1Password cloud Environments (cross-device sync is a 1Password account capability, not MCP-server memory). Approvals are granted per Environment.

权限与限制Permissions & limits

权限模型是本档案核心：每次敏感操作触发 1Password 桌面应用的安全授权弹窗（per-Environment approval）；Enterprise 管理员可在 Policies > Agentic permissions 整体开关 Local MCP server。 要 1Password 账户 + 桌面应用 + 已建 Environment。beta 阶段（官方标注）。

The permission model is the core of this dossier: each sensitive operation triggers a secure authorization prompt in the 1Password desktop app (per-Environment approval); Enterprise admins can toggle the Local MCP server feature wholesale under Policies > Agentic permissions. Requires a 1Password account + the desktop app + an existing Environment. Beta stage (marked by the official docs).

权限范围Permission scope

Environments 管理面（建/列/改名/加变量/挂 .env）；无密钥值读取面（by design）； 本机面仅受控 .env 挂载。凭据类 MCP 里权限面最保守的一档。

The Environments management surface (create/list/rename/add variables/mount .env); no secret-value read surface (by design); the local surface is only the controlled .env mount. Among the most conservative permission surfaces of credential-class MCPs.

头号误解Top misconception

  • 把它当「给 agent 读 1Password 密码的 MCP」——by design 密钥值永不回传 agent；它是 Environments（开发密钥容器）管理面，不是密码库读取面Treating it as "an MCP that lets agents read 1Password passwords" — by design secret values never return to the agent; it is the Environments (dev-secrets container) management surface, not a vault-reading surface
  • 用 remote-only MCP 客户端——官方明写要 stdio 支持，server 在你机器上随桌面应用跑Using a remote-only MCP client — the official docs require stdio support; the server runs on your machine riding the desktop app
  • 混淆 Environments 与个人密码库（Vault）——它管的是 Developer Environments（.env 场景），不是浏览器自动填充那个库Confusing Environments with the personal password Vault — it manages Developer Environments (.env scenarios), not the autofill vault
  • 企业环境默认以为可用——Enterprise 管理员策略（Agentic permissions > Local MCP server）可整体关掉Assuming it works by default in enterprises — the admin policy (Agentic permissions > Local MCP server) can switch it off wholesale
  • 把社区「1Password MCP」（读 secret 值那批）当官方——官方只有这一条 Environments 线；读值类全是社区实现，安全模型完全不同Mistaking community "1Password MCPs" (the secret-value-reading bunch) for official — the official line is this Environments one only; value-reading implementations are all community, with a completely different security model
