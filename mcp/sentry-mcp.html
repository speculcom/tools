模型与开放条件Model & openness

它自己不调模型——它是被 MCP 客户端调用的接口实现，选模型是客户端的事。 它把 Sentry 平台能力（issue、事件、release、告警）包装成 MCP 工具供 agent 查询与诊断。

运行位置Where it runs

官方托管远程 server 为主（mcp.sentry.dev 直抓 200）；仓 getsentry/toolkit 是官方工具线 （936★，最近推送 2026-10-21，GitHub API 核验）。旧仓名 getsentry/sentry-mcp 已 redirect（直抓所见）。

本地文件Local files

不碰本机文件系统——它操作的是 Sentry 云端数据（issue/事件/release）。 本地日志与源码不在它作用域内；要读本地文件得配 filesystem server。

关机后的任务Tasks after shutdown

远程托管形态与客户端进程无关，服务在 Sentry 侧；无断点续跑语义—— MCP 会话模式是请求-响应，官方未提供后台任务机制。

上下文与记忆Context & memory

无跨会话记忆——每次会话独立，状态在 Sentry 平台本身。 官方未提供 server 侧记忆或检索层（未核验到≠没有，已查文档未见）。

权限与限制Permissions & limits

权限由 Sentry 账号鉴权决定（OAuth 登录流）；能读 issue 与事件数据， 写操作面（如解决 issue）以官方工具清单为准——未逐条核验写能力边界。

适合什么任务Best for

适合：编码 agent 直接查「这个报错在 Sentry 里有没有」、线上事故诊断接 agent 工作流。 不适合：要本地日志分析（不在作用域）；要 FSL 限制期内的闭源商用集成（先读许可条款）。

传输方式Transport

官方主推 Streamable HTTP 远程托管（mcp.sentry.dev）； 客户端配置以官方文档为准。SSE 老传输的支持状态未逐条核验。 核验：官方文档页与 mcp.sentry.dev 直抓 200（2026-10-21）。

认证机制Authentication

权限范围Permission scope
