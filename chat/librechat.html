LibreChat is a self-hosted multi-provider chat platform: one interface over Anthropic, OpenAI, Google, Bedrock and Ollama, with agents, MCP, code execution and enterprise authentication. MIT licensed.

适合与不适合When to use it, when not to

适合要自建团队 AI 入口的人。需要跨 provider 切换、Agent 与 MCP 工具，或对话检索。也适合想把模型密钥与聊天数据留在自己服务器上的组织。

不适合只要一个轻量单模型前端的人。MongoDB、MeiliSearch 与沙箱都要维护。也不适合把 MIT 许可误当成模型权重或业务数据的合规许可。

A fit for: teams that need one self-hosted interface across providers, with agents, MCP tools and enterprise SSO/LDAP. Not a fit for zero-maintenance SaaS, or teams that only need a single-provider client.

模型与开放条件Model & openness

依据： 多 provider 聚合：Anthropic、AWS Bedrock、OpenAI、Azure OpenAI、Google/Vertex AI、 OpenAI Responses API，以及任何 OpenAI 兼容端点与 Ollama。模型与密钥由部署者配置。 模型选择在会话内可切换。具体 provider 清单以官方 Features 页为准。

Multi-provider aggregation: Anthropic, AWS Bedrock, OpenAI, Azure OpenAI, Google/Vertex AI, the OpenAI Responses API, any OpenAI-compatible endpoint and Ollama. Models and keys are configured by the deployer and can be switched inside a conversation; check the official Features page for the current provider list.

运行位置Where it runs

自托管 Web 应用。Docker Compose（自带 MongoDB、MeiliSearch、RAG API）或 npm 手动部署。也可一键部署到 Railway。

数据与推理凭据留在你的服务器，不经 LibreChat 云端。

Self-hosted web app: Docker Compose (with MongoDB, MeiliSearch and a RAG API) or a manual npm deployment; one-click Railway deployment is also offered. Data and inference credentials stay on your server and do not pass through LibreChat’s cloud.

本地文件Local files

支持附件上传、RAG API 文档检索与 Code Interpreter 沙箱。文件与向量索引存在自有 MongoDB/存储中。沙箱执行环境由你部署，隔离强度取决于运行配置。

Attachment upload, RAG API document retrieval and a Code Interpreter sandbox. Files and vector indexes live in your MongoDB or storage, and the sandbox is yours to deploy; isolation depends on the runtime configuration.

关机后的任务Tasks after shutdown

Scheduled Chats 可按周期让 Agent 新建会话并运行提示。Code Interpreter 与 Agent 任务在服务端执行。关机续跑取决于实例与沙箱是否常开。

Scheduled Chats can create a new conversation and run a prompt on a schedule; Code Interpreter and agent tasks run server-side. Whether they survive shutdown depends on whether the instance and sandbox stay running.

MCP servers, OpenAPI Actions, Agents, Skills, Subagents, Agent Plugins and Code Interpreter; tool approval and Tool Search are configured in the agent instructions.

Multi-user auth (OAuth2, LDAP, email), roles and groups, Admin Panel, rate limits, automated moderation and token spend statistics; enterprise SSO and fine-grained permissions depend on the deployment.

适合什么任务Best for

适合：要一个自托管。多模型。带 Agents/MCP/RAG 的团队聊天平台，并能接受 MongoDB。MeiliSearch 与沙箱的运维。不适合：只要单模型轻量前端，或不愿维护数据库。

Fits: teams that want a self-hosted, multi-model chat platform with agents, MCP and RAG, and can operate MongoDB, MeiliSearch and a sandbox. Does not fit: a single-model lightweight front end, or teams unwilling to maintain a database.

与 Open WebUI 的差别

两者都是自托管多模型聊天界面，差别在重心。Open WebUI 更偏「模型聚合 + 知识库 + 权限」。LibreChat 更偏「Agents + MCP + 代码沙箱」。要 RAG 与多用户管理优先看 Open WebUI。

要 Agent 编排、Subagents 与 Code Interpreter，LibreChat 的面更完整。两者都能接 Ollama，不存在互斥。
