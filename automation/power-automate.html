模型与开放条件Model & openness

AI 能力来自 Microsoft Copilot 与 AI Builder（预置/自定义模型）。底层模型未披露。也可通过 HTTP、自定义连接器或 Azure 服务调用外部模型 API。

可选的模型档位与区域可用性未逐项核验。

AI capabilities come from Microsoft Copilot and AI Builder (prebuilt and custom models); the underlying model is not disclosed. External model APIs can be called through HTTP, custom connectors or Azure services. Model tiers and regional availability were official docs do not itemize every sub-detail.

运行位置Where it runs

云端 SaaS。cloud flows 在 Microsoft 租户内运行。desktop flows 跑在用户 Windows 机器 或 Microsoft 托管机器上。

设计器为浏览器 + Windows 桌面应用，执行不在你的本地进程里。

Cloud SaaS: cloud flows run inside the Microsoft tenant; desktop flows run on a user’s Windows machine or a Microsoft-hosted machine. The designer is browser plus Windows desktop, and execution is not in your local process.

本地文件Local files

cloud flows 经 SharePoint、OneDrive、Dataverse 等连接器读写文件。desktop flows 能直接操作本机文件、Excel 与 legacy 应用界面。

托管机器形态下文件在 Microsoft 环境。

Cloud flows read and write files through SharePoint, OneDrive, Dataverse and other connectors; desktop flows can operate local files, Excel and legacy application UIs. With hosted machines, files live in the Microsoft environment.

关机后的任务Tasks after shutdown

cloud flows 可由定时、事件或 webhook 触发，用户关机不影响。desktop flows 分 attended （需登录会话）与 unattended（需机器或托管运行时）。

关机后无人值守能否跑取决于运行时。

Cloud flows can be triggered by schedule, event or webhook and are unaffected by a user shutting down a laptop; desktop flows split into attended (needs a signed-in session) and unattended (needs a machine or hosted runtime). Whether an unattended flow survives shutdown depends on the runtime.

工具与扩展Tools & extensions

依据： 官方文档口径的组件包括连接器生态，官方称数百个。还有自定义连接器、Copilot、AI Builder、桌面 UI 自动化与 approvals。可调 Power Platform 其他服务与 Azure API。

A connector ecosystem (Microsoft says hundreds; not itemized in official docs one by one), custom connectors, Copilot, AI Builder, desktop UI automation and approvals; other Power Platform services and Azure APIs can be called.

上下文与记忆Context & memory

flow 级变量、run history 与 Dataverse 状态存储。没有跨 flow 的通用 Agent 记忆。长流程状态要靠显式变量/表设计，不是模型上下文。

Flow-level variables, run history and Dataverse state storage. There is no general cross-flow agent memory; long-flow state must be designed as explicit variables or tables, not model context.

权限与限制Permissions & limits

依托 Entra ID、环境（environment）与连接凭据。管理员用 Power Platform admin center 配 DLP 策略、环境角色与连接权限。

终端用户权限跟随租户与连接账户。

Entra ID, environments and connection credentials. Admins set DLP policies, environment roles and connection permissions in the Power Platform admin center; end-user rights follow the tenant and the connected account.

适合什么任务Best for

适合：Microsoft 生态内的审批。邮件。SharePoint/Dataverse 流程与 Windows RPA。以及需要企业治理与审计的自动化。

不适合：非 Microsoft 为主的技术栈。纯代码编排也不适合。要求自带任意模型的场景，同样不适合。

Fits: approvals, email, SharePoint/Dataverse processes and Windows RPA inside the Microsoft estate, especially where enterprise governance and audit are required. Does not fit: non-Microsoft stacks, pure-code orchestration, or bringing your own arbitrary model.

两种 flow 别混为一谈
