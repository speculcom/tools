适合与不适合When to use it, when not to

适合：要控制量化档、后端与每个参数的用户。也适合消费级 GPU 与 Apple 硅跑 GGUF，给自研工具做推理底座。 不适合要开箱 GUI。也不适合要多模型高并发服务化，那是 vLLM/SGLang 的调度强项。

Fits: fine-grained control (quant tiers/backends/params), GGUF on consumer GPUs and Apple silicon, powering in-house tools. Not a fit: out-of-the-box GUIs; multi-model high-concurrency serving.

模型与开放条件Model & openness

GGUF 生态根。官方 server 支持 F16 与量化模型在 GPU/CPU 推理。模型可从 Hugging Face 取 GGUF，也可自转 safetensors。支持模型族随合入滚动，量化档由社区量化者产出（2026-11-21）。

The root of the GGUF ecosystem: the official server runs F16 and quantised models on GPU/CPU, with models taken from Hugging Face as GGUF or converted from safetensors; supported model families roll with merges, while quantised files come from community quantisers (2026-11-21).

运行位置Where it runs

C/C++ 推理库，另有 llama-server。OpenAI 兼容 /v1/chat/completions、/v1/completions、embeddings 与 responses，另有 Anthropic 兼容 /v1/messages。

构建后端覆盖 CPU、Metal、SYCL、CUDA、HIP 与 Vulkan，自带 Web UI（2026-11-21）。

A C/C++ inference library plus llama-server: OpenAI-compatible /v1/chat/completions, /v1/completions, embeddings and responses, and an Anthropic-compatible /v1/messages. Build backends cover CPU, Metal, SYCL, CUDA, HIP and Vulkan, with a built-in web UI (2026-11-21).

本地文件Local files

全本地。模型权重、KV cache、对话与生成物都在自有机器。--kv-offload 可把 KV cache 放 GPU，--no-kv-offload 留 CPU。官方无云托管线（2026-11-21）。

Fully local: model weights, KV cache, conversations and outputs stay on the user’s machine; --kv-offload moves KV cache to GPU while --no-kv-offload keeps it on CPU, and there is no official cloud-hosted line (2026-11-21).

关机后的任务Tasks after shutdown

llama-server 常驻即服务。连续批处理默认开启。-np/--parallel 配多 slot，--ctx-checkpoints 保留上下文检查点。适合常开进程，托管队列由部署方自建（2026-11-21）。

llama-server is a long-running service: continuous batching is on by default, -np/--parallel sets slot count and --ctx-checkpoints retains context checkpoints. It suits an always-on process, with any hosted queue built by the deployer (2026-11-21).

工具与扩展Tools & extensions

工具面强。--jinja 开 OpenAI 风格 function calling 与 tool use。它含原生格式与通用回退，覆盖任意模型。

实验性 --mcp-servers-json 接 Cursor 兼容 MCP server。--agent 开内置工具与 CORS 代理。

另有 schema 约束 JSON、多模态、reranking 与监控端点（2026-11-21）。

A strong tool surface: --jinja enables OpenAI-style function calling/tool use with native formats plus a generic fallback for any model; experimental --mcp-servers-json connects Cursor-compatible MCP servers; --agent enables built-in tools and a CORS proxy; plus schema-constrained JSON, multimodal, reranking and monitoring endpoints (2026-11-21).

上下文与记忆Context & memory

上下文按运行参数控制。-c/--ctx-size 设 prompt 窗口，--kv-unified-per-slot 给每个并行 slot 限额。

-ctk/-ctv 可把 KV cache 压到 q8/q4 等类型，--ctx-checkpoints 最多留 32 个检查点（2026-11-21）。

Context is controlled at launch: -c/--ctx-size sets the prompt window, --kv-unified-per-slot caps each parallel slot, -ctk/-ctv compress KV cache to q8/q4 types and --ctx-checkpoints retains up to 32 checkpoints (2026-11-21).

权限与限制Permissions & limits

MIT 许可，本地进程无账号体系。llama-server 用 --api-key 或 --api-key-file 做 Bearer 鉴权。

MCP/agent 默认关闭。开启时出于安全默认把 CORS 限到 localhost。官方明确提示勿在不可信环境启用（2026-11-21）。

MIT licensed with no account system for the local process; llama-server authenticates Bearer keys via --api-key or --api-key-file; MCP/agent are off by default and, when enabled, restrict CORS to localhost for safety, with official warnings against untrusted environments (2026-11-21).

适合什么任务Best for

适合要细粒度控制的人，包括量化档、后端、上下文与 KV cache。也适合消费级硬件跑 GGUF。

还适合给下游工具做本地推理底座，在 server 层接 MCP 或工具调用。不适合要开箱 GUI。也不适合要多模型高吞吐服务化，后者 vLLM/SGLang 更强（2026-11-21）。

Fit: fine-grained control over quantisation, backends, context and KV cache; GGUF on consumer hardware; a local inference base for downstream tools; MCP/tool calling at the server layer. Not fit: turnkey GUIs or high-throughput multi-model serving (vLLM/SGLang are stronger there) (2026-11-21).
