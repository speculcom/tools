Ollama 是「本地跑开源模型」的事实标准入口：一条命令装完，从官方模型库一键拉模型， 本机起一个 OpenAI 兼容 API。诚实标注：工具 MIT，但权重许可跟着模型走；官方 README 明写还有云端线。

Ollama is the de-facto entry point for running open models locally: one command installs it, the official model library pulls models in one click, and an OpenAI-compatible API comes up on your machine. Honest notes: the tool is MIT but weight licenses follow each model; the official README explicitly mentions a cloud line.

适合与不适合When to use it, when not to

适合：快速把 DeepSeek/Qwen/Llama 这类开源模型跑起来、给本地应用接 OpenAI 兼容端点、桌面与服务器同一套命令。 不适合：高并发服务化调度（vLLM/SGLang 更合适）；对云端线数据边界有硬要求但没逐条核验过。

Fits: getting DeepSeek/Qwen/Llama running with one command, OpenAI-compatible local endpoints, desktop and server alike. Not a fit: high-concurrency serving (vLLM/SGLang), hard data-boundary requirements on the cloud line.

本地文件Local files

模型权重与对话数据默认落本机；云端模型的提示与响应按 ZDR 瞬时处理、不存储不记日志、不用于训练；账号只保留基础信息与不含内容的用量元数据（Cloud FAQ）。

Model weights and conversation data land on your machine by default. On Ollama Cloud, prompts and responses are processed transiently under ZDR — not stored, not logged, not used for training; the account keeps basic details and content-free usage metadata (Cloud FAQ).

本机运行无账号即可用（API server 默认本机监听）；云端线用 Ollama 账号/API key 登录，API key 在设置页管理，数据面按 Cloud FAQ 的 ZDR 与账号删除条款。

Runs locally with no account needed (the API server listens locally by default); the cloud line signs in with an Ollama account / API key, managed in settings, with the data surface governed by the Cloud FAQ ZDR and account-deletion terms.

第一次怎么用

  1. 安装后先跑 ollama --version，确认服务已启动。
  2. 从官方模型库拉一个模型；权重许可跟着模型走，商用前单独查。
  3. 本机默认起 OpenAI 兼容端点，客户端把 base URL 指过来即可。
  4. 显存不够时先降量化档，再考虑 CPU 卸载；不要直接换卡。
  5. 官方 README 另写有云端线；本地与云端是两条计费与数据路径。
ollama pull <model>
ollama run <model>
