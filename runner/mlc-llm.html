模型与开放条件Model & openness

自带编译式推理引擎（MLCEngine）。它不是调外部模型的服务，而是把模型编译成目标平台的原生执行码。

依据： 官方定位是「Universal LLM Deployment Engine with ML Compilation」。模型侧吃 safetensors 系，走 HF 权重编译路线。

这与 llama.cpp 的 GGUF 预量化路线是两条根。

Ships its own compiled inference engine (MLCEngine) — not a service calling an external model; it compiles models into native executables for the target platform (the official positioning: "Universal LLM Deployment Engine with ML Compilation"). On the model side it takes the safetensors family (the HF-weights-compile route), a different root from llama.cpp's pre-quantized GGUF route.

编译-部署型 CLI/库：pip 装 mlc-llm，命令是 mlc_llm。覆盖平台矩阵是它的主打面。

平台含 NVIDIA、AMD 与 Intel GPU，走 CUDA、Vulkan、ROCm 与 OpenCL。Apple Metal 含 iOS 与 iPadOS。Web 浏览器走 WebGPU 加 WASM，姊妹项目是 WebLLM。Android 走 OpenCL。

本地文件Local files

读写本机文件。模型权重编译产物缓存在本地，编译配置是 JSON。REST server 跑在本机端口。

编译步骤本身产出平台特定产物。这是它与「下载即跑」型 runner 的操作差。

Reads and writes local files — model weights (compiled artifacts cached locally), compile-config JSON; the REST server runs on a local port. The compile step itself produces platform-specific artifacts (its operational difference from "download-and-run" runners).

权限与限制Permissions & limits

本机运行无鉴权默认（REST server 本地端口）。权限面=本机文件与 GPU 访问。无云账户、无遥测声明面。

Local runs are unauthenticated by default (REST server on a local port); the permission surface = local files and GPU access. No cloud account, no telemetry disclosure surface.
