让 Agent 操作浏览器：哪一层该谁负责Let an agent drive a browser: which layer does what

浏览器 Agent 常被当成一个产品，其实是四层：浏览器运行时（会话、Cookie、代理）、页面理解（DOM / 视觉 / 可访问性树）、动作执行（点击、输入、等待）与审计（截图、日志、回放）。这页把四层分别对应到已有条目。A browser agent is often sold as one product, but it is four layers: browser runtime (sessions, cookies, proxies), page understanding (DOM / vision / accessibility tree), action execution (click, type, wait) and audit (screenshots, logs, replay). This page maps each layer to an existing entry.

这是一张“谁负责哪一段”的集合页，不重复写产品档案；点进去看每个条目的八维记录、来源与边界。This is a “who owns which layer” collection, not a duplicate of product dossiers; open an entry for its eight axes, sources and boundaries.

最小跑通顺序Minimum working order

  1. 先用确定性脚本跑通一个站点，确认选择器、等待与错误页Run one site with a deterministic script first; confirm selectors, waits and error pages
  2. 再把「选哪个元素」交给模型，保留截图与动作日志Then let the model choose the element, keeping screenshots and an action log
  3. 最后加会话隔离、代理与人工审批；不要在登录态上共用浏览器Finally add session isolation, proxies and human approval; never share a browser session across logins

边界Boundary

站群没有做过「同一站点多套浏览器 Agent」的成功率对比；这类成功率高度依赖站点改版、反爬与登录态，必须按你的目标站点复跑。涉及账号、支付与个人数据时，先确认服务条款与授权，不要用 Agent 绕过验证码或访问控制。The sites have not run a success-rate comparison across browser agents on the same site; success depends heavily on site changes, anti-bot measures and login state, so re-run on your target site. For accounts, payments and personal data, confirm the terms and authorisation first; do not use an agent to bypass CAPTCHAs or access controls.
