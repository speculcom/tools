Ragas is an evaluation library installed in your own project: its main axis is replacing a feel-based look at outputs with named, repeatable metrics — LLM-judged metrics plus traditional non-LLM metrics, with test-data generation. Against the other two in this category, it delivers metrics and datasets as artefacts, not a benchmark registry or a task runtime.

When to use it, when not to

Fit: existing RAG or agent apps that want to score every change in code and keep results; no evaluation data yet, so test sets must be generated; metrics wired into an existing stack such as LangChain or LlamaIndex, or into observability tools. Not fit: expecting one command to run a public benchmark and treating the result as a conclusion, needing sandboxes and tool approval to constrain model behaviour, or unwilling to pay the extra API calls and time for LLM judging.

Model & openness

The judging model is written straight into the README's metric example: AsyncOpenAI plus llm_factory("gpt-4o", ...), with the note "Make sure your OPENAI_API_KEY environment variable is set". The docs site lists LLM Providers (Amazon Bedrock, Google Gemini, OCI Gen AI) and has Customise models and LLM Adapters pages, plus Traditional non LLM metrics that need no model at all. The per-provider support matrix was not inventoried.

Where it runs

A pip install ragas Python library: evaluation runs inside your own process through evaluate() / aevaluate(), and the docs also have a CLI section. The README adds ragas quickstart rag_eval -o ./my-project to scaffold a template project. Whether any official hosted surface exists: no official text captured in this pass (the README offers only Discord, blog and a contact address).

Local files

The inputs are your own data: the docs treat Datasets, Evaluation Sample and Testset Generation (RAG, agents, personas, single- and multi-hop queries) as core objects, and the front page claims built-in dataset management and result tracking. Where results, caches and generated test sets land on disk, and whether anything is uploaded by default: not stated officially.

Tasks after shutdown

Execution control lives in the library: the docs table of contents lists Run Config, Executor, Caching and Cancelling Tasks, and the README example calls metric.ascore(...) through asyncio - long runs are your own process and your own async calls. Who resumes work after the machine shuts down, and whether a task queue exists: not stated officially.

Tools & extensions

Extension is code-level: the docs front page says custom metrics can be created with simple decorators. The integration surface in the table of contents splits three ways - Frameworks (LangChain, LangGraph, LlamaIndex, Haystack, AG-UI, Griptape, Swarm and more), Observability (Arize, LangSmith) and LLM Providers. MCP integration method: not verified in this pass.

Context & memory

"Context" in Ragas is the object being measured, not its own memory: the RAG metric family covers Context Precision, Context Recall, Context Entities Recall, Noise Sensitivity, Faithfulness and Response Relevancy (docs Available Metrics listing), and the site also lists Evaluating Multi-turn Conversations. Cross-session memory: not stated officially.

Permissions & limits

Apache-2.0 (LICENSE text read directly). The README has an Open Analytics section stating that minimal, anonymized usage data is collected, that the collection code is open source in the repository, and that aggregated data is public, with "To opt-out, set the RAGAS_DO_NOT_TRACK environment variable to true". Retention and training use by the model provider your data passes through: no official terms captured in this pass.

Best for

Fits: attaching LLM-judged metrics to a RAG or agent application, generating a test set when you have none, and building a change-evaluate-observe-iterate loop inside your own code and CI. Not a fit: expecting one command to run a public benchmark registry and treating its output as a conclusion, needing sandboxing or tool approval as runtime boundaries, or refusing the API-call cost of judge models.

First run

  1. Settle the judging model first: the README example needs OPENAI_API_KEY, and before switching provider read the docs pages on LLM Providers and Customise models.
  2. pip install ragas; to start from a template, use ragas quickstart rag_eval -o ./my-project.
  3. Without evaluation data, generate a test set first; with data, configure a first round from the RAG metric family (Context Precision / Recall, Faithfulness, Response Relevancy).
  4. If you do not want anonymized usage data, set RAGAS_DO_NOT_TRACK to true (README wording).
  5. Put the evaluation into your change flow and compare metric movement on the same dataset, not somebody else's ranking.
