It is a policy layer attached to inference calls, and it can also evaluate content without invoking a model. The official docs separate two uses: calling a model with a guardrail ID and version, or ApplyGuardrail, which sends content to the guardrail without starting a model call.

When to use it, when not to

Fit: teams whose models mostly run on Bedrock, where policy, console and SDK are one line and data-retention modes can act as an admission gate. Not fit: teams that need the guardrail code inside their own environment (that is the local-library line), or anyone expecting one guardrail to behave the same across clouds. Per the official support page, guardrail-to-model mapping must be checked model by model in the model card, not inferred by model type.

Model & openness

It guards the models you invoke on Bedrock. The support page records that a guardrail applies to InvokeModel / InvokeModelWithResponseStream / Converse / ConverseStream on the bedrock-runtime endpoint, and that the bedrock-mantle endpoint does not support guardrails. Most catalogue models work; embeddings, rerankers, speech and a few text models listed on that page do not, and attaching a guardrail to them fails with ValidationException. ApplyGuardrail evaluates content on its own, so it also works for applications outside Bedrock.

Where it runs

Hosted cloud: regional APIs plus the Bedrock console. Detection executes on AWS's side, and the Standard tier uses cross-Region inference. No local or offline form is recorded on the official pages; a guardrail is a cloud resource with a working draft and versions.

Local files

It does not touch your workspace files: content is submitted through the API or the console test window. The data-protection page warns against putting confidential information into tags or free-form Name fields, because those may end up in billing and diagnostic logs.

Tasks after shutdown

Primarily synchronous evaluation; the official Guardrails docs have no hosted long-running queue or keep-running-after-shutdown entry; cross-region inference and retention follow the region page, and evaluations return per request.

Tools & extensions

Policy surface on record: content filters (Hate / Insults / Sexual / Violence / Misconduct / Prompt Attack), denied topics, word filters, sensitive-information filters (PII blocked or masked, with custom regex), contextual grounding checks and Automated Reasoning checks. Tagging lets only part of the user input be evaluated, and that capability is exposed through the SDK / API rather than the console.

Context & memory

It evaluates text and image per request and keeps no session memory. Language coverage is tier-split: Classic supports English, French and Spanish, Standard covers more languages (tier page on record). A dedicated supported-languages page exists but its full list was official docs do not itemize every sub-detail.

Permissions & limits

Retention is an explicit mode: none / default / aws_review / (legacy) provider_data_share / inherit, resolved as project then account then the model default. Recorded on the official pages: model providers get no access to customer prompts and completions; retained content is held inside the AWS boundary for up to 30 days; models requiring human review are simply unavailable under none or default. IAM and SCPs can enforce organisation-wide zero retention. Compliance certificate details were official docs do not itemize every sub-detail and are recorded as unknown.

Best for

Fits: teams whose models mostly live on Bedrock, who want the guardrail attached to the inference call itself, and who need governance switches for zero retention versus human review. Not a fit: teams needing self-hosted rails (the local-library line), one policy spanning several clouds, or anything depending on a mainland-China region.

Licence and terms of use

Commercial cloud service under the AWS Service Terms and the shared-responsibility model (recorded on the data-protection page, direct-fetched 2026-11-06); content rights still follow the terms of whichever model you pick.

Test notes

This site has not completed measured runs; nothing here covers block rates, latency or cost.

Suggested measurements (three):

  • How the same guardrail judges the same sample set under Classic versus Standard
  • What breaks in a workload when the account mode is set to none and a review-requiring model turns unavailable
  • Latency and result consistency between ApplyGuardrail and a guardrail attached to the inference call

Capability boundaries

The tier difference is substantive: only the Standard tier covers harm hidden inside code elements, cross-Region inference and prompt-leakage detection, and it raises the denied-topic limit from 200 to 1,000 characters (tier page on record). Classic keeps English, French and Spanish. Standard contextual grounding works in a region subset and fails validation elsewhere. Automated Reasoning checks are a separate thing: they validate model answers against logical rules, which is not the same as content filtering.
