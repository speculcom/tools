Braintrust is an observability platform that treats evaluation as a release gate. Its official self-description on file is an active observability platform, with evaluation, human feedback and production scoring in one panel.

When to use it, when not to

Fit: teams that want experiment comparison in PRs and CI and are willing to host the observability stack with a vendor: datasets feed experiments, code, judge and autoevals scorers run in parallel, and production traces get online scoring. When data must stay in-house it offers a hybrid customer-side data plane plus vendor-side control plane, but the control plane remains vendor-side; full self-hosting is not its model. This entry records supported evaluation surfaces, not scores or peer rankings.

Model & openness

You bring the models used for evaluation: official pages are on record that OpenAI and Anthropic credentials are configured under Settings → Models (direct-fetched today). The scorer surface splits into code, LLM judges and autoevals (guides/evals fetched today). The full list of supported judge vendors, and whether calls are unified through the gateway, were not itemized — recorded as unknown.

Where it runs

The main interaction surface is the browser console (the docs' positioning today is "active observability platform"); evals can also run locally and in CI through the bt CLI (/cli fetched today). The data plane can be deployed into the customer environment while the control plane stays vendor-side, holding authentication, user management and metadata (/self-hosting fetched today).

Local files

By default the data sits vendor-side; with the customer-side data plane, PostgreSQL, Redis, object storage and Brainstore run in your own environment (fetched today), while the control plane keeps only authentication and metadata. The platform does not read your local codebase; the bt CLI reads and writes local eval configuration and syncs data (on record today).

Tasks after shutdown

Production traces are scored asynchronously via online scoring (guides/evals fetched today), and experiments run datasets in batch for regression comparison. Sampling ratios, scoring latency and alert timing are touched on in official troubleshooting pages but were official docs do not itemize every sub-detail — recorded as unknown.

Tools & extensions

The bt CLI installs via curl, npm, pnpm or mise and runs evals locally and in CI, manages functions, queries logs and syncs data (fetched today); SDKs cover Python and TypeScript; the docs index is on record with an OpenTelemetry trace-sending integration page whose body was not fetched. MCP support is not itemized in official docs in official statements — recorded as unknown.

Context & memory

Traces, experiments and datasets are compared in one panel; the human-review surface supports multiple scores on a single row (on record from official pages today). Dataset versioning and comparison semantics were not read — recorded as unknown; cross-session memory is not a feature surface for this class of platform.

Permissions & limits

Compliance and encryption are on record from today's fetch: AES-256, SOC 2 Type II and HIPAA, plus the statement that inference inputs and outputs are not stored by the model host (/security). Tier and quota facts run from free to paid tiers with custom enterprise retention, and quotas vary with trace volume, data volume and monthly score counts (pricing fetched today); price numbers are excluded per D9. Whether data trains models was not found in clause text — recorded as unknown.

Best for

Fits teams that treat evaluation as a release gate — running experiments on PRs and in CI — and would rather not operate the whole observability stack. When data must stay in your own environment there is a hybrid "customer data plane plus vendor control plane" deployment, but the control plane remains vendor-side, so full self-hosting is not its model. Not a fit for teams intending to redistribute the platform. This site records supported evaluation types, not scores, and does not rank.

Test notes

  • Hybrid upgrade cost: migration risk for Brainstore and object storage when following the data-plane v2.21.0 line
