Inspect is an open evaluation framework from the UK AI Security Institute, with Meridian Labs. It uses Python to combine Dataset, Solver and Scorer into a Task and runs inspect eval in your own environment. Sandboxing, tool approval and local logs keep untrusted model code under control. The docs also position it as an authoring and reuse artefact for frontier AI evaluations, not a hosted scoring service.

When to use it, when not to

Fit: writing your own evals and agent tasks, including multi-agent and external agents; putting untrusted model code into Docker or Kubernetes sandboxes; batch-running eval sets in a terminal and reviewing every sample in local logs; reusing one task definition across providers. Not fit: wanting a hosted console with a few clicks, a metric library without maintaining Python evaluations, or treating someone else's scores as the deliverable; this entry does not use it that way either.

Model & openness

Official wording: the docs front page states "Built-in support for over 20 model providers" and names local inference with HuggingFace, vLLM and SGLang. The quick-start tabs pair pip install openai + export OPENAI_API_KEY, then Anthropic, Google and hf/... + HF_TOKEN. Each runs with --model openai/... style selectors. The full provider list and per-provider capability differences were not inventoried.

Where it runs

pip install inspect-ai into your own Python environment. The main entry point is the terminal command inspect eval; the docs example is inspect eval simpleqa.py --model .... The same page lists the web-based Inspect View tool for monitoring and visualising evaluations and a VS Code extension for authoring and debugging. Execution happens on your machine inside the sandbox you choose. An official hosted cloud line is not stated officially.

Local files

An evaluation is a Task written in .py (Dataset + Solver + Scorer). Datasets can be loaded straight from HuggingFace with hf_dataset(). The docs front page lists "over 200 pre-built evaluations ready to run on any model". Its table of contents has Log Files, Inspect View and Task Views entries. The default log directory name and file layout are not itemised in official docs verbatim in this pass.

Tasks after shutdown

This is local batch execution. The docs table of contents lists Running Eval Sets, Parallelism, Handling Errors, Setting Limits, Checkpointing and Intervention. In other words, parallel eval sets, checkpoints and human intervention are documented concepts. Whether a task continues elsewhere after your machine shuts down is not stated officially; Inspect is not a hosted service.

Tools & extensions

The docs front page lists built-in bash, python, text editing, web search and computer tools, and states support for custom and MCP tools. The table of contents adds Tool Approval, Tool Result Review, Agent Bridge and Extensions. The same page describes running arbitrary external agents as the subject under test, naming Claude Code, Codex CLI and Gemini CLI.

Context & memory

The table of contents lists Compaction, Caching, Fallbacks, Multimodal and Structured Output on the model side. It also lists Multiple Scorers, Scoring Policy and Model Grading on the scoring side. Cross-session memory is not its model: one evaluation run, one log. Default compaction strategy and thresholds have no official text captured in this pass.

Permissions & limits

MIT, with the LICENSE text read directly; the copyright holder is the UK AI Security Institute. It runs in your environment, and model calls go through the providers and keys you configure. The docs front page describes a sandboxing system for "running untrusted model code" in Docker, Kubernetes, Modal, Proxmox and Vagrant via an extension API. The table of contents adds Sandboxing, Approvers, Hooks and Filesystems. Telemetry and data-upload terms have no official statement captured in this pass.

Best for

Fits: writing your own evals and agent tasks, putting untrusted model code into a sandbox, keeping tool approval plus local logs for sample-by-sample review, and running one task definition across 20+ providers. Not a fit: wanting only a hosted console, needing a metric library without maintaining Python evaluations, or treating somebody else's leaderboard numbers as the deliverable.

First run

  1. Decide the model access first: the official quick-start pattern is "install the matching SDK + export the API key", and local inference goes through HuggingFace / vLLM / SGLang.
  2. pip install inspect-ai, then run the first task with inspect eval <task.py> --model <provider/model>.
  3. If the model executes code or touches files, read the official Sandboxing position first and put the task into a sandbox backend such as Docker, then consider tool approval.
  4. To go through results sample by sample use the Inspect View tool listed in the docs; for authoring and debugging the official docs recommend (but do not require) the VS Code extension.
  5. For batch runs, use the docs entries on Eval Sets and Parallelism rather than writing your own loop.
