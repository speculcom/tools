Protect AI's open-source LLM input/output scanning toolkit: one side screens prompts (injection, invisible text, secrets, toxicity, banned topics), the other screens completions (bias, malicious links, sensitive data, factual consistency). It is a scanner collection you deploy, not a hosted guardrail service.

When to use it, when not to

Fit: teams embedding pre- and post-checks in their own pipeline and willing to own dependencies and model downloads; the docs give two forms, a Python library and an API server. Not fit: expecting continued upstream updates, since the README warning says the project is archived and the Hugging Face models are unmaintained. Also not for readers looking for detection-rate numbers: the official material only lists channels, and this site runs no end-to-end tests.

Model & openness

It guards the text going into the model and the text coming back, not any vendor's model itself. The README's starter example goes through ChatGPT / the OpenAI API (examples/openai_api.py), and the documentation index lists two delivery forms as of the verification day: a Python library and an API server. Which scanners need downloaded local weights and which need an external inference service was only captured at documentation-index level; not verified item by item, recorded as unknown.

Where it runs

Self-hosted: pip install llm-guard runs in your own environment; the README requires Python 3.9 or newer, while the PyPI package metadata measured today states =3.10 and 3.13 (the two disagree; logged in the unknowns list). The docs index also gives an API server path, i.e. hosting the scanners inside your own service as pre/post checks. No vendor-side computation is described in the official text.

Local files

Both the README and the documentation index describe the object of processing as prompt / completion text; no capability to read workspace files or traverse directories is declared. Support for file-shaped inputs (attachments, directories) and any temp-file behaviour on disk is not stated officially.

Tasks after shutdown

As a library it lives and dies with your process; as an API server it is a service you keep resident, with start/stop and scaling in your hands. Managed queues, continuation after shutdown and asynchronous tasks are not stated officially.

Tools & extensions

The README lists 15 Prompt scanners and 21 Output scanners, covering input channels such as PromptInjection, InvisibleText, Secrets, Anonymize, Toxicity, BanTopics, Regex and TokenLimit, and output channels such as Bias, MaliciousURLs, Sensitive, FactualConsistency, Relevance, JSON and LanguageSame. The documented configuration model is thresholds plus mask / block / answer style disposition actions. MCP integration is not stated officially.

Context & memory

Detection operates on the single text passed in; no session memory, cross-turn context or historical attack store is described officially. Context-length limits are set by scanners like TokenLimit; the concrete defaults were not verified and are recorded as unknown.

Permissions & limits

The licence is MIT (see the license field, judged against the official LICENSE text), so commercial use and redistribution are permitted with the copyright notice retained. Data flow is the dimension with the biggest gap here: neither the README nor the documentation index captured today states telemetry, log retention, or the scope of sending text to third parties, so it is recorded as unknown. Compliance certifications (SOC 2 class) were not mentioned on the pages reached. The repository is archived and the official text says it is no longer actively maintained.

Best for

Fits teams that want input/output checks wired into their own pipeline, can own dependencies and model downloads themselves, and accept that the ruleset stops being updated. Does not fit deployments needing continued security-rule maintenance or a hosted SLA, nor readers looking for detection or bypass rates — this site runs no end-to-end tests and quotes no vendor numbers.

Licence and terms of use

MIT (official LICENSE opens with "The MIT License (MIT)"; copyright line "Copyright (c) Protect AI. All rights reserved."). Open source; usable after pip install llm-guard, with no vendor API key stated as a runtime prerequisite; advanced scanners install dependencies on demand.
