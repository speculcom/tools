PSA Intelligence's open-source command-line checker: before you or your agent open an external document set, it statically finds canaries, trackers, remote beacons and per-recipient fingerprints. It is not a model I/O guardrail or a prompt-injection classifier; it is pre-contact anti-tracking screening.

When to use it, when not to

Fit: a first static check when taking over leaked files, legal disclosure or investigation material, and batch rechecks in a pipeline. Not fit: understanding whether natural-language instructions were tampered with, or real-time interception of model input and output; the official text captured on 2026-11-06 describes its surface as analysis of file structure, metadata, embedded objects and near-duplicate fingerprints.

8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

Neither the README nor the documentation index reached today treats "whose model" as a configuration item: detection is described as static analysis of raw file structure, metadata, embedded objects and near-duplicate fingerprints. The documentation index states, as of the verification day, offline operation with no LLM and no API key involved. Whether any stage ever consults a model is not stated officially.

Where it runs

A local command-line tool with two documented installs: pipx install canary-scan (the README expects you to provide system tools such as exiftool, qpdf, poppler-utils, mupdf-tools, ripgrep, unzip and p7zip) and the container image ghcr.io/psaintelligence/canary-scan:latest, which the README recommends because the image bundles those system tools. PyPI metadata measured today requires Python 3.10 or newer.

Local files

Reading the file set you supply is the core action: the Docker example mounts the data source read-only (-v /mnt/datasource:/data:ro) and writes results to a separate output directory. The README states inspection happens without opening a file in its native viewer, deliberately avoiding remote references that documents may contain. Per-stage artefacts land in .canary-scan/.

Tasks after shutdown

A batch command run per invocation, not a resident service. No daemon, task queue or incremental-watch mode is stated officially; periodic re-scans have to be scheduled by you.

Tools & extensions

The command surface listed by the documentation index for the day is scan, stage, report and deps, plus --guide for a cheat sheet. Reporting is JSON (the example filters severity=="critical" with jq), so it drops straight into scripts and pipelines. The seven-stage pipeline is inventory, metadata, remote-refs, embedded, stego, uniqueness and report, each writing one JSONL artefact. MCP or other extension points are not stated officially.

Context & memory

Each scan is self-contained; there is no session memory. Cross-file linkage comes from the uniqueness stage's near-duplicate fingerprints and the stage artefacts. Historical baselines, cross-run comparison stores and retention policy are not stated officially.

Permissions & limits

Licensed Apache-2.0, with BSD 2-Clause for bundled scripts (see the license field). On data flow: the README and documentation index captured today declare no telemetry, no reporting and no external service calls, with "offline" being the wording given by the documentation index; a formal network-isolation clause is not published. On the supply chain, the official text says third-party Python dependencies are pinned with uv's exclude-newer to releases no newer than 14 days, and the bundled scripts are fixed at build time via make vendor with provenance recorded.

Best for

Fits a static pre-flight over externally supplied document sets (leaks, legal disclosures, investigation material) to find anything that could reveal to the external party that the data source is being examined — tracking pixels, remote templates, beacons, per-recipient fingerprints. Does not fit judgement calls about tampered natural-language instructions, nor runtime interception of model input/output: the official text positions it as pre-contact document inspection, not a model-I/O guardrail.

Licence and terms of use

Apache-2.0 (per the README License section, the LICENSE file and the PyPI classifier). The README also states the bundled third-party scripts pdfid, pdf-parser and rtfdump are BSD 2-Clause, with provenance recorded in src/canary_scan/bundled/VERSIONS.txt. Open source, with no model or API key required.

Official command surface and pipeline

Usage points given by the README and docs index (2026-11-06):

  • Container: docker run --rm -v /mnt/datasource:/data:ro -v $(pwd)/canary-scan-out:/output ghcr.io/psaintelligence/canary-scan:latest scan /data -o /output
  • Host: pipx install canary-scan, then install libimage-exiftool-perl qpdf poppler-utils mupdf-tools ripgrep unzip p7zip-full, then canary-scan scan /mnt/datasource
  • Subcommands: scan / stage / report / deps; --guide prints a cheat sheet
  • Seven stages: inventory → metadata → remote-refs → embedded → stego → uniqueness → report, each writing one JSONL file into .canary-scan/
  • Report: canary-scan-out/canary-scan-report.json; the example filters severity=="critical" with jq

Supply-chain terms (key points of the official README): third-party Python dependencies are pinned to releases no newer than 14 days via uv's exclude-newer; the Didier Stevens scripts are fixed at build time with make vendor, with commit SHA, version and date recorded in src/canary_scan/bundled/VERSIONS.txt.
