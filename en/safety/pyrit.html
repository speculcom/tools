PyRIT is Microsoft's build-your-own-red-team toolkit for local runs (MIT, moved from Azure/PyRIT to microsoft/PyRIT): the repo describes automated scans, adaptive multi-turn attacks and a web UI; the official docs define it as assessing the security and safety of generative AI systems at scale. The split from garak is clean: garak defaults to one command against one endpoint; PyRIT defaults to orchestrating targets, converters, scorers, memory and attack strategies in Python into a repeatable assessment.

When to use it, when not to

Fit: orchestrating adaptive multi-turn attacks (the docs name Crescendo and TAP) into a repeatable assessment; a local memory backend that writes the process into your own SQLite or Azure SQL; reviewers using the CoPyRIT interface to inspect results one by one; adding garak-style probes to the same scan flow, as the official scenario page shows with pyrit_scan run garak.prompt_inject. Not fit: wanting one command and done, a hosted report platform or compliance deliverable, or expecting the tool to replace red-team judgement.

Model & openness

Two sides both need models: the target under red-team, and the side driving the attacks. The repository front page names targets covering "OpenAI, Anthropic, Azure OpenAI, Microsoft Foundry, Azure Machine Learning, Google Gemini, Google Vertex AI, AWS Bedrock, Hugging Face, Ollama, Groq, OpenRouter, Cohere, and GitHub Copilot", with protocols written as "HTTP, WebSockets, browser automation with Playwright, or custom targets"; the docs 'latest' page compresses this into Any Target. On credentials the official wording is "PyRIT loads API credentials from environment variables or .env files", with OPENAI_CHAT_ENDPOINT / OPENAI_CHAT_KEY / OPENAI_CHAT_MODEL as the sample variables.

Where it runs

Installed into your own Python environment: pip install pyrit (PyPI records requires-python =3.10,3.15, current version 1.1.0). The repository front page offers three entry points — a "command-line scanner", a "graphical interface" (CoPyRIT), and an "extensible Python framework"; the docs spell the CLI as pyrit_scan and pyrit_shell, and the GUI as interactive exploration with results reviewed in the browser. Execution happens on your own machine; whether any hosted execution surface exists: no official statement captured.

Local files

It reads local configuration and .env credentials, and writes scan artefacts and state. The docs page states "Built-in Memory" has two backends, SQLite and Azure SQL — the first lands in a database file on your machine, the second in your own database. Default SQLite filename and path, plus cleanup and export methods: not itemized in official docs word for word in this pass.

Tasks after shutdown

Local semantics for long tasks are all present: adaptive multi-turn attacks and scenarios advance inside local processes, and results can be reviewed in the CoPyRIT interface (repository front page: "Explore AI systems interactively and review results in your browser"). A hosted queue that "keeps running after shutdown": not stated by the vendor — it is not a managed service.

Tools & extensions

Component surface on record in the docs: Automated Red Teaming (Crescendo and TAP named), Scenario Framework, Any Target, Built-in Memory, Flexible Scoring, plus the targets/converters/scorers/memory/orchestrators module split. The direct interface with another archive in this category: a dedicated docs page says the Garak scenario family "implements probes inspired by the Garak framework", run as pyrit_scan run garak.prompt_inject --target openai_chat. MCP support: not described in the official docs, recorded as unknown.

Context & memory

Adaptive multi-turn attacks depend on revisitable conversation state, and that state lives in the memory backends above; the docs list "adaptive multi-turn attacks" alongside the scenario catalogue. The boundary of cross-session memory, and any compaction or truncation strategy: no itemised official text captured in this pass, recorded as unknown.

Permissions & limits

Licence: MIT, copyright holder Microsoft (LICENSE read directly). Ownership needs one recorded fact: the original Azure/PyRIT repository page states "PyRIT has moved! Please see https://github.com/microsoft/PyRIT!", and this archive files the post-migration repository. Data flow: probe and attack prompts go to the target endpoint and the attack-model endpoint you configured, credentials are loaded from environment variables or .env (see the model_access axis), and run records land in your own SQLite/Azure SQL. Whether telemetry is on by default, and retention clauses: no official statement captured, moved to unknowns. It is an evaluation and forensics tool that does not block, so this site writes no "what share it stops" ratio and cites no scenario-report numbers.

Best for

Fits: orchestrating multi-turn adaptive attacks (Crescendo, TAP) into a repeatable assessment; needing to compose targets/converters/scorers yourself in Python; letting non-engineering reviewers go through results in a local GUI; teams already folding garak-style probes into one scan pipeline. Not a fit: wanting a single command that scans one endpoint and ends there (that is garak's default shape); needing hosted reports and compliance deliverables; expecting it to replace human red-team judgement.
