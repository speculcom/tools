Phoenix is an open-licensed observability and evaluation platform that runs on your own machine or cluster. Its evaluation model is an evaluator attached to a dataset, and its licence is Elastic License 2.0.

When to use it, when not to

Fit: teams already using OpenTelemetry as the map and wanting batch comparison experiments in notebooks: traces arrive, settle into datasets, evaluators run with each experiment, and scores stay traceable to the source call. Not fit: teams that only want a vendor-hosted console, or teams that want to resell Phoenix as a service; ELv2 explicitly forbids offering the software as a hosted or managed service, and the LICENSE was on file that day. This entry records which evaluation types it supports, not scores.

Model & openness

The platform is not tied to model vendors; the evaluation surface has three layers — LLM-as-judge, custom Python and TypeScript evaluators, and deterministic checks (server-evals doc direct-fetched today). The built-in deterministic evaluators contains, exact_match, regex, levenshtein_distance and json_distance need no LLM and no API key (fetched the same day). The full list of judge-side vendor adapters supported was official docs do not itemize every sub-detail — recorded as unknown.

Where it runs

Running the service on your own machine is the main route: pip install arize-phoenix or Docker (repo README and PyPI fetched today; requires-python ≥3.11), with a web UI served locally; the repository also ships helm and kustomize directories for your own clusters. The vendor-hosted line is Arize AX, not Phoenix itself (README fetched today).

Local files

Self-hosted, traces and evaluation data stay in your environment and arrive over OpenTelemetry; the platform does not read your local codebase or workspace files. The self-hosting docs area contains deployment-options and configuration subfolders (directory structure fetched today), but their bodies were not fetched, so external database and object-storage configuration is recorded as unknown.

Tasks after shutdown

Server-side evaluators can be attached to datasets and run automatically with experiments, with no local code (server-evals doc fetched today); batch comparison runs on datasets through experiments. Resume-after-shutdown is not a feature surface for this kind of platform. Scheduling, sampling and retry semantics are not on record item by item — unknown.

OpenTelemetry tracing plus Python/JS SDKs (Releases fetched today include @arizeai/phoenix-cli); the in-repo docs areas cover tracing, prompt-engineering, datasets-and-experiments and evaluation (structure fetched today). Context & memory

What is observed is traces and spans; what is evaluated is datasets against experiments (the datasets-and-experiments area holds concepts, how-to and quickstart files, structure fetched today). Dataset versioning, splits and experiment-comparison semantics were not read — recorded as unknown.

Permissions & limits

The license boundary matters most: ELv2 forbids providing the software to third parties as a hosted or managed service, and enterprise functionality is gated by a license key (LICENSE fetched today). Self-hosting has no account system. The official docs site and product page returned 403 to this site's fetch channel today, so commercial terms, data usage and training opt-out were not read — recorded as unknown.

Best for

Fits teams already standardizing on OpenTelemetry who want batch comparisons in a notebook or on their own cluster: traces come in first, become datasets, evaluators run with the experiment, and each score links back to its source call. Not a fit for those who only want a hosted console, or who intend to resell Phoenix wrapped as a service (ELv2 forbids that explicitly), or who need a ready-made red-team or compliance-audit surface. This site does not measure scores and does not rank.

Licence and terms of use

Elastic License 2.0 (ELv2, per the repository LICENSE direct-fetched today). Three clauses are explicit: you may not provide the software to third parties as a hosted or managed service, may not circumvent the license-key functionality, and may not remove licensing or copyright notices. The README calls it open source, but ELv2 is not an OSI-approved license.
