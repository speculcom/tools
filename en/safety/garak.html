garak is an LLM probe scanner that runs in your own terminal (NVIDIA and maintainer Leon Derczynski, Apache-2.0): it writes conversations with a model as probes, failure criteria as detectors, runs them through a harness, and logs each failing prompt and response locally. The repo calls itself a generative AI red-teaming and assessment kit; the site calls it an LLM vulnerability scanner. Both are evaluation semantics, not runtime blocking.

When to use it, when not to

Fit: running a batch of probes against a controlled endpoint before release (HuggingFace, OpenAI, Bedrock, replicate, litellm or any REST interface); needing reviewable evidence files (JSONL, hit logs) rather than a pass/fail slogan; reusing one probe set across targets. Not fit: blocking user input in the request path, treating all probes passed as proof of model safety, or teams needing a hosted report platform or compliance certificate.

Model & openness

It ships no model of its own — the thing under test is somebody else's model or application: the repository front page defines generators as "plugins for LLMs to be probed", and names hugging face hub generative models, replicate text models, openai api chat & continuation models, aws bedrock foundation models and litellm, adding "pretty much anything accessible via REST". The documentation's first-scan example is --model_type huggingface --model_name gpt2. The full generator list and per-provider parameter differences: not itemised.

Where it runs

A local Python process with a terminal interface: the README install command is python -m pip install -U garak, PyPI records pip install garak with requires-python >=3.11, and the "Setting up" doc page likewise describes a command-line tool. Scan requests go to the target endpoint you pick — a cloud API or local inference. Whether a hosted execution surface exists, and the official Docker story: no official text captured in this pass, recorded as unknown.

Local files

It reads the probe datasets installed with the package and your local configuration, and writes local result files: the README records JSONL, garak.log and hit logs; the "Our Features" doc page lists four output kinds — Screen output, Report log, Hit log, Debug log. Default directory names, retention and cleanup rules: not itemized in official docs word for word in this pass.

Tasks after shutdown

There is no "keeps running after you shut down" hosted task: one scan is one local process that writes logs when it ends. The docs table of contents lists Setting up, Your first scan and Getting help, with no resume or queue semantics. How batch runs parallelise and throttle: no official text captured in this pass.

Tools & extensions

Four plugin surfaces (README's own phrasing): probes are "classes for generating interactions with LLMs", detectors are "classes for detecting an LLM is exhibiting a given failure mode", harnesses are "classes for structuring testing", and generators connect to models. Selection syntax appears in the docs example --probes lmrc.Profanity, and --list_probes enumerates probes. MCP support: not described in the official docs, recorded as unknown.

Context & memory

Here "context" means how a harness assembles multiple turns into one probe, not cross-session memory. Best for

Fits: running a probe sweep against an endpoint you control before launch, keeping reviewable prompt/response evidence files rather than a slogan, reusing one probe set across HuggingFace, OpenAI, Bedrock, litellm and other targets. Not a fit: intercepting user requests at runtime (it does not block); reading "all probes PASS" as proof the model is safe (the official framing only records failing samples); teams needing a hosted report platform or compliance certificates.

能力边界

按官方在册口径能确认的边界有三条：

  • 它是评测工具，交付物是「失败样本 + 日志」，不是拦截动作。README 的判定表述是「the response will be marked as FAIL」。
  • 它能接什么模型，等于 generators 插件面覆盖了什么。官方点名的接入见 model_access 维。其余接入方式要查 reference 文档。
  • 探针名单（README 出现的 lmrc、promptinject、encoding、snowball、xss、gcg 等）说明的是测试语义的种类， 与「挡住多少攻击比例」没有关系。 本档不做这类换算，也不做产品排名。

第一次怎么用

  1. 先确认被测端点属于哪一类 generator。官方首扫示例是 --model_type huggingface --model_name gpt2。
  2. python -m pip install -U garak，然后用 python -m garak --list_probes 看探针名，不要凭印象写 --probes。
  3. 点选具体探针跑第一次扫描（文档示例形式：--probes lmrc.Profanity）。把输出文件路径记下来——默认目录未在官方文档逐字说明。
  4. 复核只看失败样本与命中日志。这一步是它的价值所在，也是「评测」与「防护」的分界。
  5. 要进 CI 就先解决 target 的凭据与限流。这两项官方文档在本批次没有给出可直接引用的口径。
