It is a guardrail library that runs locally, not a hosted safety service. NVIDIA describes it as an open-source Python library for adding programmable guardrails to LLM applications; rail types, judging models and data flow are all decided by your config.yml.

When to use it, when not to

Fit: teams adding guardrails inside their own process or container, with topic control, jailbreak detection, PII and tool-call control written as rails. Not fit: wanting a hosted console and review workflow, or treating guardrail quality as a vendor promise; the judging model is the one you choose, so changing the model changes the verdict.

Model & openness

It guards the model your app already calls; it does not supply one. The official Supported LLMs page records NVIDIA NIM, OpenAI, Azure, Anthropic, Hugging Face, Ollama and LangChain, served either on the same machine or at a remote endpoint. Rail decisions can use the application LLM for self-checking, dedicated NemoGuard / Nemotron safety models, or third parties (the catalog records LlamaGuard, ActiveFence, Cisco AI Defense).

Where it runs

An open-source Python library; the About page records two delivery forms: the PyPI package and a container image. It runs inside your own process or container. The installation page records pip install, Python 3.10-3.13, starting the server with uv, and Docker. Rail logic executes locally; model calls go wherever you configure them.

Local files

The config folder (config.yml plus flows and actions) lives on your own filesystem and is read directly by the CLI and the server. No official statement was found about reading your project's business files; evaluation uses public datasets (chit-chat, MSMARCO, on the evaluate page). The wider local file surface was not verified item by item and is recorded as unknown.

Tasks after shutdown

There is no hosted 'keeps running after shutdown' task surface: it comes up with your application. The CLI page records chat / server / convert / find_providers, and the evaluate page records offline batch evaluation. Queues and resumption are not part of the product framing.

Tools & extensions

Five rail types are on record: input / dialog / retrieval / execution / output, where execution rails govern tool calls and custom actions let you plug in your own checks. LangChain and LangGraph integrate through passthrough mode. The top-level config.yml keys (models / instructions / rails / prompts / knowledge_base / tracing) contain no MCP server entry, so MCP access is recorded as unknown.

Context & memory

Conversation messages are passed in by the caller and rails judge user / assistant messages one by one; retrieval rails can read the knowledge_base. No official statement was verified on cross-session memory or rail-state persistence, recorded as unknown; effective context length is set by whichever model you choose.

Permissions & limits

Data flow depends on the endpoint you select: local or self-hosted endpoints keep content inside your environment, while the catalog page records that third-party guardrail services send submitted content to that party. Apache-2.0 is on the PyPI and repository pages the same day. Logging and tracing have dedicated pages. Compliance certifications and training-use commitments were not verified and are recorded as unknown.

Best for

Fits: teams adding programmable rails inside their own process or container - topic control, PII, jailbreak detection, tool-call governance - while keeping the freedom to swap models and endpoints. Not a fit: anyone wanting a hosted console with review workflows, or treating rail quality as a vendor guarantee, since the judgement inherits whichever model runs it.

Capability boundaries

The catalog families on record are content safety, jailbreak protection, topic control, PII detection, agentic security and tool calling, hallucination and self-checks, plus third-party rail APIs. What it blocks are messages and actions; human-review outsourcing and cross-vendor model scoring are absent from the official framing (this site's view, judged from the scope of the pages on record). The evaluation surface ships in the open-source package and runs dialog, fact-checking, moderation and hallucination metrics over public datasets - that measures your own rail configuration, not a cross-vendor leaderboard.
