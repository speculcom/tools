GitGuardian is a continuous monitoring platform for the credential layer: the site calls it a Credential Layer Security Platform, with a SaaS platform, ggshield and ggscout covering code repos, CI/CD, container registries, Slack/Jira/Confluence and AI coding assistants. In this category it answers a different question from redaction and red-teaming: not whether the model can fail, but whether you know about secrets that have already leaked.

When to use it, when not to

Fit: organisations with credentials and non-human identities at scale (many repos, CI, containers, collaboration tools and AI assistants) that need continuous monitoring and incident closure rather than a one-off scan; pre-commit/pre-push and IDE-side blocking; self-hosting or air-gapped forms when network boundaries demand it. Not fit: the requirement that personal-data operators run on your own machine before data reaches a model (that is Presidio's constraint); one-off red-team evidence; or replacing model evaluation with a secret scanner.

Model & openness

It neither guards a model nor offers model tiers: its main axis is credentials (secrets) and identity. Its relation to models under test has only two surfaces on record — the docs navigation lists a "GitGuardian MCP Server", whose page describes bringing secret security into your AI coding assistant, and ggshield, which covers the IDE and pre-commit/pre-push places "wherever code is written". Swappable detection models: not applicable, since it does pattern matching plus validity checks rather than model evaluation.

Where it runs

The browser platform is the main interaction surface (the docs navigation covers Platform / Secrets Detection / Internal Monitoring / Public Monitoring / NHI Governance / Endpoint Protection / Honeytoken, and the login entry points at dashboard.gitguardian.com), with scanning and orchestration on the SaaS side. Two local surfaces also exist: ggshield — "Scans run locally" per the docs — and Self-Hosting, worded "set up and run the GitGuardian platform on your infrastructure", which explicitly lists air-gapped environments and two Kubernetes install shapes.

Local files

ggshield scans repositories, directories and diffs on your machine, with documented output formats (json / gitlab / sarif) and commands secret scan, diagnose and ignore-display; the platform side connects your repositories, CI/CD, container registries and collaboration tools (internal monitoring docs: "code repositories to container registries and collaboration tools"). How long scanned code content is retained vendor-side: not addressed clause by clause in the public terms, moved to unknowns.

Tasks after shutdown

Background work is one of its strengths, but ownership differs: the platform monitors continuously (public GitHub monitoring plus the incident lifecycle), while the local side is the instant pre-commit/pre-push interception. SaaS change cadence can be re-read day by day in the docs' SaaS Releases (latest on record the same day: the 2026-10-29 team-sync entry).

Tools & extensions

The integration surface is systematic in the docs navigation: GitHub / GitLab / Bitbucket / Azure, CI (Azure Pipelines, Jenkins), Jira / Slack / Confluence, container registries (including a Harbor entry), Endpoint Protection, Honeytoken (decoy credentials), ggscout and the GitGuardian API. The MCP surface is on record officially: the MCP Server page states "Bring secrets security directly into your AI coding assistant" and lists three security constraints — "read-only permissions, server-side scanning, and secret redaction".

Context & memory

Its "memory" is an asset and incident ledger, not conversation context: NHI Governance (non-human identity), the incident lifecycle and the monitored perimeter persist inside the platform. Cross-session memory and context windows are not applicable — it generates nothing. Detector history and versions have a separate Detection Engine Releases page (on record in the navigation, not read item by item in this pass).

Permissions & limits

Clause by clause with sources: the readable entry for account and data terms is the privacy policy on the site, where the retention sentence reads "Data collected when you request information or when you contact us is kept for two (2) years from our last contact.", and the transfer sentence reads "We may share your Personal Data with our US office, which is located outside of the EEA, in the US."; whether customer code or matched content is used for training is not mentioned, and the policy does not state the storage scope of customer code — both go to unknowns. Detection semantics are on record in the engine FAQ: three stages "Pre-Validation", "Matching", "Post-Validation", plus "GitGuardian will check the validity of the detected credentials". Red line: the vendor's "600+ types of hardcoded secrets" is a count of secret types; this site never converts it into a blocking or coverage rate and never ranks it against PII tooling — the "Secrets never leave your perimeter" phrasing is only read in the self-hosted/perimeter context.

Best for

Fits: credentials and non-human identities already at scale (many repositories plus CI plus containers plus collaboration tools plus AI coding assistants), where the need is continuous monitoring with an incident loop rather than one scan; needing instant interception at pre-commit/pre-push and in the IDE; and when the network-boundary requirement is high, self-hosting or even air-gapped is available. Not a fit: when the constraint is "PII operators must run on my own machine before data reaches a model" (that is the Presidio constraint); when you only want a one-off red-team scan for evidence; or when a secret scanner is expected to replace model evaluation.

Licence and terms of use

Commercial SaaS, not open source: neither the site nor the docs expose a licence field or a self-deployable open core, and no such claim was captured in this pass (/trust and /security both returned 404 that day). The only compliance clue is the framework list on record at the site — "PCI DSS, CIS, NIS2, SOC 2, DORA, ISO 27001, SOX, GDPR" — which is positioning language, not a certificate verified by this site; the actual certificates, DPA and subprocessor list are not disclosed on public pages and go to unknowns.
