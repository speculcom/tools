Nightfall is the hosted DLP layer for the AI era: the homepage calls it a Security Platform for Agents, MCP and Data Movement, putting three things on one layer — text and file scanning before a model (DLP API), Inference Hooks for IDEs and agents, and a Gateway between AI clients and remote MCP servers. The line against self-deployed tools is not a ranking: can the data leave your boundary is the dividing line. If it can, this offers a policy-driven, event-driven, audited hosted surface; if it cannot, look for operators and recognisers that stay on your machine.

When to use it, when not to

Fit: SaaS, endpoint and agent surfaces already in use that need unified control; action at the MCP and IDE-hook layer, including Block server and Disable tool; handling PII and credentials through a hosted API before they reach a model; an event and audit surface rather than building one. Not fit: a hard rule that text must not leave the boundary, or requirements for a public licence and self-hosted audit; teams needing only credential-leak monitoring and incident workflow.

Model & openness

No model picking is offered: the detection engine is the vendor's own, the official pages disclose no model tiers and give no bring-your-own-model entry point. What it guards is your agent and LLM chain — the DLP API takes text and files, the MCP Gateway sits between "your AI clients and remote MCP servers", and the Inference Hooks documentation pages name Cursor, Claude Code and VS Code Copilot. Whether the detection model can be replaced or chosen: no official statement captured, recorded as unknown.

Where it runs

Hosted delivery: scanning goes through the /v3/scan and /v3/upload endpoints on the API side, with results reviewed in the console and on the Violations page (on record in the release notes). There is a local agent on the endpoint side — the macOS/Windows endpoint agent appears in the docs and release notes (AirDrop and Bluetooth exfiltration control, MDM-granted permissions) — but detection and verdicts remain a service-side capability per the official framing. A self-hosted or air-gapped form: absent from the pages captured, recorded as unknown.

Local files

What you can hand it (official FAQ on record): "plain text, structured and unstructured files, and even images", with JSON, XML and CSV named; on the endpoint side the agent reads files on your machine in order to block at the moment of read. Whether submitted content is retained, and for how long: not declared in the DLP API docs or FAQ, moved to unknowns. File and image capability limits live on the supported-file-types page (not read item by item in this pass).

Tasks after shutdown

The asynchronous surface is explicit: file scanning is a multi-step flow — /v3/upload (POST to start), /v3/upload/{fileId} (PATCH chunks), /finish, then /scan — with webhook and asynchronous-notification pages on record, and events aggregated in the console. This layer runs vendor-side, so the "keeps running after shutdown" local-task semantic does not apply.

Tools & extensions

API surface (on record in the DLP docs): request fields payload, policyUUIDs, detectionRules, redactionConfig and alertConfig; response fields findings, redactedPayload and message. Extension surface: an official Nightfall MCP server documentation page (letting AI assistants query your security data directly), Inference Hooks into IDEs and agents, and Premier-tier OpenTelemetry audit trail plus MCP server discovery (on the pricing page). MCP transport details and tool-approval semantics: official docs do not itemize every sub-detail in this pass.

Context & memory

Its "context" is policy and rule set, not conversation memory: one scan is defined by which rules run, via policyUUIDs and detectionRules. The revisable history has a stated boundary — MCP Gateway audit records carry user, server, tool, status and request payload, with payloads "capped at 8 KiB"; how anything beyond that is handled is not stated officially, recorded as unknown.

Permissions & limits

Clause by clause with sources: SOC 2 Type 2 is on record at the security page; transfer path, retention period and training use of customer content have no itemised answer on any official page captured in this pass (neither the developer-api docs nor the FAQ declares it, and /trust returned 404), so all three go to unknowns with no inference such as "not used for training". Tier and quota facts (pricing page, no prices): Foundation Edition covers "Data Detection & Response across 12 API-integrated SaaS apps", the endpoint agent "covers every SaaS app, desktop app, and AI app", each user licence includes "2 endpoint devices", and every plan includes "150 GB of data-at-rest scanning"; Premier adds the AI agent stack, MCP server discovery and the OpenTelemetry audit trail. Red line: what is on record are detection categories and actions (block, mask/redact, removeFinding, cryptoConfig); this site publishes no detection or miss rate and does not rank Nightfall against self-deployed options — the selection question is whether your data may leave your boundary.

Best for

Fits: SaaS, endpoint and agent surfaces already in use and needing one control plane; needing real actions at the MCP and IDE-hook layer; happy to use a hosted API to strip PII and credentials before data reaches a model; wanting an events and audit surface rather than building one. Not a fit: a hard "text never leaves my boundary" constraint, or a requirement for an auditable open-source licence (that constraint points at self-deployed tooling); teams that only need leaked-credential detection with an incident workflow.

Licence and terms of use

Commercial SaaS, not open source: neither the site nor the help centre exposes a repository or licence field, and no self-hosted artefact was captured in this pass (the /trust and /changelog entries both returned 404 that day). The one compliance statement that can be confirmed is on record at the security page: "Nightfall is SOC 2 Type 2 certified"; ISO 27001, GDPR/DPA and the subprocessor list are not named on the pages captured — "not disclosed", not "absent".
