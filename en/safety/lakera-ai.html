Lakera is the vendor-hosted layer of AI security: its site calls itself an AI-Native Security Platform, with Workforce AI Security, AI Agent Security and AI Red Teaming lines; engineering-facing pieces are the platform.lakera.ai console and the api.lakera.ai Bearer API. The split from the other red-team entries is plain: garak and PyRIT are run-it-yourself and keep evidence, while Lakera sees each request and returns a flagged verdict, leaving block or log to you. Another fact on file: ownership and terms now point to Check Point, with privacy and security pages 301-redirecting there.

When to use it, when not to

Fit: real-time control of prompt injection, jailbreak, PII leakage and prohibited content in the request path, with detection on the vendor side; per-project switching between block the interaction and logging for investigation; stacks already using Amazon Bedrock, Google Cloud, Microsoft Copilot Studio, Salesforce Agentforce, n8n, Relevance AI or an MCP server. Not fit: offline or private deployment (no official statement captured), replacing or choosing the underlying detection model, one-off reproducible scan evidence, or self-serve red-team assessment; Red requires contacting the team.

Model & openness

What it guards and evaluates is not one vendor's model but your application chain: the docs list Amazon Bedrock, Google Cloud, Microsoft Copilot Studio, Salesforce Agentforce, n8n, Relevance AI and MCP servers as integration surfaces. The Guard API takes text (a POST with messages and project_id), not weights; whether the underlying detection model can be swapped or a tier chosen: not disclosed officially — the API Reference only exposes git_revision and model_version inside the response's developer info.

Where it runs

Delivered from the cloud: sign-up and configuration at platform.lakera.ai, detection through the hosted API at api.lakera.ai, authentication of the form "Authorization: Bearer $LAKERA_GUARD_API_KEY", and the official quickstart call is POST https://api.lakera.ai/v2/guard. The site self-describes as "The AI-Native Security Platform", with product lines Workforce AI Security, AI Agent Security and AI Red Teaming. A local or private-deployment form: no official statement captured in this pass, recorded as unknown.

Local files

Nothing lands locally: prompts and responses are sent and returned by your application, and decisions can be reviewed in the console's Guard results surface (the docs list the /guard and /guard/results endpoints). Export format, retention duration and deletion path for hit records: not given item by item on the pages on record, moved to unknowns.

Tasks after shutdown

Two kinds of asynchronous behaviour must be read separately: Guard is a synchronous API call that the official framing describes as real-time screening; Red is a hosted assessment project, documented as four steps (enumeration, attack development, impact testing, reporting) delivering "detailed findings with remediation guidance". Project duration, concurrency limits and result notification: not stated officially.

Tools & extensions

Two API endpoints on record (/guard and /guard/results), with a boolean flagged verdict in the response. The integration surface is the list in the model_access axis, where "MCP servers" appears among the protected objects — meaning it both acts as MCP-side protection and treats MCP servers as objects under inspection. Concrete transports and tool-approval semantics: official docs do not itemize every sub-detail in this pass.

Context & memory

Verdicts are organised per text request, and policies are tiered per project (Project mode decides between "block the interaction or logging for investigation"), so its "memory" surface is project and policy configuration, not cross-session context. Cross-session memory or history stitching: not stated officially, recorded as unknown.

Permissions & limits

Read clause by clause from the official terms: the privacy entry 301s to checkpoint.com/privacy, where the entity is written as "Check Point Software Technologies Ltd."; the retention sentence reads "We will retain your information for as long as necessary to achieve the purposes described in this Privacy Policy."; the transfer sentence reads "We may collect and transfer Personal Data on a global basis", with transfers outside the EEA/UK handled via adequacy or one of the other listed mechanisms; the usage sentence includes "We may use telemetry, threat indicators … including capabilities powered by artificial intelligence (AI)". ⚠ Those sentences speak about personal data and telemetry, and do not separately address retention or training use of customer prompt content — that item goes to unknowns, with no inference. Commercial tiers: the pricing entry redirects to platform.lakera.ai/pricing, which did not render tier text when fetched; this site does not collect prices.

Best for

Fits: needing live control of prompt injection / jailbreak / PII leakage / violating content inside the request path, accepting that detection runs vendor-side; needing policies that switch per project between blocking and logging only; already running Bedrock, Copilot Studio, Agentforce, n8n or MCP servers. Not a fit: mandatory offline or private deployment (no such statement captured); wanting to swap or choose the underlying detection model; wanting only a reproducible self-run scan for engineering evidence (that is the garak and PyRIT direction); and Red assessments are not self-serve.

Licence and terms of use

Commercial SaaS, not open source: neither the site nor the docs expose a repository or licence field, and no self-hosted artefact was captured in this pass. The readable terms entry is a redirect measured the same day — lakera.ai/privacy-policy 301s to checkpoint.com/privacy, and the site footer credits Check Point; compliance certificates (SOC 2 / ISO 27001 and the like) are not named on the pages captured, which is "not disclosed", not "absent".
