promptfoo is an evaluation and red-team tool in the terminal. Officially an open-source CLI and library for evaluating and red-teaming LLM apps; artefacts stay local and you bring your own model keys.

When to use it, when not to

Fit: teams managing evals as code assets: one YAML defines many prompts, models and cases, one command produces a comparison matrix, and builds fail in CI below threshold. Not fit: needing a hosted console for long-term dashboards, or vendor-run compliance audits. It also has a red-team surface, but this entry records supported attack plugins and vulnerability classes, not scores or pass rates.

Model & openness

The evaluator ships no vendor model; judge calls run against the account you configure.

Where it runs

Terminal-first: npx promptfoo init to start, eval to run, view to serve a local results page (all on record the same day), with configuration in promptfooconfig.yaml and local runs stated as requiring no login. A hosted viewer at promptfoo.app also appears on that page, which states shared links are private to your organisation; hosted-side details are not itemized in official docs.

Local files

Reads and writes stay on your machine: configuration, test cases and result artefacts live in local directories and the viewer renders local files (on record); test data may come from CSV or JSON, or from custom functions. The platform does not pick up implicit context beyond what you point it at.

Tasks after shutdown

Evaluation runs as a local batch process; caching, concurrency and hot reload are on record, as is failing the build when quality thresholds are not met in CI. Resuming after shutdown does not apply. Distributed execution and checkpointed restarts are not on record and are treated as unknown.

Tools & extensions

Its extension surface, as the called side, is provider configuration, assertion types and custom functions; the documentation index was on record the same day including CI and code-scanning (GitHub Action) integration pages, and results can be posted to PR comments. Whether promptfoo itself provides an MCP server is not stated in what was captured, so it is recorded as unknown.

Context & memory

Evaluation context is entirely defined by the configuration file: a matrix across prompts x models x test cases (matrix views on record); expectations can come from a CSV __expected column or custom functions. Cross-session memory is not part of what this class of tool does.

Permissions & limits

MIT licensed (metadata on record). Local execution plus your own keys means model spend and egress sit in your account (BYOK on record); the official CI page recommends storing keys as encrypted secrets. Retention and training terms for the promptfoo.app hosted side were not captured, so they remain unknown.

Best for

Fits teams that want evaluation in the repository, one command to compare many prompts against many models, and a CI threshold that blocks merges. Does not fit anyone needing a hosted console as a long-term metrics dashboard, or vendor-run compliance auditing. This site records the assertion types and red-teaming surface only, never scores produced by the tool, and draws no ranking.
