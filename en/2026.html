Tools · 2026 additions · 2026-11-24

Agent tool wiring changed eight times in 2026

Claude Ship gives PR review, fixes and approval to agents; Replit Missions orchestrates an agent swarm under a goal and budget; MCP Apps lets tools return a UI; Agent Skills packages capabilities as folders; AG-UI adds the agent-to-user event stream; the next MCP removes sessions from the core; AP2 and ERC-8004 add payment authorisation and identity. None is a new model, but each changes tool selection.

Only nodes with an official spec or announcement; a protocol version does not mean adoption. “Candidate”, “final” and “beta” are labelled separately.

2026-11-23Agent / code delivery

Claude Ship: agents review, fix and approve PRs

Anthropic splits code delivery into three agents: Code Review is GA and reads changes in context with adversarial verification; PR Steward handles failing CI, merge conflicts and review feedback, documenting each push and how to roll it back; Claude Approvals reads a policy file in the repo, approves routine changes under team rules and escalates risky ones. Team / Enterprise + GitHub, beta.

Beta；批准权可 opt-in，默认不放开
Why it matters

It is not another “AI writes code” tool but an attempt to hand the review-fix-approve delivery chain to agents, bounded by a policy file. For teams stuck in PR queues, it is 2026’s most direct product attempt to automate review too — and it puts the governance question “should an AI approve a merge?” on the table.

Boundary / what it does not claim

Beta; Code Review findings still need human judgement, PR Steward changes code, and Claude Approvals only approves routine changes when policy allows. The official outcome figures (merged PRs more than doubled, reverted share down 40%+) are Anthropic’s own team numbers without third-party replication. It does not claim unattended merging, or that a policy file equals compliance.

Sources：TechCrunch report (2026-11-23) · Unite.AI report · Anthropic Newsroom

2026-11-19Agent / cloud delivery

Replit Missions: give an agent swarm a goal

You define the outcome, budget and boundaries; Missions coordinates a swarm of agents to plan, build, test and iterate. An official example had a swarm build the DataCat monitoring platform in two days under a $3,000 budget; on E-Commerce Bench it turned ¥100,000 into ¥4.82M, about 48× the starting capital.

Why it matters

It turns “multi-agent” from a framework concept into a purchasable product: instead of writing an orchestrator, you bound a swarm with a goal and budget. For small teams that need a complete application but lack engineering bandwidth, it is one of 2026’s most testable cloud delivery forms; DataCat and E-Commerce Bench provide checkable cost/output samples.

Boundary / what it does not claim

The official examples are vendor accounts, not third-party replication; $3,000 and two days are task-specific, not general pricing. Swarms still make mistakes, and budgets/boundaries are yours to set; E-Commerce Bench is simulated, so 48× does not generalise to real business. It does not claim to replace engineering teams or to finish any goal automatically.

Sources：Replit official blog · Replit product page

2026-11Protocol / frontend

AG-UI 1.0: an event stream from agent to user

One ordered event stream carrying tokens, tool calls, shared state and interrupts to the frontend; HTTP + SSE, with RunAgentInput and typed events.

spec
AG-UI 1.0
transport
HTTP + SSE
input
RunAgentInput
role
Agent ↔ 用户
Why it matters

MCP handles tools, A2A handles agent-to-agent; AG-UI adds how an agent shows its process to a person. For chat-style agent frontends it is more maintainable than a home-grown WebSocket event protocol.

Boundary / what it does not claim

It is an event protocol, not a model or runtime; SSE is not right for every case (use another transport for low-latency bidirectional); 1.0 does not mean every frontend framework is adapted. It does not claim to replace MCP or A2A.

Sources：AG-UI docs

2026-10-22Standard / skills

Agent Skills: a folder is a capability

Released in December 2025 and donated to the AAIF on 2026-10-22; a reusable capability described by SKILL.md plus scripts/assets, loaded on demand, with 70+ platforms (vendor figure).

form
folder + SKILL.md

progressive disclosure

Why it matters

It packages prompt, scripts and permissions into a portable unit, the key shift from “APIs” to “capabilities”; for internal agent platforms it is more maintainable than another prompt template.

Boundary / what it does not claim

SKILL.md is not a runtime or a security sandbox; script permissions still belong to the host; “70+ platforms” is a vendor count. It does not claim installing a skill makes it safe, or that skills replace tool-permission design.

Sources：Anthropic announcement · Agent Skills docs

2026-07-28Protocol / next MCP

Next MCP: stateless core + extensions

The 2026-07-28 spec candidate removes protocol-level sessions from the core in favour of stateless requests; Extensions and Tasks become optional capabilities, lowering horizontal-scaling and multi-tenant costs.

version
2026-07-28 RC
core
stateless
extensions
Extensions / Tasks
status
候选
Why it matters

A stateless core makes MCP servers look more like ordinary HTTP services that fit load balancers and multi-tenant gateways; for the 32 MCP objects on the tools site, it changes deployment, not just spec detail.

Boundary / what it does not claim

A candidate, not a frozen standard; moving session state to the application means the app must handle sessions and replay; Tasks is still an extension with uneven client support. It does not claim MCP no longer needs state, or that every server should go stateless.

Sources：MCP spec · MCP blog

2026-01-26Protocol / MCP

MCP Apps: a tool can return a UI

SEP-1865 is final: a tool result can carry a ui:// resource, the client renders it in a sandboxed iframe and receives interactions over JSON-RPC; a text fallback is required.

spec
SEP-1865
resource
ui://
render
sandboxed iframe
fallback
text required
Why it matters

It upgrades “a tool returns JSON” to “a tool returns an interactive panel”, the biggest interface change for agent tools in 2026; charts, forms and approvals can happen inside the conversation.

Boundary / what it does not claim

Not every client supports it; iframes bring permission and injection risk; text fallback is mandatory. It does not claim MCP Apps replaces ordinary tool calls, or that every UI can be embedded safely.

Sources：MCP Apps official blog · MCP spec
