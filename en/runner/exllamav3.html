The successor to ExLlamaV2: low-latency local inference on NVIDIA GPUs using the EXL3 quantisation format. It is an engine, not a GGUF tool and not an API server.

When to use it, when not to

Fits NVIDIA single/multi-GPU users chasing EXL3 quantisation and low-latency inference who are willing to set up CUDA. Does not fit AMD/CPU, an out-of-the-box GUI, or the GGUF ecosystem.

Model & openness

Uses EXL3 quantised checkpoints (.exl3) and some HF safetensors; supported models follow the official repository and docs and are not enumerated here. It is the successor line to ExLlamaV2.

Where it runs

CUDA inference engine for local/single-machine multi-GPU use. PyPI records 1.6.6 released 2026-10-31 (version record only rechecked 2026-11-04). CUDA requirements follow the official repository.

Local files

Self-hosted, with weights and .exl3 checkpoints on the local machine; there is no official hosted cloud.

Tasks after shutdown

A local inference process, not a long-running service; serving usually goes through an outer layer such as TabbyAPI.

Tools & extensions

Primarily inference execution; tool calling and MCP are not core and are kept at the official category level.

Context & memory

Long context depends on VRAM and configuration; KV-cache details live in official docs and are kept at the official category level.

Permissions & limits

A local process with no account system; permissions come from the runtime environment.

Best for

Fits NVIDIA single/multi-GPU users chasing EXL3 quantisation and low-latency inference who are willing to set up CUDA. Does not fit AMD/CPU, an out-of-the-box GUI, or the GGUF ecosystem.

Model does not fit · Slow response or output

Top misconception

  • Treating ExLlamaV3 as a replacement for llama.cpp — it uses EXL3/CUDA, not GGUF
  • Assuming installing the package is enough — you still need CUDA and a matching checkpoint
  • Treating TabbyAPI as ExLlama itself — TabbyAPI is the outer API server
