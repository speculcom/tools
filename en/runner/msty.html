8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

A hybrid surface — local models (GGUF download/management, llama.cpp-lineage backend) + cloud-model access (OpenAI/Anthropic and similar API keys); four product lines: Studio (the desktop flagship) / Go (mobile) / Nexus (private enterprise LLM platform) / Stack (cloud-hosted).

Where it runs

A desktop GUI app (Windows/macOS) + the Go mobile app; local inference runs on the built-in llama.cpp-lineage backend. The live site is msty.ai (msty.app 301-redirects to msty.ai; www.msty.app measured 000 direct — three-channel verification 2026-10-31); the vendor entity is CloudStack, LLC (official-site wording).

Local files

Reads and writes local files — local model files, chat history (local storage is its headline privacy positioning).

Tasks after shutdown

The desktop app is persistent; the cloud lines (Stack/Nexus) involve a cloud account. Hybrid architecture: local inference does not depend on the cloud; cloud-model access needs an account/key.

Tools & extensions

In-app RAG/knowledge bases (document Q&A), an MCP access surface (per the official product-line wording); not a tool-plugging surface for agents — it is a consumer/enterprise desktop app.

Context & memory

In-app chat history persists locally; knowledge bases (RAG document libraries) are reused across sessions. Context length varies with the chosen model and configuration (local models are bound by the llama.cpp-lineage backend's parameters).

Permissions & limits

Desktop-app permissions = local files + network; the cloud lines need an account and subscription. Closed-source — no code-audit surface; privacy positioning follows the official site's self-description.

Best for

Fits: wanting "one desktop app for local + cloud" hybrid use; private enterprise LLMs (the Nexus line). Does not fit: open-source auditable stacks (closed-source); CLI-only serving routes (the vLLM/TGI line).
