Ollama is the de-facto entry point for running open models locally: one command installs it, the official model library pulls models in one click, and an OpenAI-compatible API comes up on your machine. Honest notes: the tool is MIT but weight licenses follow each model; the official README explicitly mentions a cloud line.

When to use it, when not to

Fits: getting DeepSeek/Qwen/Llama running with one command, OpenAI-compatible local endpoints, desktop and server alike. Not a fit: high-concurrency serving (vLLM/SGLang), hard data-boundary requirements on the cloud line.

8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

One-click pulls of open-source models from the official model library (ollama.com/search direct-fetched 200); GGUF and safetensors importable (docs.ollama.com/import direct-fetch verified); the library catalog shifts with listings — follow the ollama.com/search list for the day.

Where it runs

A local process (CLI + API server, port 11434 by default). The official Cloud docs cover API keys, usage and plans; the Cloud FAQ states zero data retention (ZDR). GitHub 185,274★ (API verified 2026-10-21).

Local files

Model weights and conversation data land on your machine by default. On Ollama Cloud, prompts and responses are processed transiently under ZDR — not stored, not logged, not used for training; the account keeps basic details and content-free usage metadata (Cloud FAQ).

Tasks after shutdown

The resident API server carries background inference; keep_alive and concurrent-request queueing are described in the official local FAQ (OLLAMA_KEEP_ALIVE, parallel requests and VRAM queueing).

Tools & extensions

The official tool surface is the function-calling / tool-calling API (docs.ollama.com has a Tool calling page); the docs navigation does not list MCP integration, so MCP needs an external bridge and this dossier does not treat external bridges as official capability.

Context & memory

Default context scales by VRAM: <24GiB 4k, 24–48GiB 32k, ≥48GiB 256k; cloud models default to the largest context (official Context length page). Cross-session memory is not part of the official docs narrative.

Permissions & limits

Runs locally with no account needed (the API server listens locally by default); the cloud line signs in with an Ollama account / API key, managed in settings, with the data surface governed by the Cloud FAQ ZDR and account-deletion terms.

Best for

Fits: getting an open-source model running with one command, wanting an OpenAI-compatible local API, desktop and server alike. Does not fit: maximum throughput/service scheduling (that is vLLM/SGLang's job); hard requirements on cloud data boundaries (read the Cloud FAQ ZDR terms first).

Licence and terms of use

MIT (official repo LICENSE, direct-fetched 2026-10-21); model weights carry their own licenses — whatever you download is bound by its own terms.

When something fails

Model does not fit · Slow response or output

Top misconception

  • Reading 'MIT Ollama' as 'models free for commercial use' — weight licenses follow the model, not the tool
  • Seeing only the local line — the official README explicitly states a cloud line; its data boundary needs a separate check
  • Running long documents on default context — context follows the Modelfile/params and varies by model

第一次怎么用

  1. 安装后先跑 ollama --version，确认服务已启动。
  2. 从官方模型库拉一个模型；权重许可跟着模型走，商用前单独查。
  3. 本机默认起 OpenAI 兼容端点，客户端把 base URL 指过来即可。
  4. 显存不够时先降量化档，再考虑 CPU 卸载；不要直接换卡。
  5. 官方 README 另写有云端线；本地与云端是两条计费与数据路径。
ollama pull <model>
ollama run <model>
# OpenAI 兼容端点默认在本机；客户端 base_url 指向它
