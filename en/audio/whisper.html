Whisper is the open-source base of transcription: MIT weights in multiple sizes run locally, privacy-sensitive audio never leaves the machine; it's a model, not a product — meeting-note UX needs a shell, diarization needs derivative tooling.

When to use it, when not to

Fits: privacy-sensitive transcription (audio stays local), offline environments, developer integration (MIT), multilingual. Not a fit: out-of-box meeting-product UX (it's a model), out-of-box diarization, heavy use without a GPU.

8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

An open-source transcription model family (tiny→large-v3 multiple tiers, the official README lists model sizes and language coverage); weights distributed via Hugging Face (linked from the official README). A huge derivative ecosystem: whisper.cpp, faster-whisper, WhisperX etc. (partially mentioned in the official README — the ecosystem's full shape kept at official category level).

Where it runs

Runs locally (Python + PyTorch, the official README's install surface); GPU or CPU both work, tiers trade speed/quality. Hosted line: the whisper transcription endpoint on the OpenAI API (platform.openai.com docs line) is the cloud form of the same model.

Local files

Fully local: audio and transcription results stay on your machine — this is its most fundamental data-boundary difference from every cloud transcription product.

Tasks after shutdown

Batch task-based (file in, text out, runs and exits locally); no background-resident/memory concept.

Tools & extensions

CLI and Python API (official repo); timestamps/translation (into English) built in (official README); VAD/speaker diarization are not in the official repo — they rely on derivatives like WhisperX (derivative surface kept at official category level).

Context & memory

No context concept — segment-by-segment transcription; long audio relies on segmentation strategies (the official repo has long-audio handling notes).

Permissions & limits

Running locally means no account, no upload — privacy-sensitive audio (medical/legal/personal) going local is its irreplaceable scenario; the cloud API form follows OpenAI platform terms (kept at official category level).

Best for

Fits: privacy-sensitive transcription (audio never leaves your machine), offline environments, developer integration (MIT, no licensing burden), multilingual transcription. Does not fit: out-of-the-box meeting-notes product experience (it is a model, not a product), out-of-the-box speaker diarization (needs derivatives), heavy use without a GPU (big tiers are slow on CPU).

Licence and terms of use

MIT (weights and code, official repo LICENSE direct-fetched 2026-10-22) — permissively open, local use requires no account and has no quotas.

When something fails

Account and permissions · Rate limits and retries · File-reading issues

Top misconception

  • Whisper is a model, not a product — 'meeting transcription tool' UX (Otter-type) means building your own shell or using a derivative product
  • Diarization/live streaming are not in the official repo — 'Whisper live captions' products are all derivatives; verify quality and license individually
  • The official repo and the OpenAI API whisper endpoint are one model in two forms — local MIT vs platform terms, completely different data boundaries
