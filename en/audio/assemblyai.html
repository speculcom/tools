AssemblyAI is the 'transcription + understanding' speech API: summarization/entities/Q&A on top of transcripts (the LeMUR line); documentation experience is its developer reputation — offset competition with Deepgram's real-time performance narrative.

When to use it, when not to

Fits: post-transcript understanding pipelines (summarize/extract/Q&A), English-first, docs-experience-first teams. Not a fit: non-developers, privacy-sensitive audio (cloud), Chinese-first work.

8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

A self-developed unified speech-understanding model line (best-seller narrative: one model transcribes + understands, official site); hosted-API form, developers do not pick bare model weights.

Where it runs

API/SDK as the main entry (REST + WebSocket + SDKs, official docs surface); pre-recorded file transcription is the traditional strength, with real-time streaming endpoints alongside (official docs).

Local files

Cloud API — audio uploaded via the API; data-retention policy per the terms (kept at the official category level); the official site carries a "not used for training"-type promise narrative (seen on the site), terms-level details kept at the official category level.

Tasks after shutdown

Batch (file → result polling/webhook) + real-time streaming, two forms; no "keep-running-after-shutdown" concept (API service).

Tools & extensions

Transcription + speaker diarization + summarization + topics/entities/sentiment and other understanding-layer parameters (fully listed in official docs); the LeMUR line (post-transcription LLM Q&A/extraction, official docs narrative) — "transcription + understanding" in one is its differentiating narrative.

Context & memory

APIs have no memory concept; LeMUR Q&A over existing transcripts is "an LLM over transcript artifacts", not product memory.

Permissions & limits

API key + usage billing (D9: pricing not collected); enterprise-compliance narrative (SOC2/HIPAA-type certification lines seen on the site, details kept at the official category level); data-retention/training switches per the terms (kept at the official category level).

Best for

Fits: developers building "transcription + understanding" pipelines (summarization/extraction/Q&A in one step), English-leaning high accuracy, teams that prioritize documented developer experience. Does not fit: non-developers using it directly, privacy-sensitive audio (cloud), Chinese-first usage.

Licence and terms of use

Free credits + usage-based (API-platform posture). Governed by the official terms page (assemblyai.com/terms, direct-fetched 2026-10-22); data retention and training practices not verified line by line.

When something fails

Account and permissions · Rate limits and retries · File-reading issues

Top misconception

  • Like Deepgram it is an API platform, not an end product — the difference: AssemblyAI builds the understanding layer (summary/entities/Q&A) into the API
  • 'Not used for training' promises only count once they land in terms and the DPA — site narrative ≠ terms text (not verified line by line)
  • Quality varies by language/accent — official benchmarks are English-first; test Chinese yourself
