Pipedream is the developer-facing automation platform: code steps (Node/Python/Bash) are first-class citizens, the UI is a flow-building shell; the Connect line makes *your app* a node inside other people's workflows — being integrated is its commercial axis.

When to use it, when not to

A fit for: engineers automating, wanting code-level control plus a hosted runtime and managed OAuth; SaaS teams building an integration surface (Connect). Not a fit for teams that never touch code (go Zapier/Make); full self-hosting (no official statement of such a form).

8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

Workflow steps can connect to each vendor's LLMs (official AI-integration docs line); Connect lets an app or AI agent call any AI API / LLM. The signature trait is code-first automation: steps can be written in Node/Python/Bash. Pipedream is not a model provider.

Where it runs

Pipedream hosts a serverless runtime and workflow service; Connect's API, SDK, MCP Servers and API Proxy also run on the platform. The local CLI is for development and deployment; the official material does not claim a full self-hosted form.

Local files

Execution happens on Pipedream's cloud; locally you develop via CLI/SDK. Connect credentials and tokens are sent over HTTPS and encrypted at rest on the platform. Workflow structures can be exported as JSON with the official export tool; the platform does not run local models.

Tasks after shutdown

The hosted serverless runtime carries schedules, webhooks, event queues and retries while your machine is off. Workflows has been in maintenance mode since 2026 and shuts down on 2027-03-31; Connect is not affected.

Tools & extensions

Connect provides a client SDK, managed auth for 2,500+ APIs, 10k prebuilt tools/triggers, MCP Servers and an API Proxy; the workflow side has code steps and a source-available component registry.

Context & memory

The platform keeps no conversation memory: Connect identifies an end user via external_user_id and fetches that user's token per call. Cross-call conversation history and app state are the caller's responsibility; the platform persistence surface is the connected account and workflow configuration.

Permissions & limits

Connect accepts OAuth/API keys via Pipedream's approved OAuth clients or your own; credentials are sent over HTTPS and encrypted at rest, and Pipedream can provide a SOC 2 Type 2 report and HIPAA BAA. Workflows credentials and OAuth tokens will be permanently deleted by 2027-04-30.

Best for

Fits: developers adding third-party integrations to apps or AI agents (Connect line); automation teams wanting code-level control with a hosted runtime. Does not fit: teams that never touch code; those requiring full self-hosting; or users treating Workflows as a long-term production platform without planning the 2027 migration.

When something fails

Top misconception

  • Filing it under “pure low-code” — it is developer-facing: code steps are first-class, the UI is a flow shell
  • Conflating Connect and Workflows — two product lines (being integrated vs. automating yourself); merged in this file, read them separately in official docs
  • Treating Workflows as a long-term platform — officially shutting down on 2027-03-31, with Workflows data deleted by 2027-04-30
  • Sending OAuth tokens received by the frontend downstream — official guidance requires all third-party calls to run server-side

第一次怎么用

  1. 新项目先选 Connect，不要围绕 Workflows 设计：官方已停止 Workflows 新签购，2027-03-31 关停。
  2. 用 Connect SDK 接授权，把外部用户 ID 映射到 external_user_id；token 只在服务端取用，绝不下发到前端。
  3. 现有 Workflows 立即用官方导出工具把结构下载为 JSON，按项目逐个归档；2027-04-30 前平台会永久删除数据与凭据。
  4. 迁到 Connect 后重做凭据轮换：旧 Workflows 的 OAuth token 会随关停删除，不能当作新链路的凭证。
