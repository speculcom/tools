Model & openness

Nav2 is not a model product; the official README lists no model provider list. Policy or model integration usually goes through user code and ecosystem integrations; this site records it as model/policy-agnostic (site judgement, verification limited to README).

Where it runs

Nav2 is used as a library/framework in local processes, commonly via Python/C++ or the ROS ecosystem; it is not a hosted cloud service. Installation and platform support follow official README/docs and are outside this profile's test scope.

Local files

Nav2 reads and writes local configuration, scenes, models or data assets; file permissions and asset licences must be checked by the user. It does not manage training-data copyright or robot workspace safety for the user.

Tasks after shutdown

Nodes or training processes can run in the background; shutdown continuation, distribution and failure recovery are outside this verification scope and must be checked against official deployment docs.

Tools & extensions

Nav2 provides command-line, plugin or ecosystem interfaces (such as ROS topics/services, simulation plugins, policy-training interfaces). MCP integration is outside the command-line/plugin/ROS interfaces listed in the official README.

Context & memory

Not applicable: Nav2 is not a chat model and has no LLM context window; state is carried by configuration, scenes, node state or training checkpoints.

Permissions & limits

Permissions follow the operating system and runtime environment; with robot hardware, device access, network and emergency-stop boundaries also need checking. The official README covers run entry points only and sets no unified permission model; this profile records no local test.

Best for

Fits: autonomous mobile-robot navigation and behavior orchestration; requires a TF tree and sensor configuration. Does not fit arm manipulation planning or non-ROS systems.

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • Assuming Nav2 provides model intelligence itself — it provides navigation stack infrastructure; policies or models come from user code and ecosystems.
  • Assuming results transfer to real hardware without checks — reality gap, permissions and safety boundaries need separate verification.
