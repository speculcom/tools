Model & openness

It calls no model itself — an official hosted remote server called by MCP clients. One exception wording: the Fin Operator tool family drives Intercom's own AI (Operator) to work — send_operator_message consumes Operator credits (billed the same way as starting a turn inside Intercom), while the other four Operator tools are free.

Where it runs

An official hosted remote server (no self-hosted line): the US endpoint https://mcp.intercom.com/mcp, the EU endpoint https://mcp.eu.intercom.com/mcp (EU requests are processed within the EU, in line with its Regional Data Hosting commitments); AU-hosted workspaces are not yet supported (stated plainly by the official docs). The endpoints measured 401 direct (they exist, auth required — not dead links).

Local files

Reads and writes no local files — the read/write objects all live on the Intercom workspace side (conversations/contacts/companies/Help Center articles).

Tasks after shutdown

No persistent local background; the connection lives between the client and Intercom's hosted endpoint (official wording: the connection stays live to receive updates).

Tools & extensions

The current official-docs count is 14 tools: the universal family search (query DSL: object_type:conversations/contacts, field operators eq/neq/gt/contains, pagination via starting_after) + fetch (full details by prefixed ID); the direct-API family search_conversations / get_conversation / search_contacts / companies / Help Center articles (list/search/get read + create/update write); and the five Fin Operator tools (send_operator_message / get_operator_response / get_proposal_details / apply_proposals / reject_proposals — apply changes your workspace's live configuration).

Context & memory

No server-side cross-session memory; the context is your Intercom workspace data itself (official narrative: AI assistants keep awareness of your workspace). Operator chats have server-side session state (get_operator_response collects the answer later).

Permissions & limits

Two authentication modes: OAuth (recommended; Dynamic Client Registration, but every registered redirect URI passes an allowlist — localhost/127.0.0.1 on any port is already allowed, other callbacks must be requested first) or Bearer token (an Intercom API token, with scopes: read users/companies, read conversations, read+write articles). Bearer connections do not get the Fin Operator tools (stated plainly by the official docs); connections made before the Operator permission existed must reconnect. Tools are authorized as you — mirroring your own workspace permissions, MCP grants no extra rights.

Best for

Fits: support teams plugging Intercom data into AI tools (Claude/Cursor/VS Code and other officially listed clients) — querying conversations and contacts, reading and writing Help Center docs, driving Operator; EU workspaces get a data-residency line. Not a fit: AU-hosted workspaces (unsupported); wanting a self-hosted/open-source implementation (none); wanting Bearer simplicity while also using Operator (you won't get it).

Transport

streamable-http (recommended: US https://mcp.intercom.com/mcp, EU https://mcp.eu.intercom.com/mcp) + legacy SSE (/sse, marked deprecated by the official docs, kept only for backwards compatibility). Verified: the mcp.intercom.com landing page and developers.intercom.com/docs/guides/mcp (200 direct on 2026-10-31; endpoints 401 direct = exist, auth required).

Authentication

OAuth (recommended; DCR + redirect-URI allowlist) or Bearer token (API token + scopes: read users/companies, read conversations, read+write articles). Tool authorization mirrors your own workspace permissions — MCP grants no extra rights.

Permission scope

Read surface (conversations/contacts/companies/articles) + write surface (Help Center article create/update, Operator apply_proposals changing live workspace configuration); no local surface. The write surface is gated by workspace permissions and proposal approval.

Licence and terms of use

Closed-source official hosted service (Intercom ToS); intercom/intercom-mcp-server on GitHub is a documentation-only repo (no license declared, last push 2025-09-22, GitHub API verified 2026-10-31) — the server itself is not open source.

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • Treating the old inventory URL (intercom.com/mcp) as the docs line — measured 404 on 2026-10-31; the current line is developers.intercom.com/docs/guides/mcp plus the endpoint itself
  • Treating the intercom/intercom-mcp-server repo as source — it is a documentation repo (no license, push stopped 2025-09); the server is closed-source hosted
  • Using a Bearer token yet expecting Operator tools — the official docs state Bearer connections exclude the Fin Operator tools; use OAuth
  • Mixing US/EU endpoints — app.intercom.com is US (mcp.intercom.com), app.eu.intercom.com is EU (mcp.eu.intercom.com); AU is unsupported
  • Old connections (built before the Operator permission) erroring when calling Operator tools — reconnect (official troubleshooting wording)
  • Self-built MCP client OAuth callbacks not on the allowlist — registration and authorization fail unless localhost; otherwise request allowlisting first
  • apply_proposals really changes live workspace configuration — Operator proposals are not a preview toy
