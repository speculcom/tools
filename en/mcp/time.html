Model & openness

It calls no model itself; it is an interface implementation called by clients. It uses IANA timezone names and supports automatic system-timezone detection.

Where it runs

A local Python process communicating over stdio.

It depends on the Python MCP SDK 1.x (requires mcp=1.29.0,2); SDK 2.0 renamed the APIs this server uses.

A 2026-08-30 fix addressed security and compatibility issues of container bind mounts under Docker / Podman / SELinux.

Running directly with uvx, no pre-install needed, is recommended.

Local files

No file-access capability whatsoever. No file reads or writes involved.

Tasks after shutdown

Not supported. A single time query is a synchronous operation, ending with the client process.

Tools & extensions

It provides 2 tools: get_current_time (current time in a given timezone) and convert_time (conversion between timezones). Output is structured time data, ready for direct consumption.

Context & memory

Stateless. Each call is independent; no history is kept.

Permissions & limits

No substantive permission risk: no file access, no network access, writes no state. Its entire permission set is "being able to query the current time and convert timezones".

Best for

Gives an Agent reliable time and timezone-conversion capability. Suits scenarios where the model should not guess the time (scheduling, cross-timezone collaboration).

Transport

Supports stdio, and offers container deployment (Docker / Podman).

The 2026-08-30 bind-mount security/compatibility fix (including SELinux) is the same commit (#2205) as for fetch and git.

The official README (full-text verification 2026-10-08) gives only local-process integration (uvx / pip / Docker); there is no official launch method for a remote transport.

Authentication

No separate authentication layer, but this server accesses no external resources; whether auth exists makes no security difference.

Permission scope

No file or network access; reads and writes no external resources. Together with sequential-thinking it is the lowest permission-risk class; safe in sensitive environments.

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • Assuming the model already knows the exact time — it needs this to read the system clock rather than guess
  • Assuming it can schedule tasks — it only reads the time, it does not schedule

It uses IANA timezone names (e.g. America/New_York), not UTC offsets. That is also where it beats "letting the model do timezone math" — IANA names carry daylight-saving rules.
