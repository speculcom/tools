Model & openness

It calls no model itself; it is an interface implementation called by clients. It gives agents version-aware library and API documentation, solving usage errors caused by stale model training data.

Where it runs

A remotely hosted HTTP service (https://mcp.context7.com/mcp), operated by Upstash. This is the only entry in this section that defaults to remote; all other reference servers are local stdio processes.

Local files

No local file access at all. A pure documentation-retrieval service.

Tasks after shutdown

Always available as a remotely hosted service, independent of the client process lifecycle — the only entry in this section unaffected by your machine's switch.

But service availability depends on Upstash's service status; this repository's releases cannot guarantee the server side — the two must be judged separately.

Tools & extensions

It provides MCP tools for retrieving library documentation.

The README stresses correct usage: use Library Ids, specify a version ("Specify a Version"), and declare via a rule that Context7 should always be used when library docs are needed. Output is structured documentation content.

Context & memory

No cross-session memory, but documentation retrieval is itself "external memory" — compensating for stale model training data; that is its core positioning.

Permissions & limits

The permission risk profile is completely different from local servers: it touches no local files, but your query content is sent to Upstash servers.

Passing a Library Id and a question produces a network request. Authentication uses an API key (Authorization: Bearer YOUR_API_KEY). There is no separate approval mechanism.

Best for

Scenarios where you need current-version library docs: API changes after a library upgrade, config options introduced by new versions, third-party library usage the model is unsure about. Not a fit for internal code or private libraries.

Permission scope

No local permission risk, but there is a data-egress risk: query content is sent to Upstash servers. The library names and question text you pass are outbound content; sensitive scenarios need an assessment.

The 2026-10-08 check adds one explicit official privacy commitment (the official FAQ title is "How do you keep the privacy of my queries?"):

Queries send only the documentation question and the library name/ID, not full prompts, source code or conversation history; and the official docs require agents not to include credentials, personal data or proprietary code in queries.

The document-index scope on the server side is Upstash's; it is not visible to clients.

The two easiest misreadings:

① Pro's "Unlimited API Calls" does not mean "unlimited and free" — it means "does not block". The official comparison table writes Pro's Additional API Calls column as "Unlimited (overage billed by usage)" — the first half means no blocking, the second half means overage costs extra.

② Private Repo Parsing is a completely separate billing item. It is a different wallet from the API-call quota; the Pro seat price does not include it. If you want private-library docs ingested, that cost is calculated separately (unit price on the official page).

Third-party figures disagree with the official page (official prevails)

Several third-party sites (around 2026-09) claim Pro is "5,000 calls/seat" — the official page says 2,000. This entry follows the official figure; the third-party number is treated as outdated or speculative.

Draw the open-source boundary clearly

The official README itself states: this repository hosts only the MCP server's source code; the API backend, parsing engine and crawling engine are proprietary. So "MIT" refers to that client-side code, not the whole service.
