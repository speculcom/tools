Model & openness

It calls no model itself — an interface implementation called by MCP clients. It feeds Figma design context (components, variables, layout data, Code Connect mappings) to coding agents so generated code matches the real design system.

Where it runs

Two forms: official hosted remote (mcp.figma.com/mcp — direct fetch 405 = exists but needs auth, officially recommended) + desktop local server (127.0.0.1:3845/mcp, requires the desktop app + a Dev/Full seat). The official docs state "strongly recommend the remote server".

Local files

In the desktop form it can download image assets into the project (Download assets setting, seen in the directly fetched official docs); the remote form returns asset links. Design data lives in Figma's cloud.

Tasks after shutdown

The remote form lives on Figma's side; the desktop form lives and dies with the desktop app. No background-task semantics.

Tools & extensions

Fetch design context and code, read FigJam/Make content, Code Connect mappings, writing to the canvas (create/update components and variables — "write to canvas", Professional plan or above); the complete inventory follows the developer docs.

Context & memory

No server-side cross-session memory — design state lives in the Figma files themselves; Code Connect is a "design↔code" mapping layer, not memory.

Permissions & limits

Plans and seats are hard gates: the remote server is available on all plans but writing to the canvas needs Professional+ and editing non-draft files needs a Full seat; the desktop server needs a Dev/Full seat; only clients in the Figma MCP catalog can connect (VS Code/Cursor/Claude Code etc.). Free during beta, moving to usage-based billing later (seen in the directly fetched official help page).

Best for

Fits: design-system-driven coding flows (the agent generates code from real components/variables), code↔canvas two-way flow. Not a fit: clients outside the MCP catalog (needs the developer waitlist); teams wanting free canvas writes (plan gates).

Transport

Streamable HTTP, two entry points: remote mcp.figma.com/mcp (recommended) + desktop local http://127.0.0.1:3845/mcp. Verified: developers.figma.com docs fetched directly (2026-10-21); endpoint returns 405 (exists, GET not accepted).

Authentication

First connection goes through Figma account login (OAuth semantics); no official docs for a plaintext-token configuration route. The seat type (Dev/Full) determines the capability surface.

Permission scope

Read surface: design context, FigJam/Make, Code Connect; write surface: canvas create/update (plan + seat gates). The client whitelist (catalog) is Figma's side access gate — the biggest difference between it and most MCP servers.

Licence and terms of use

Closed-source official service (Figma ToS + plan gating); no open-source repo — official developer docs direct-fetched 2026-10-21.

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • Reading 'beta free' as free forever — the official docs state it will become usage-based paid
  • Hard-wiring a client outside the catalog — Figma only accepts the MCP catalog list
  • Treating the desktop server as the recommended route — the official strong recommendation is the remote server; the desktop line serves enterprise/government needs
  • The old help.figma.com article URL 404s — the live docs line is developers.figma.com (direct-fetched 2026-10-21)
