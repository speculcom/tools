MCP tools

The permission scope, transport and output usability of MCP servers. Admission criteria: released as an installable MCP server, has an official repository or documentation that can be traced back, and has substantive updates within the last 30 days. This is a capability-gap reference table, not a selection comparison.

Answer one question first: what capability are you actually missing

MCP is not "making AI smarter" — it is giving AI access to what it could not otherwise reach. If all you want is chat and writing code, you do not need it. You install it, the AI calls it — 32 entries by origin: 7 are the MCP org's reference servers, and 25 are maintained by their own vendor or official teams (Playwright, Context7, GitHub, and Neon / Notion / Stripe and others). Each entry states its origin and permission scope in the scope axis.

  1. 1I need to read/write local files / work with Git
    filesystem, gitBoth have read and write permissions; for the git category it is worth checking what directories the scope can be limited to.
  2. 2I need it to remember things across sessions
    memoryThis is the most misunderstood category — it is not "model memory" but an external knowledge-graph store.
  3. 3I need AI to reach the web for material
    context7, fetchfetch carries the highest risk: the entry quotes an official warning — it can reach local and internal IPs, with no address allowlist and no approval mechanism.
  4. 4I need to drive a real browser
    playwrightNote the official explicit statement that source restrictions are not a security boundary; real isolation requires `--isolated` or a containerised network policy.
  5. 5I want time / decomposition / cross-platform file search
    time, sequential-thinking, everythingAll three are read-only, so risk is lowest.
  6. 6I need to work with GitHub (repos / issues / PRs / Actions)
    See github-mcpGitHub's own MCP server — not the same line as the archived reference server; permissions follow the GitHub token and can be tightened to read-only.

⚠ An easily overlooked dimension: data leaving the country. Context7 is delivered as a remote service by default — queries go to Upstash's servers; GitHub MCP Server offers both a remote hosted and a local Docker form; the other eight are local stdio processes. And — installing an MCP server is manual; calling it is not: once running, the server reports its tool list to your client automatically, and after that the agent decides whether and when to call it. You only get involved at the approval step.

What to look at when choosing

Every tool is broken down by the same questions, so you can compare them side by side. Open any entry to see the official wording and link; disagree and check it yourself.

01

Model & openness

Whose model does it use? Can you switch to a third party? How is multi-model routing configured?

02

Where it runs

Local, cloud or hybrid? Is the index local or remote? Remote control is not the same as cloud execution.

03

Local files

How wide an area can it reach? How does it read large files you have not opened? How capable is it at the symbol level?

04

Tasks after shutdown

Does it keep running once the computer is off? This is the most common misconception about local forms.

05

Tools & extensions

How wide is the toolchain: MCP · LSP · plugins · hooks · custom instructions?

06

Context & memory

Indexing algorithm, context window, session resume and fork, and the boundary of cross-session memory.

07

Permissions & limits

Sandbox and approval boundaries, credential handling, whether data leaves your machine, and how quota is charged.

08

Best for

What tasks is it best at? When should you not use it?

09

Transport

How the client connects to it: stdio / SSE / Streamable HTTP / remote.

10

Authentication

How identity is proved. Note that authentication is not authorisation: the former is who you are, the latter is what you may do.

11

Permission scope

How much can it reach? Can it modify? Delete? Be tightened? This is the first priority in the MCP track.

Why there is no overall ranking

This is not an omission but a deliberate methodological choice.

  • No shared measurement, no score. Benchmarks across tools use different rules — different questions, budgets and environments. A 90 and a B 88 are not comparable.
  • "Unknown" is a legitimate answer. If it cannot be found, we write "unknown" and explain why, instead of filling the gap with guesses. Missing information is itself information.
  • Every field carries a source link, so you can go back to the original.
  • A recent check does not mean it stays valid. When upstream archives or changes, the entry is marked active / maintenance / archived.
  • Families are not mixed. Ready-made tools, things you build yourself, and plug-in-and-run components are three different roles with different ways of judging them; forcing them into one master table would manufacture false comparability.

How to read the confidence marks

Both the detail pages and the table above carry confidence, which reflects how complete this site's data is, not a judgement of the product.

verifiedall 11 dimensions have official sources and were updated within 90 days
partialsome dimensions are marked unknown, the official docs were unreachable, or the info is over 90 days old
stalethe vendor has shipped a significant change that this site has not updated yet

Sources and how to re-check them

All data comes from the open-source repository speculcom/ai-handbook (CC BY 4.0).

Every entry is plain Markdown plus frontmatter, carrying dimension records and an evidence chain with links, checked dates and confidence marks. The repository contains:

  • tools/METHODOLOGY.md —— the methodology charter and core rules
  • tools/axes/ —— the definition and decision criteria for each dimension (with positive and negative examples)
  • tools/SCHEMA.md —— the data-format spec and build validation rules
  • tools/protocols/<category>/_protocol.md —— the measurement protocol (not yet run, so this site has no measured conclusions)

Found an error or have new evidence? Open an issue or a PR — each correction notes its basis and blast radius.
