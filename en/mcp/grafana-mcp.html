Grafana's official MCP server (Apache-2.0, Go): plugs agents into your Grafana instance — dashboards, datasources, unified SQL, alerts and IRM. Three hard facts: a service-account token + RBAC scopes are the front gate; some tool groups are disabled by default; full dashboard JSON is a context-window black hole, and the official README ships summary/JSONPath/patch as the escape hatches.

When to use it, when not to

Fits: agents querying dashboards/metrics/alerts on self-hosted or Grafana Cloud instances, editing dashboards, unified SQL across datasources. Not a fit: zero-config no-token scenarios (a service-account token is required); Grafana below 9.0 (some features lack API endpoints).

Model & openness

It calls no model itself — an interface implementation called by MCP clients. It wraps your Grafana instance (dashboards, data sources, alerts, OnCall/IRM etc.) as tools for agents.

Where it runs

A local process (uvx mcp-grafana stdio; the official line also offers Docker, binary, Helm deployment paths); GitHub 3,593★, last push 2026-10-23, latest release v2.1.1 (2026-10-20, API verified). Full functionality requires Grafana 9.0 or newer (official README: older versions lack API endpoints, data-source operations may be unavailable).

Local files

Reads and writes no local files — the scope is the Grafana instance and its connected data sources; unified-SQL credentials are handled by data source configuration, the official README states the server never sees the credentials.

Tasks after shutdown

stdio lives and dies with the client; no background-task semantics.

Tools & extensions

Dashboard family (search/read/summary/JSONPath property extraction/update/create/patch), data source family, unified SQL (ClickHouse/Snowflake/Athena/MySQL/PostgreSQL/MSSQL), the Prometheus/Loki/CloudWatch/Elasticsearch query families, Cloud Logging, the RBAC and user-management families; some tool groups (running panel queries, query examples, Graphite) are disabled by default, enable with --enabled-tools. The complete inventory follows the repo README.

Context & memory

No server-side cross-session memory — state lives in the Grafana instance itself. The official README warns specifically: full dashboard JSON eats the context window, prefer the window-saving tools summary/JSONPath/patch.

Permissions & limits

The permission surface is the core of this entry: Grafana service account token + fine-grained RBAC scopes (the official README lists the minimum action per tool); the README also gives a convenience note — the built-in Editor role is coarser than hand-made scopes, use it only when "convenience matters more than least privilege". The SSE/streamable-http line can set separate caller authentication (--server-auth-token); stdio is unaffected.

Best for

Fits: agents querying dashboards/metrics/alerts, modifying dashboards, and running cross-data-source unified SQL on self-hosted or Grafana Cloud instances. Not a fit: zero-config tokenless scenarios (a service account token is required); Grafana below 9.0 (some features missing).

Transport

stdio (uvx mcp-grafana) is primary; the official line also provides an SSE/streamable-http server mode (with optional caller auth). Verified: repo README (fetched directly 2026-10-23).

Authentication

Server side connects to Grafana with GRAFANA_SERVICE_ACCOUNT_TOKEN; client side optional --server-auth-token Bearer (only effective for SSE/streamable-http). Official README: when caller auth is enabled, validated Authorization headers are stripped before reaching Grafana.

Permission scope

Both read and write: dashboard reads + update/create/patch, alert and IRM lines have write actions; the minimum RBAC action per tool is listed in the README. SQL credentials go through data source configuration, the server never handles them.

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • Treating "open source" as "zero config" — it needs GRAFANA_URL plus a service-account token, and RBAC scopes decide which tools actually work
  • Pulling full dashboard JSON by default — the official README warns it eats the context window; summary/JSONPath/patch are the intended tools
  • Assuming every tool is on — run-panel-query, query examples and Graphite are disabled by default and need --enabled-tools
  • Grabbing the built-in Editor role for convenience — the README notes it is coarser than hand-applied scopes; avoid it under strict least-privilege
