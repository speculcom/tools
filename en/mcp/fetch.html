Model & openness

It calls no model itself; it is an interface implementation called by clients. Its core is converting web-page HTML into Markdown for LLM consumption.

Where it runs

A local Python process communicating over stdio. It depends on the Python MCP SDK 1.x (requires mcp=1.29.0,2); SDK 2.0 renamed the APIs this server uses.

A 2026-08-30 fix addressed security and compatibility issues of container bind mounts under Docker / Podman / SELinux.

Local files

No file read/write tools. The core capability is web fetching; local files are not involved.

Tasks after shutdown

Not supported. A single fetch is a synchronous operation, ending with the client process.

Tools & extensions

It provides the fetch tool to retrieve web content and convert it to Markdown. Output is converted text; its degree of structure depends on the target page itself.

Context & memory

Stateless. Each call is independent; no fetch history is kept.

Permissions & limits

The official docs warn explicitly about the security risk: the README states this server can access local/internal IP addresses and may represent a security risk. Use with caution and make sure no sensitive data is exposed. There is no separate approval mechanism, and the target-address range cannot be restricted.

Best for

Converts public web content to Markdown for an Agent to read. Not a fit for environments with intranet access, nor for pages requiring login state.

Transport

Supports stdio, and offers container deployment (Docker / Podman). The 2026-08-30 fix addressed bind-mount security and compatibility (including SELinux).

The official README (full-text verification 2026-10-08) gives only local-process integration: uvx / pip / Docker; there is no official launch method for a remote transport.

Authentication

No separate authentication layer. In stdio form it inherits the client user's permissions. Authentication configuration for the container form is not stated in the repo.

Permission scope

The highest-risk class: no file scope (files are not involved), but the network range cannot be narrowed — the official warning says it can access local/internal IPs. No address allowlist, no approval mechanism. An assessment is mandatory before using it in production or in environments hosting intranet services.

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • Enabling it directly where the intranet is reachable — the official docs warn it can reach local and internal IPs
  • Assuming it fetches pages behind a login — it is a stateless fetch
  • Assuming the output is clean Markdown — the structure varies with the target page

Test notes

This site has not completed measured runs. The test protocol is at protocols/mcp/_protocol.md.

Suggested measurement: measurement of this server should not be done in environments containing sensitive intranet services. Verify fetch success rate and output quality in an isolated container or test network.

⚠ The official security warning (original wording)

CAUTION This server can access local/internal IP addresses and may represent a security risk. Exercise caution when using this MCP server to ensure this does not expose any sensitive data.

This is the clearest self-flagged risk by the official side in this entire section, and the site considers it the most valuable first-hand information — such warnings are rare; most comparable tools only write "be careful when using".

Why this risk deserves its own section

ScenarioRisk
Intranet has database admin panels (10.x / 192.168.x)The Agent may fetch intranet pages
Cloud metadata services (e.g. 169.254.169.254)Instance metadata and credentials may be obtained

The key point: there is no address allowlist and no approval mechanism. Once enabled, the Agent has a channel for probing the intranet.
