11 questions, one table

11 questions, each comparable item by item with its peers.

Model & openness

It needs an external model to run Stagehand — on the hosted line Browserbase itself covers the LLM costs for Gemini (the official README states the hosted version "provides the LLM costs for Gemini"); the self-hosted line requires your own GEMINI_API_KEY (switch models with --modelName plus the matching key). It is a browser-automation-plus-model hybrid, not a pure interface wrapper.

Where it runs

The current flagship is the official hosted remote server (https://mcp.browserbase.com/mcp, streamable-http); the self-hosted line goes through npm (@browserbasehq/mcp 3.0.0, 2026-03-31) or cloning the GitHub repo. The GitHub repo browserbase/mcp-server-browserbase is archived (API-verified archived=true, 3,397★, last push 2026-07-20) — the README top states plainly it is "no longer maintained, kept for historical purposes, not representative of current production services"; the underlying Stagehand repo remains active (MIT 25,883★, pushed 2026-10-30).

Local files

Reads and writes no local files — the artifacts are page state and extraction results (text/structured data) inside a cloud browser session. The self-hosted line runs on your machine, but the browser itself is still a Browserbase cloud session (BROWSERBASE_API_KEY required).

Tasks after shutdown

The browser session lives on Browserbase's cloud (start creates/reuses a session, end closes it); no local background process. The session lifecycle is managed explicitly by tool calls, not persistent.

Tools & extensions

6 tools (README wording; hosted and self-hosted share the same set): start (create/reuse a session) / end (close the session) / navigate (go to a URL) / act (manipulate the page from a natural-language instruction) / observe (observe actionable elements) / extract (extract page data per instruction). The act/observe/extract trio is driven by Stagehand's act-and-observe paradigm.

Context & memory

No server-side cross-session memory; the context is the current Browserbase browser session (start can reuse an existing one). In-session page state is naturally continuous; nothing persists across sessions.

Permissions & limits

The hosted line needs a Browserbase account (API key + project id, configured in the client); the self-hosted line needs the BROWSERBASE_API_KEY/BROWSERBASE_PROJECT_ID/GEMINI_API_KEY environment variables. act manipulates real web pages (clicks/form filling) — gate the authorization boundary per target site; cloud session content is retained on Browserbase's side, so sensitive flows need your own assessment.

Best for

Fits: agents wanting "cloud browser + natural-language web driving" (no local browser to set up); the hosted line for easy onboarding with the vendor covering LLM costs. Not a fit: wanting an open-source auditable full implementation (the GitHub repo is archived; the current implementation is closed on the hosted side); scenarios that only need local browser automation (Playwright MCP is more direct).

Transport

streamable-http (hosted https://mcp.browserbase.com/mcp, officially recommended) + stdio (npx @browserbasehq/mcp self-hosted); the README states both STDIO and SHTTP transports are supported, recommending SHTTP via the hosted line. Verified: repo README (fetched via GitHub API raw 2026-10-31) + the docs.browserbase.com MCP page (200 direct).

Authentication

Browserbase account credentials (BROWSERBASE_API_KEY + BROWSERBASE_PROJECT_ID); the self-hosted line adds a model key (GEMINI_API_KEY by default). The hosted endpoint measured 400 direct (exists, requires a proper MCP handshake and auth — not a dead link).

Permission scope

Read surface (navigate/observe/extract) + web write surface (act clicks and fills forms); no local file write surface. Cloud browser sessions can carry login state — gate the "touching things on a web page" boundary per the target site's authorization.

Licence and terms of use

Self-hosted repo Apache-2.0 (GitHub API verified 2026-10-31); the hosted line is a closed service (Browserbase ToS).

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • Treating the GitHub repo as the current implementation — the repo is archived (stated plainly at the README top); the official recommendation is the hosted line mcp.browserbase.com/mcp; "repo archived != product discontinued" is this dossier's core two-wording
  • Thinking self-hosting needs no Browserbase account — self-hosting only puts the server process on your machine; the browser session still lives on Browserbase cloud and the API key is still required
  • Thinking it needs no model key at all — the self-hosted line requires your own GEMINI_API_KEY (or a swapped model with its key); only the hosted line has the vendor covering Gemini costs
  • Treating act as a safe action — it clicks and fills forms on real web pages; login-state and write-operation risks are gated per target site
