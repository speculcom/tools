Model & openness

It calls no model itself — an interface implementation called by MCP clients. It wraps Stripe dashboard capabilities (product/price/customer/payment queries, docs retrieval) as tools for agents.

Where it runs

Mainly a local process (Python/TS packages starting stdio); GitHub stripe/ai 2,000★, last push 2026-10-30 (API verified). Stripe also has an agentic commerce product line (ACP etc.) — that is a separate layer of "agents taking payments directly" and does not count as this server itself.

Local files

Never touches the local file system — the scope is Stripe cloud account data (customers/products/invoices etc.).

Tasks after shutdown

stdio lives and dies with the client; no background-task semantics.

Tools & extensions

Stripe API retrieval, account data queries, docs search, etc.; write capabilities (creating products/prices) exist — the complete inventory follows the repo README, kept at category level.

Context & memory

No server-side cross-session memory — state lives in the Stripe account itself.

Permissions & limits

Credential = Stripe API key, everything follows the key's permissions: the difference between test and live keys is huge. The official tooling supports trimming by key type and tool allowlists; payment write operations (refunds/sending invoices) genuinely exist — before hooking up an agent, defend against the worst case of the key's permissions.

Best for

Fits: letting an agent look up API usage, query account objects, and try test-mode operations while developing Stripe integrations. Not a fit: hard "read-only insurance" boundaries; non-Stripe stacks.

Transport

stdio (Python/TS packages starting a local process) is primary; the official docs also describe a remote line — kept at the official category level. Verified: docs.stripe.com/agentic-commerce 200, stripe/ai repo (direct fetch 2026-10-21).

Authentication

Stripe API key (test/live states); key permissions = the upper bound of tool permissions. Support surface of restricted keys kept at the official category level.

Permission scope

Read surface: account object queries, API reference retrieval; write surface: create products/prices, invoice and refund tools exist. Tool-allowlist trimming can narrow it; no official docs for a tool-level human approval mechanism.

Licence and terms of use

MIT (stripe/ai repo, GitHub API verified 2026-10-21 — Stripe's official AI tooling repo including the MCP tool line).

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • Mixing the Agent Toolkit with the agentic-commerce (ACP payments) line — one is a dev tool, the other a commerce product line
  • Plugging a live key into an agent for write rehearsals — start in test mode; defend write tools (refunds etc.) at the worst case
  • Looking for the old stripe/agent-toolkit repo name — the live official line is the stripe/ai repo (API-verified 2026-10-21)
