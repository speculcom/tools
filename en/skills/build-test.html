How to build and test: start from the smallest runnable version

不要一上来写一个大而全的 Skill。先做一个能跑通的最小版本，再用真实任务测失败分支。

What Structure Build & test Review Tools home

第一步：选一个真实、重复、可验收的任务

任务要有明确输入与输出。比如“把一份 PDF 发票抽成 JSON”“按固定模板生成周报”“对一个 PR 做检查清单”。不要选“帮我分析一下”这种没有验收标准的任务。

先手工做一遍，记录步骤、工具、判断点与返工点；这些就是 SKILL.md 的骨架。

第二步：写最小版本

只写一个主流程，不写分支；只放一个脚本，不放一堆模板。先让 Skill 在 3 个真实样本上跑通，再扩。

最小版本要包含：触发条件、输入、步骤、输出、一个失败提示、一个验收检查。

第三步：测失败分支

至少测：输入缺失、格式不对、文件太大、网络失败、权限不足、输出为空。每个分支都要有可读的报错与下一步建议。

不要只测 happy path。Skill 在生产里出问题，八成是输入不干净或权限不够。

第四步：版本化与回归

每次改 SKILL.md 或脚本，记版本、改了什么、为什么改。保留一组固定样本做回归，改完重跑。

如果 Skill 会修改仓库或发消息，先在 dry-run 模式跑；确认输出后再开写权限。
