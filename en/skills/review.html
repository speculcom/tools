Reviewing a third-party Skill: permissions, scripts and supply chain

A third-party Skill is executable code, not harmless text. Before installing, inspect permissions, scripts, network access, secrets and supply chain.

Source and licence

The source should be a verifiable repository or an official marketplace, with a LICENSE, recent commits and issue history. If the source, licence or maintenance record is missing, do not install it. Stars are not trust: stars can be bought; code does not become safe because of them.

What it touches

Read SKILL.md and the scripts. Look for directory reads/writes, file deletion, shell execution, network access, secret requests and local services. Treat “download and execute”, “curl | bash”, “write the key to a file” and “disable security settings” as high-risk steps.

Dependencies and supply chain

Are package versions locked? Are packages installed from an untrusted source? Is there a postinstall script? Does it export the whole environment? Run the Skill in an isolated directory or container, with the smallest permission set; expand only after checking output.

A small test run

Use redacted samples. Observe which files it reads and writes and which network requests it makes. Do not use production keys or customer data for the first test. Afterward, inspect logs and temporary files for residue or writes to unexpected locations.
