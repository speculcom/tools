8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

Models are orchestrated and routed on the Manus side (no complete model list published officially); users do not pick models directly — "which model does the work" is an internal product decision, one of its key differences from general chat products.

Where it runs

Tasks run in Manus's cloud sandbox (the sandbox surface on the manus.computer domain, as seen via direct fetch): the agent executes code, browses the web and produces files inside a cloud VM; the web UI issues and follows up, nothing is installed locally.

Local files

Artifacts (files/web pages/reports) are generated in the cloud sandbox and can be downloaded/exported; uploaded data is stored on the account side. The exact opposite of a "local agent" — the execution surface is on the vendor's cloud.

Tasks after shutdown

Asynchronous tasks are its native form: after submitting a task you can leave the page and the agent keeps running in the cloud (the official narrative is "hand the task to it"); there are productization traces of grace-period/queueing mechanics (credit system and concurrency limits).

Tools & extensions

Built-in tool surfaces incl. browser, code execution, file operations and deployment (the manus.space publishing surface); connecting external services (email/calendar etc.) goes through official integration lines. MCP support official docs do not itemize every sub-detail.

Context & memory

Work is organized by task/session; the product surface has no cross-task memory entry, and reuse relies on files and project assets, which are the main persistent surface.

Permissions & limits

Account + subscription system; the cloud sandbox has network egress (browsing/downloading is product semantics); data retention and training terms are governed by the official Terms/Privacy, details official docs do not itemize every sub-detail.

Best for

Suits: handing whole tasks (research reports, data tidying, site building & publishing) asynchronously to a cloud agent, with artifacts published directly (manus.space). Does not suit: picking models, local files participating in execution, or heavy free use (credit system).

Licence and terms of use

Subscription + credit model. Governed by the official Terms (manus.im/terms, direct-fetched 2026-10-22); output ownership follows those terms — clause details not verified line by line.

When something fails

Account and permissions · Rate limits and retries · File-reading issues

Top misconception

  • Treating Manus as 'a chatting bot' — the official positioning is a general-task agent (chat is just one entry); execution happens in a cloud sandbox
  • Distinguish it from coding-category cloud agents (Devin/Jules): Manus's main axis is general tasks (reports/sites/data), not codebases
  • The cloud sandbox has a live network egress — think through what data it will carry while browsing before uploading anything sensitive (per official Privacy, not verified line by line)
