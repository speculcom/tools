Open WebUI is a self-hosted chat front end for multiple model providers: connect Ollama or any OpenAI-compatible API, then add knowledge bases, tool calling, multi-user roles and data that stays on your own infrastructure. The licence is BSD-3 with a branding clause from v0.6.6.

When to use it, when not to

A fit for: teams that want one private chat entry point over local and cloud models, with RAG, tool calling, multi-user access control and self-hosted data boundaries. Not a fit for zero-ops SaaS, or procurement that needs a vendor SLA.

8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

No built-in model: connect Ollama and any local or cloud OpenAI-compatible API, plus providers such as Anthropic. Credentials stay in your instance. Provider coverage and version differences follow the official Connect a Provider documentation.

Where it runs

Self-hosted web app: Docker, Python, Kubernetes or a desktop app. The front end is a browser; inference and data stay on your machine or server by default and do not pass through Open WebUI’s cloud.

Local files

Upload documents, images and code; knowledge bases and vector stores live in your instance. Open Terminal gives an agent a controlled shell and filesystem to read, write, run scripts and return artefacts to the conversation.

Tasks after shutdown

Automations can run prompts on a schedule, and long tasks run in the instance background. Whether they continue after shutdown depends on where the instance is deployed; the platform does not host your execution environment.

Tools & extensions

Python Tools and Functions, Skills, OpenAPI and MCP (the official mcpo bridge turns an MCP server into OpenAPI); built-in code execution, web search and image-generation plugin surfaces.

Context & memory

The context window is set by the connected model. The instance provides conversation history, Memory, knowledge-base retrieval and a full-text injection switch; cross-project long-term memory boundaries were kept at the official category level.

Permissions & limits

Multi-user RBAC: roles, groups, per-model and per-resource access, SSO/OIDC/LDAP, SCIM, MFA and API keys. Data and logs stay on your infrastructure; admins can disable telemetry and external services.

Best for

Fits: teams that want one private chat entry point over local and cloud models, with RAG, tool use, multi-user permissions and a self-hosted data boundary. Does not fit: zero-ops SaaS, or procurement that requires a vendor SLA.

Licence and terms of use

BSD-3-Clause based, with a branding clause from v0.6.6: you may not remove, alter or obscure the Open WebUI name, logo or UI marks, except with 50 or fewer users in a 30-day period, written permission as a contributor, or an enterprise licence that explicitly allows rebranding. Code up to and including v0.6.5 remains pure BSD-3.

When something fails

Account and permissions · Rate limits and retries · File-reading issues

Top misconception

  • Treating Open WebUI as the model itself — it is only the front end; connect Ollama or an API
  • Assuming BSD-3 allows white-labelling — from v0.6.6 the branding cannot be removed, and over 50 users needs an enterprise licence
  • Calling self-hosting zero-ops — upgrades, backups, keys and the vector store are yours
