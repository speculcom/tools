Model & openness

Official model-selector page: auto routing (Auto smart routing ~0.5×), tiers (Ultimate ~2.0× deep reasoning, Fast low-cost quick) or direct model selection, with the Credit rate shown before sending; the Lite tier only supports Auto/Efficient and a curated model list. The official docs state you can bring your own API keys: after adding custom models under Settings → Models, the task/Agent/automation selectors can all use them (Custom Models page). There are also two release notes — "model consumption reference factor adjustment notice" and "Lite model tier retirement notice" — factors and tiers change; the client is authoritative.

Where it runs

The official family page (What is Qoder) gives the product matrix: Qoder (an integrated agentic workspace), Qoder IDE (the Editor window for AI-assisted coding / multi-file changes), a JetBrains plugin (completion/Ask/Agent/MCP/project rules), Qoder CLI (a terminal coding agent, connectable to scripts and automation), Cloud Agents (a fully managed cloud sandbox: define Agent/Environment via API, start Sessions, stream results back), QoderWork, QoderWake, Agent SDK. The official positioning is "agentic platform for real work" — understand the task and context → plan → execute with tools → verify → iterate, an end-to-end loop.

Local files

The IDE/plugin/CLI forms work with local code and projects; the CLI's official line: "understand your entire codebase, write and modify code, run commands"; Cloud Agents run in a vendor-managed cloud sandbox (official Overview: no building your own agent loop, no managing the tool-execution sandbox, no managing long connections). Cloud Agents can mount your own Alibaba Cloud OSS buckets at /mnt/buckets/<name> (Beta, up to 8 buckets, read-only or read-write; official Storage Buckets page); Sessions also expose archive/delete APIs, while a fixed retention period is not promised in the official docs.

Tasks after shutdown

Cloud Agents is the official managed surface: fully managed runtime, Sessions run in the cloud, results stream back in real time; the Quest window in Qoder IDE (an async task workflow) was officially retired at 2026-10-15 23:59 UTC+8 — the official notice gives a timeline and migration advice (move to Qoder or keep using the Editor window). The CLI ships scheduled tasks: standard five-field cron interpreted in the CLI host time zone, with task definitions/execution limits/auto-expiry documented in the official Scheduled Task Reference; session logs default to ~/.qoder/projects/<project/session-id>.jsonl.

Tools & extensions

The official extension surface has pages: Connectors (connector marketplace or custom MCP servers), Skills (find/install/create reusable task capabilities), Subagents (expert Agents provided by extensions), Plugins, a custom-extension publishing guide (personal Skill/Plugin/custom MCP); the official marketplace republishes Cloud Agents as Plugin/Skill/MCP connectors for other AI tools to plug into; Repo Wiki (generates project knowledge from a code repository for use in tasks).

Context & memory

The memory mechanism has an official page (Memory: letting Qoder reuse stable preferences and project context across later tasks); Repo Wiki generates repository knowledge; rules/project settings. Experts Mode (a requirement auto-decomposed, multiple expert Agents developing in parallel) has an official page and customer-case narratives. CLI session logs default to ~/.qoder/projects/<project/session-id>.jsonl, with state.json holding state; QODER_CONFIG_DIR can relocate the root and --delete-session removes a session (official CLI Sessions page).

Permissions & limits

The official "Access Permissions" page: pick the permission mode before sending a task / during execution, default Ask for approval (key operations request approval), covering files, terminal, network and enabled tools; changing the permission mode does not change the task's workspace or execution mode. The account system uses a qoder.com account; on the enterprise side the official docs cover Teams/Enterprise: SAML 2.0/OIDC SSO, four roles (Admin / Config Admin / Member / Directory Member), and an Admin-only audit log that records administrative-operation metadata, not business content — see SSO / Members and Roles / Audit Log.

Best for

Fits: one account covering the whole "IDE+plugin+CLI+cloud" agentic coding loop, the Repo Wiki/memory/Skills context system, BYOK to add your own models, Cloud Agents running long tasks managed. Does not fit: those looking for a domestic compliance narrative (the international line uses qoder.com accounts and overseas endpoints; the domestic line is Qoder CN — see the qoder-cn dossier), or anyone depending on the old Quest window workflow (retired).

Name history

Qoder and Qoder CN (formerly Tongyi Lingma) share the Qoder brand but are two product lines: the domestic line qoder.com.cn (dossier qoder-cn), the international line qoder.com (this dossier). The docs.qoder.com customer-case pages mention "Alibaba Qoder" and a "Qoder workshop hosted by Alibaba Cloud", pointing at the same Alibaba umbrella; the official docs document the two lines separately, so this dossier records them separately and does not infer feature equivalence.

Top misconception
