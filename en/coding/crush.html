A TUI coding agent in the Charm ecosystem that runs in your terminal. Its MCP section describes three transport options, and it ships an official subscription plan, Hyper.

Hyper is its own paid provider, so two cost models coexist. The license on GitHub is NOASSERTION, so commercial use is not something you can assume.

When to use it, when not to

Several kinds of people fit:

  • Users who like the Charm ecosystem's terminal experience (TUI aesthetics and interaction)
  • People who need to switch between several providers, or want the official Hyper subscription
  • People who want to switch models mid-session without losing context (the official README promises exactly this)
  • People who want local models and want to declare their context window explicitly
  • People who need all three MCP transports supported

Not a fit for scenarios needing a clear open-source licence for redistribution — GitHub reports NOASSERTION and the terms were not verified.

Model & openness

It ships no model of its own — all models are BYOK, but many providers can be connected.

The official README gives the full list and several ways to switch. It includes Charm's own subscription offering Hyper.

Official README wording:

Official wording: "Hyper, from Charm, is the official Crush provider. It's subscription-based"

The official README also mentions Hyper has a free tier, and zero data retention (ZDR).

Besides Hyper, providers named in the official README:

  • Anthropic, OpenAI, Gemini, OpenRouter
  • Vercel AI Gateway, Z.ai, MiniMax, Synthetic
  • Hugging Face, Cerebras, io.net, Alibaba
  • Groq, Avian, OpenCode Zen & Go
  • Google Cloud VertexAI, Amazon Bedrock (Claude)
  • Azure OpenAI, Moonshot

Each has a corresponding environment variable (e.g. ANTHROPIC_API_KEY).

Three ways to switch:

  • connect any compatible endpoint: the command is provider add, arguments in order are provider id, --type, --base-url, --api-key, where --type only accepts openai-compat or anthropic
  • register a model: via model add <provider>/<id> --context-window …, declaring how long a context the model supports
  • set default models: model large / model small set the default large and small models respectively

The default catalog comes from the officially maintained Catwalk repository and updates automatically.

Local models: officially supported are llamacpp, omlx, lmstudio, litellm, ollama, with automatic model discovery.

The local connection example in the official README:

provider add ollama --type ollama --base-url http://localhost:11434/v1/

Where it runs

A local process, running in the terminal, with a TUI built on Charm's terminal libraries.

Install options include Homebrew, NPM, Arch Linux, etc.

Multiple clients can share one workspace. A second client pointing at the same working directory attaches to the existing workspace, sharing the session list, message history, permission queue, LSP and MCP state.

But every new invocation starts a new process. So the first-wins rule affects the shared workspace's configuration.

Local files

By default it reads and writes only within the project workspace; there is no full semantic index. The scope is bounded by two things: LSP, and ignore rules.

Ignore boundary: official README wording "Crush respects .gitignore files by default". A .crushignore with the same syntax can add exclusions, placed at the project root or in subdirectories.

Initialization: crush init analyzes the codebase and generates a context file. Default name AGENTS.md; rename or relocate via initialize-as.

Symbol-level capability depends on attached LSPs.

Official README wording:

Official wording: "LSP-Enhanced: Crush uses LSPs for additional context"

Configure manually via lsp add go --command gopls, or let auto-lsp configure them automatically.

Context files: the global ~/.config/crush/CRUSH.md (Crush-specific) and ~/.config/AGENTS.md (cross-tool standard) are injected automatically; paths can be added via global-context-path.

Unknown: the indexing algorithm and time cost on large repos are not stated by the official docs. (README and docs/config both checked.)

Tasks after shutdown

It cannot keep running after shutdown. This is the form-factor boundary of a local CLI, not a defect.

Multi-client workspace sharing is not background execution. The official README explains: running crush serve exposes a local backend, and multiple TUI clients join the same workspace via --cwd. But the workspace's lifecycle follows the client streams.

Official README wording:

Official wording: "A workspace lives as long as at least one client has an SSE event stream open against it." "When the last stream disconnects, the workspace is torn down."

That is, when the last stream disconnects, the workspace is torn down.

The execution environment is your local machine. crush serve is also a local backend. Neither the official README nor docs/config has any vendor-hosted wording, nor any "keeps running after shutdown" claim.

Interruption is recoverable: sessions are saved per project. You can resume via the session selector, and the exit banner also prompts resume. But the process itself does not stay resident.

Tools & extensions

MCP is explicitly supported, all three transports, and it is the most completely documented.

The official README states support for http, stdio and sse. This is one of the few entries in this section that spells out MCP transports clearly.

It also supports a custom config file ~/.config/crush/crushrc (Windows: %USERPROFILE%\.config\crush\crushrc), and config can be overridden by machine conditions (the example branches on $HOSTNAME).

Models can be added manually, with the context window declared explicitly. The command given in the official README is model add ollama/llama3.3 --name "Llama 3.3" --context-window 128000.

Context & memory

The context mechanism has three parts: sessions, global context files, LSP.

Sessions: official README wording "Session-Based: maintain multiple work sessions and contexts per project" — multiple work sessions and contexts per project, switchable and resumable.

Context survives model switches: official README wording "Flexible: switch LLMs mid-session while preserving context" — i.e. the official docs explicitly promise switching models does not lose context.

Context files: the global ~/.config/crush/CRUSH.md and ~/.config/AGENTS.md are injected automatically; on the project side crush init generates AGENTS.md; context-path / global-context-path can add more.

Compaction strategy verified. The auto-summarize boolean in docs/config, official description:

Official wording: "automatically summarize long conversations"

The command palette also has "Summarize Session" to compact the current session manually.

LSP provides additional context (see local_files).

Permissions & limits

By default it asks before every tool call. Official README wording:

Official wording: "By default, Crush will ask you for permission before running tool calls"

In config, permissions allow view edit skips confirmation for specific tools.

The official caution on the no-confirmation mode is Use this with care.

There is also a --yolo switch that relaxes approvals wholesale. But this flag follows the "first-wins" rule. Within the same cwd, the first client's setting locks the behavior of later clients. On mismatch, a debug log line records the discrepancy. Mind this rule when multiple clients attach to the same directory at once.

Credential config also supports per-machine branching (overridable via $HOSTNAME conditions).

MCP: all three transports spelled out

Official README wording:

"Extensible: add capabilities via MCPs (http, stdio, and sse)"

This one deserves its own note. Most tools just say "supports MCP"; Crush lists all three transports outright.

Cross-checked against this site's own observations of the tools section: quite a few reference servers only support stdio. They do not support remote transports. So a CLI tool that explicitly supports http has a larger extension-compatibility surface than one might assume.

The license status deserves a flag

The license field returned by the GitHub API is NOASSERTION, i.e. unrecognized. It is neither MIT nor Apache-2.0.

This means:

  • do not assume closed-source redistribution is allowed
  • check the LICENSE file in the repository yourself before citing
