8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

Official "Choosing models" page: pick the v0 model in the in-chat model picker, or add custom models from the AI Gateway catalog. The updated picker and custom models target Enterprise teams (custom models need team-owner approval). The model in a session follows the most recent response until you switch. In-app AI features have a separate ai-models integration page (Grok/fal/Deep Infra etc.).

Where it runs

Web form (v0.app); VM-backed chats run in isolated VMs on Vercel Sandbox (official sandbox page: hosts project files / runs previews / executes commands; state does not leak between chats; it replaces the older in-browser environment). Coding agents are pre-installed in the sandbox (official page: run CLIs like claude directly in the terminal, alongside v0's built-in assistant in the same project).

Local files

Projects live on the v0 platform. The GitHub integration is an official page: code goes into your repositories, branch isolation, PRs and CI follow the standard flow; existing GitHub repositories can be imported (git-import page). The official states explicitly that GitHub sync only moves code — it does not grant deployment permission via GitHub (deployment permission follows Vercel roles).

Tasks after shutdown

The deployment line is persistent: preview deployments build per branch, publish updates the Vercel production deployment (official deployments page); deployment errors can be diagnosed and fixed via "Fix with v0" reading the logs (agentic-features page). Whether build tasks keep running after the page is closed: outside the official product pages.

Tools & extensions

Agent capabilities are official pages: web search, browser use, terminal commands, error fixing, external tool integration — all inside the sandbox. Two MCP lines (bring-your-own MCP servers with a preset list / Remote MCP via Marketplace integrations). Database integrations: Supabase/Blob/Neon/Upstash; Figma import; v0 itself can also act as an MCP server called by other agents.

Context & memory

The code viewer (browse/edit code, review changes, add comments as next-round context); Design mode visually selects elements, edits styles and writes back to code; projects organize multiple chats. Cross-session memory: outside the official product pages.

Permissions & limits

Tool-call permissions have three modes (Ask/Auto/Full) + Agent Permissions rules (MCP page and agentic-features page framing). The enterprise side goes through Vercel Enterprise: seats/v0 roles (Builder etc.) and Vercel team roles are managed separately (enterprise page). Security page official framing: do not trust LLM-generated code — security analysis before execution, sandbox isolation, input validation, adversarial testing.

Best for

Good fit: Next.js/Vercel-stack teams (the deployment chain is natively connected), wanting real terminals and pre-installed agents inside a sandbox, unifying enterprise seats with the Vercel account system.

Not a fit: stacks outside the Next.js/Vercel ecosystem (the deployment line is part of the product semantics), non-Enterprise wanting custom models.

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • The deployment chain is bound to Vercel: publishing goes through the Vercel project and domains (official deployments page) — GitHub sync only moves code; deployment via GitHub/Vercel CLI follows your Vercel role, two permission systems not to be conflated (the official page warns explicitly)
  • Custom models (the AI Gateway catalog) are an Enterprise-team feature requiring owner approval — the model menu on regular plans is narrower than the docs read like
  • The sandbox has two generations: VM-backed and the older in-browser one (the official sandbox page states the replacement) — 'runs in the browser' behavior described in older tutorials may be outdated
