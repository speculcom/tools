Trae is ByteDance's three-client AI IDE (desktop / web / mobile): dual windows on desktop (Agent/IDE) with SOLO mode for whole-task delegation, built-in multi-model plus custom keys, Privacy mode and sandboxed execution as official switches.

When to use it, when not to

Fits: one task flow across desktop+web+mobile, whole-task delegation via SOLO mode, starting with built-in multi-model without configuring your own keys. Not a fit: expecting the domestic and international editions to match (two separate lines); fully offline use (cloud tasks are part of the product semantics).

8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

The official docs (docs.trae.ai/ide/models) explicitly state built-in multi-model support, plus adding custom models via API key. The built-in list changes with versions (the list captured in the 2026-10-08 pass includes GPT-family / DeepSeek / Gemini-family entries; not enumerated as a complete list). The international edition (trae.ai) and domestic edition (trae.cn) differ in model surface — each official page is authoritative.

Where it runs

Official framing: three clients — Desktop (a standalone app that does not depend on TRAE IDE to run; supports local and cloud tasks), Web (a no-install cloud environment), Mobile (dispatch and manage tasks; auto-switches to cloud execution when the device is offline). Desktop gives dual windows: the Agent window and the IDE window; inside the IDE window you switch between IDE mode and SOLO mode.

Local files

The official security page states explicitly: codebase files always stay on the local device (in the Privacy mode context). Sandboxed execution puts agent-generated commands into a restricted environment (file-access control + high-risk command interception). Data boundaries of the cloud-task line: not itemized in official docs one by one.

Tasks after shutdown

The background/async surface is part of the official narrative: Desktop supports handing long tasks to the cloud, Mobile monitors task progress across devices, offline auto-switches to cloud execution — task state syncs across the three clients (official docs framing).

Tools & extensions

The agent can search the codebase, plan in multiple steps and call tools. Custom agents can configure prompt / MCP servers / tool sets (the official docs state the MCP configuration surface explicitly). The CUE completion line (multi-line edits / next-edit prediction) has its own page.

Context & memory

Context can take files/folders/snippets/terminal output/repos/docs/web pages (official docs); no separate cross-session memory entry, and reuse relies on projects and rule files.

Permissions & limits

Account system (ByteDance-side accounts). Privacy mode toggle — when on, the official states your chats / code / outputs are not used for analysis, optimization or training. Sandboxed-execution toggle. Enterprise/team control surface: not itemized in official docs one by one.

Best for

Good fit: desktop + Web + mobile sharing one task flow, SOLO mode for whole-segment delegation, built-in multi-model to start without configuring your own keys.

Not a fit: expecting the domestic and international editions to be feature-identical (they are two lines), wanting fully offline use (the cloud-task line is part of the product semantics).

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • International trae.ai and domestic trae.cn are two lines — don't infer model lists or feature sets from one to the other
  • 'Code never leaves your machine' is the official claim in the Privacy-mode context — the data boundaries of cloud tasks / web / mobile lines need separate reading (not verified line by line)
  • SOLO mode means 'AI takes the lead' through the whole flow (official wording) — a completely different control assumption from IDE mode; switch by task complexity
