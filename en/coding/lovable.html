Lovable is Sweden's full-stack AI app builder: natural language in, a working app out with frontend, database, auth and hosting — the built-in backend runs on the Supabase open-source foundation, Git two-way sync puts code in your own repo, and the official line is 'never locked in'. But you cannot pick the build model, and the training-data policy splits by plan.

When to use it, when not to

Fits: idea-to-launch in one place, Git sync into your own repo, enterprise governance (SSO/SCIM/audit/EU inference). Not a fit: wanting to pick the build model; wanting to download the codebase back for free (a paid-plan feature).

8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

The official FAQ states plainly: build-side models are chosen by Lovable and updated automatically; users cannot pin a specific model for Build/Plan/Chat modes. AI features inside your own app can pick models from the supported list on the official AI features page (chat/image/video/audio each have their own pages). Enterprise has EU inference (model requests stay on European endpoints).

Where it runs

The web app is the primary form; the official pages also list a desktop app, iOS/Android mobile apps, the Lovable API (publish projects / manage workspaces), and the Lovable MCP server (plug Lovable into IDEs and external agents). Projects are built inside workspaces; one project maps to one application whose codebase can be synced out (per the official welcome page).

Local files

Project code lives inside the Lovable platform; Git sync provides automatic two-way synchronization with GitHub/GitLab/Bitbucket repos (stated on the official page), and Download codebase is available (paid plans). The built-in backend (Cloud) is hosted by Lovable, built on the open-source Supabase base (stated on the official cloud page: database/auth/storage/edge functions, no need to self-host Supabase). The official "deployment, hosting and ownership" page stance is "you are never locked in": export code, migrate data, self-host part or all of the stack.

Tasks after shutdown

The hosted surface is part of the product semantics: hosted applications scale automatically with traffic, database instances are adjustable (official cloud page); project monitoring checks apps on schedule catching bugs and visitor errors; Subagents split research/code exploration of complex tasks into parallel work. Whether build tasks continue after closing the browser has not been verified in any official statement.

Tools & extensions

The connector system has official pages: app connectors (apps calling external services), app user connectors (end users connecting their own accounts), custom REST connectors, chat connectors (MCP servers, including custom remote MCP and MCP registries); built-in security scanning + Aikido/Wiz integrations; Code mode has a built-in code editor; published apps can be reverse-published as MCP servers.

Context & memory

Project sessions have three modes: Chat (discuss) / Plan (write a structured plan first, then execute) / Build (implement directly and verify); cross-project referencing reuses implementations across projects; projects can be imported from Replit/Bolt/v0 etc.; design systems can be plugged in. A cross-session memory mechanism has not been verified in any official statement.

Permissions & limits

Account + workspace system; the enterprise surface has official pages: SSO (Okta/Auth0/Entra/OIDC/SAML), SCIM user provisioning, audit logs (exportable to SIEM/cloud storage), Action center (approving release requests), workspace security center and sensitive-data scanning; project visibility (private/internal/public) and RLS row-level security policies control data access; personal 2FA.

Best for

Fits: one-stop from idea to a full-stack app with database/auth/hosting; wanting Git two-way sync to put code in your own repo; an enterprise governance narrative (SSO/SCIM/audit/EU inference). Does not fit: people who want to pin the build model (the official FAQ says you cannot); people wanting to download the codebase back locally for free (Download codebase is a paid-plan feature).

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • You cannot pick the build-side model (official FAQ: Lovable chooses and auto-updates models for Build/Plan/Chat modes) — a completely different experience from IDE-style model pickers; what you can pick are the AI-feature models inside your own app
  • Training policy splits by plan: the official FAQ states that from 2026-09-09 Free/Pro customer data may be used for training by default (switchable off in account settings), while Business/Enterprise is excluded by default — don't flatten the data boundary into one answer for the whole product
  • 'Code is exportable' does not mean 'the backend comes free': the built-in backend is Lovable-hosted on the Supabase open-source foundation; database migration and external hosting follow the official migration paths (the deployment-hosting-ownership page gives routes and boundaries)
