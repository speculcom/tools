Where it runs

Important change: Windsurf has been renamed Devin Desktop —

the official docs title the stable-release notes "agent-native editor"; the download page offers macOS (Apple Silicon / Intel), Windows (arm64 / x64) and Linux x64 for Debian.

Folder selection on SSH or WSL hosts is supported.

Local files

A local editor that reads and writes the workspace directly. Official context-awareness page wording: "The entire local codebase is then indexed (including files that are not open)" — the whole local codebase is indexed by the RAG context engine, with snippets fetched on demand at retrieval time.

The Pro tier has larger index caps and context length; Teams / Enterprise can index remote repositories.

Files in .gitignore are not exposed to Cascade by default (Cascade Gitignore Access is off by default); .codeiumignore can exclude paths.

Fast Context is a dedicated retrieval subagent (SWE-grep / SWE-grep-mini models, using only grep / read / glob, up to 4 rounds, at most 8 parallel tool calls per round). You can also drag files into the panel or send a selection to chat.

Tasks after shutdown

True background comes from Devin Cloud: official windsurf/devin page wording "Each Devin session runs on its own VM with a desktop, browser, and computer use, so it can keep working after you close your laptop" —

each Devin session runs on its own cloud VM, keeping working after you close the laptop. You can plan locally with Cascade and hand it to Devin cloud for implementation in one click, with sessions appearing in the Agent Command Center.

Local Cascade and Devin Local run on your machine (Devin Local "operates on your machine") and need the client resident.

Note Devin Cloud access is rolling out, and Enterprise requires an admin to enable it.

Tools & extensions

Supports the Agent Client Protocol (ACP) — the docs site has "Agent Client Protocol (preview)" and "Building a custom ACP agent" as dedicated pages, indicating ACP is in preview.

MCP support has one important detail:

the changelog records that MCP servers passed in by ACP clients can now be used and listed by the agent, including HTTP and SSE type MCP servers.

Context & memory

The Memories mechanism is verified (official cascade/memories page): Cascade automatically generates and stores memories during conversations, and you can ask it to "create a memory";

memories bind to the workspace, stored locally at ~/.codeium/windsurf/memories/, not committed to the repo, consuming no credits, auto-retrieved when Cascade deems them relevant.

For cross-session persistence the official recommendation is Rules (global / workspace / system three levels, .windsurf/rules/*.md) or AGENTS.md. There is also session history:

the changelog records that switching back to one of the 10 most recently viewed sessions shows its transcript immediately.

The underlying context engine is RAG (official M-Query retrieval).

Permissions & limits

There are explicit security mechanisms and CVE fix records: the changelog records a fix for a Restricted Mode bypass (CVE-2026-81376) — previously only dotted-form restricted workspace settings were checked, now nested-object form is checked too.

This one is worth noting: Restricted Mode could once be bypassed via nested objects.

Best for

People who need multiple model providers to choose from (not locked to a single model); people who need ACP to plug in custom agents (note it is preview); people who need remote-host (SSH / WSL) support. The Free tier fits people who only need unlimited inline edits and unlimited Tab completion.

But the changelog has one notable advance:

MCP servers passed by an ACP client ... are now usable by the agent
and listed in ..., including for HTTP and SSE MCP servers

MCP servers passed in via ACP clients are now usable, including HTTP and SSE types.

This is stronger than what the official reference servers can do — in this repository's tools section, most official servers only support stdio.

Security: a Restricted Mode CVE happened

The changelog records one fix:

Restricted Mode blocks restricted workspace settings written in
nested object form, not just the dotted form (CVE-2026-81376).

What it means: Restricted Mode used to block only restricted workspace settings written in dotted form (a.b.c); now it also blocks nested-object form.

This deserves a standalone record, because it reveals a real permission bypass: Restricted Mode could once be bypassed via nested-object form.

For an AI coding tool, Restricted Mode is an important security boundary, and the existence of such a fix reminds us: this boundary was once more fragile than it looked.
