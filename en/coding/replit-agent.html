Replit Agent is the cloud-IDE agent from plain language to a deployable app: it builds the project, sets up infrastructure, tests, and deploys in one chain; Free/Power/Max modes pick tiers rather than bare models, with checkpoints as the rollback safety net.

When to use it, when not to

Fits: idea straight to a deployable app (database/deploy included), non-engineer prototypes, multiple artifacts sharing one backend. Not a fit: your existing codebase as the main battlefield; fully self-selecting models.

Model & openness

Choose by "mode" rather than by bare model: the official docs list four modes — Free/Auto/Power/Max. Free is the free tier within plan allowances, Auto routes automatically, Power/Max are paid tiers (Max uses the strongest frontier models). Which models sit behind each tier is shown live by the in-account Model selector (official framing: the model list is account-specific and shifts with plans and staged rollouts). Enterprise workspaces have only the Auto mode; admins can manage model access via Enterprise model controls.

Where it runs

Built-in agent in a cloud IDE: projects, dependencies, databases and deployments all live on Replit cloud. The official docs state the Agent "writes code, sets up infrastructure, tests results" and automatically creates checkpoints you can roll back to. Desktop/mobile are entry points; execution happens in the cloud.

Local files

Code and data default to living in Replit cloud projects, not on your machine. Code and projects migrate through GitHub/GitLab repositories (official Connect your repository / Contribute code); platform-hosted databases, Auth and object storage data move out under each service's docs. External services (BigQuery/Slack/Notion/Linear etc.) are connected via official connectors, pulling data directly from chat.

Tasks after shutdown

There is a background-task surface: the official docs give quota lines of Core 1 / Pro 10 "Active background tasks" — background tasks are part of the product semantics. Plan mode produces a task list for approval before work starts.

Tools & extensions

The agent ships with the full chain — create projects, install dependencies, test, deploy. The connector surface (BigQuery/Slack/Notion/Linear etc.) follows the official Integrations directory for the day. MCP both ways: the Agent can connect prelisted or custom MCP servers (official Connect via MCP), and Replit also offers an MCP Server for compatible clients (Connect through MCP).

Context & memory

Multiple artifacts within a project share the same backend and data (web/mobile/slides/video in one project); checkpoints provide a state-rollback surface. Cross-project memory is not part of the official docs narrative.

Permissions & limits

Account + plan system. Paid actions require confirmation (official FAQ: "paid actions require confirmation before they start"; when the Free tier runs out it offers "Allow once" for one-time approval). Enterprise has model-access controls. Deployment yields a Replit-hosted URL.

Best for

Good fit: going from natural language straight to a deployable app (database and deployment included), non-engineers building prototypes, wanting checkpoint rollback as a safety net.

Not a fit: making your existing codebase the main battlefield (its main axis is idea → new project), wanting full self-selection at the model layer.

When something fails

Authentication and permissions · Invalid tool inputs · Invalid output format

Top misconception

  • Treating Replit Agent as 'a coding agent installed into your existing repo' — the official positioning is idea-to-new-project (infrastructure included); collaborating on existing codebases is not the docs' main narrative
  • Free/Power/Max are modes, not model names — which models sit behind each tier shifts with official changes; don't treat tiers as a fixed model list
  • Artifacts and data live in Replit's cloud by default — export/migration paths exist but the boundaries are yours to verify (not verified line by line)
