An open-source IDE extension with fully self-configured models — VS Code extension, JetBrains plugin and a cn CLI over one agent core, with models configured freely in config.yaml. The official model-provider list spans Anthropic, Azure AI Foundry, Amazon Bedrock, DeepSeek, Gemini, Mistral, Ollama (local models), OpenAI, Vertex AI, xAI and "More (30 items)".

The extension itself is free; the commercial line is a separate product. The repository README states "Apache 2.0 © 2023-2026 Continue Dev, Inc." and there is no license fee for the extension — model calls are yours to pay (BYOK, or local Ollama). The commercial line is now Continuous AI at hub.continue.dev/pricing: Starter $3 / million tokens pay-as-you-go, Team $20 / seat / month (including $10 in credits per seat), Company custom (SAML/OIDC, BYOK, SLA).

But the official status has changed. Continue was acquired by Cursor; the homepage continue.dev now serves an acquisition notice, the old Hub pricing page continue.dev/pricing returns 404, and the repository is marked read-only. The last releases are the final 2.0.0 line for the VS Code extension, CLI and JetBrains plugin.

When to use it, when not to

A fit for three groups:

  • People who need model freedom (many providers, including local models via Ollama) and do not want to be locked to one vendor.
  • People already working in VS Code / JetBrains who want an open-source, auditable extension.
  • People who want the same agent in the terminal and in CI (cn -p).

Not a fit for scenarios needing ongoing maintenance and long-term evolution — the upstream repository is read-only and the company was acquired by Cursor, so it persists only in a "code is still freely usable" form. Also not a fit for anyone relying on official support and continued fixes.

Model & openness

Models are fully self-configured — this is its most core positioning.

Providers listed on the official model providers page:

  • Anthropic
  • Azure AI Foundry
  • Amazon Bedrock
  • DeepSeek
  • Gemini
  • Mistral
  • Ollama (local models)
  • OpenAI
  • Vertex AI
  • xAI

That page also points to "More (30 items)".

Configuration lives in config.yaml under models, with fields provider + model + apiBase.

roles (chat / autocomplete / embed / rerank / edit / apply / summarize) can be set, plus capabilities (tool_use is required for Agent mode; image_input also exists).

Contrast with ./cursor.md: Cursor can only use models in its catalog; Continue can point at any provider.

Tool-calling quality after switching across providers: the official pages give no comparison.

Where it runs

An IDE-extension form, not a standalone editor.

The officially listed forms are the VS Code extension and the JetBrains plugin, plus a CLI (cn).

Official docs first sentence: "Open source AI code assistant for VS Code and JetBrains"

Official README recommendation: "We recommend using the Continue CLI instead of the JetBrains plugin"

The three forms share the same agent core. Official CLI page wording: "the same agent that powers the Continue IDE extensions". The CLI needs Node.js 20+ or a bundled runtime.

This entry covers only the extension form; the terminal form's capabilities are in tools and background.

Local files

Reads and writes inside the IDE workspace; changes are presented as diffs.

Context comes from explicit references, not implicit full indexing. The official Chat context page lists context providers such as @Files, @Terminal, @Git Diff, plus highlighted code (VS Code cmd/ctrl+L, JetBrains cmd/ctrl+J) and the current active file.

Two config directories: MCP at .continue/mcpServers/, rules at .continue/rules.

How the codebase semantic index is implemented is not stated by the official side (checked the docs.continue.dev homepage and the Chat context-selection pages).

Tasks after shutdown

The extension form has no "keeps running after shutdown" capability.

It is an editor / IDE plugin, alive with the IDE process; close the IDE and it ends.

The official docs also describe no cloud execution surface (verified: checked the docs.continue.dev homepage, Agent quick-start and CLI quickstart pages)

The only async form is the CLI's headless mode. cn -p "..." runs once and outputs to stdout.

Official wording: "Use this in scripts, CI/CD, and git hooks"

Tools & extensions

The tool surface is "three mode tiers + MCP".

The official Agent page shows three options under mode switching:

  • Chat (no tools)
  • Plan (read-only tools)
  • Agent (all tools)

Cmd/Ctrl + . cycles through them.

MCP is officially supported (official MCP deep-dive page): configured under mcpServers in config, can live in the .continue/mcpServers/ directory; three transports supported:

  • stdio
  • sse
  • streamable-http

JSON MCP configs from Claude / Cursor / Cline can be reused directly.

The official stresses: "MCP can only be used in the agent mode"

The CLI side additionally has --mcp <slug>, --agent <slug>, --rule. Extension mechanisms also include context providers, rules and custom prompts.

Context & memory

Context is explicitly selected, not auto-indexed (see local_files).

At the session level: the CLI supports --resume replay; the official CLI headless page says cn -p --resume

official wording: "replays the previous session's history"

Cross-session long-term memory is carried by rules, context providers and assistant configuration; config.yaml has a data field.

Context-window size follows the chosen model; the official gives no unified number on the pages checked (checked the Agent quick-start and config.yaml reference pages).

Permissions & limits

Asks per tool by default; policies can loosen it.

On the IDE side, official Agent quick-start wording: "By default, Agent mode will ask permission when it wants to use a tool"

tool policies can set specific tools to automatic or excluded. In the IDE, click Continue to allow or Cancel to deny.

The CLI side differs. Official headless page wording: "tools that would normally prompt for approval (ask permission) are automatically excluded"; to write files you must explicitly pass --allow Write --allow Edit (or --allow "*"), plus --readonly (Plan), --auto, --exclude.

telemetry: the repository README says the final 2.0.0 release came "removing anonymous telemetry".

Whether data is used for training: not stated on the official pages checked.

MCP and permissions

MCP officially supports three transports: stdio, sse, streamable-http; configuration lives in .continue/mcpServers/, and JSON MCP configs from Claude / Cursor / Cline can be copied in directly. One hard official limit to note: "MCP can only be used in the agent mode".

Permission stance splits by side:

  • IDE: official wording "By default, Agent mode will ask permission when it wants to use a tool"; tool policies can set tools to automatic or excluded;
