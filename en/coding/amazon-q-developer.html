8 questions, one table

8 questions, each comparable item by item with its peers.

Model & openness

The official what-is page states explicitly: Powered by Amazon Bedrock — models are invoked through Bedrock; the models answer questions over Bedrock-augmented AWS content; includes automated abuse detection (a Bedrock-side safety mechanism). Users cannot self-select the underlying model (the official gives no model picker); BYOK does not apply — billing and accounts go through AWS.

Where it runs

Two form lines: the IDE plugin (conversation, inline completion, generating new code, security vulnerability scans, language upgrades/debugging/optimization and other code transformations inside VS Code / JetBrains) and the command line (official CLI page original: "The Q CLI has become the Kiro CLI" — the CLI line has migrated to the Kiro brand). The positioning is a generative assistant for "understanding, building, extending and operating AWS applications"; AWS architecture/resources/best-practices/docs Q&A is the official main line.

Local files

The IDE plugin processes code inside your local IDE (completion/generation/scanning happen within the plugin workflow). Whether code leaves the machine to the service side is not verified one by one (Bedrock inference being service-side is a settled fact). The Q&A surface references your AWS resource context (official framing: cited answers grounded in your AWS resources and architecture).

Tasks after shutdown

No official long-running async task surface (no background-continuation statement verified). Agentic coding capabilities are pointed by the official to Kiro (EOL announcement original: "For capabilities similar to Amazon Q Developer IDE plugins, explore Kiro… including agentic coding, chat and MCP support").

Tools & extensions

Built-in IDE-plugin capabilities listed officially: code conversation, inline completion, generating new code, security scans, code transformations (Java version upgrades etc.), debugging and optimization. MCP support sits on the Kiro side (the EOL announcement names Kiro as having MCP support); MCP on the Amazon Q plugin side is not verified.

Context & memory

Context is anchored on the AWS side: your AWS resources, architecture, documentation and support content (official what-is page framing); inside the IDE it follows the current project. Cross-session memory: not verified to an official statement.

Permissions & limits

Accounts and billing go through AWS (IAM/account system). Approval details for the IDE plugin operating on local files are not verified one by one. Bedrock-side automated abuse detection is the officially stated safety mechanism.

Best for

Good fit: heavy AWS users — architecture/resource/best-practice questions with citations, and official-signature transformation tasks in the IDE like Java upgrades and security scans.

Not a fit: wanting agentic coding's new capabilities (the official clearly points to Kiro), betting long-term on the IDE plugin line (support ends 2027-04-30, see pitfalls).

Top misconception

  • Official EOL notice: support for Amazon Q Developer IDE plugins ends 2027-04-30 (AWS End of support notice); the official alternative is Kiro (agentic coding/chat/MCP) — new-project IDE choices should go straight to the Kiro dossier
  • The CLI line has been renamed: the official CLI page says 'The Q CLI has become the Kiro CLI' — old Q CLI tutorials actually point to Kiro CLI (kiro.dev/docs/cli)
  • The product is not dead (site and docs measured 200 on 2026-10-22, lifecycle still active) — 'an EOL notice exists' and 'it is gone' are different things; the plugin keeps working during the transition window
