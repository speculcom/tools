Tools · Skills

Skills 是什么：能力包，不是提示词What Skills are: capability packages, not prompts

Skill 是把一套可复用的工作流、脚本和资源打成一个包。它和 prompt、MCP、agent 不是同一层东西；先分清边界，再决定要不要装。

先分清：Skill 是能力包，不是更长的提示词；MCP 是工具接口，agent 是执行主体。Skill 可以调用 MCP，也可以被 agent 加载。下面 12 条只做索引，不执行仓库脚本，也不背书安全与许可。

和 prompt 的分界

Prompt 是这一次对话里的指令；Skill 是跨会话可复用的能力包。Prompt 可以只有几句话；Skill 一般包含 SKILL.md、脚本、模板、参考资料和触发条件。

Skill 里的 SKILL.md 可以包含提示词，但它的重点不是“怎么说”，而是“按什么步骤做、用哪个脚本、产出什么、怎么验收”。

和 MCP 的分界

MCP 是工具接口：把外部服务暴露成模型能调用的工具，重点是协议、参数与权限。Skill 是能力包：告诉模型在什么场景、按什么顺序、调用哪些工具与脚本，最后怎么检查。

一个 Skill 可以调用 MCP 工具；一个 MCP server 也可以被多个 Skill 复用。两者不是替代关系。

和 agent 的分界

Agent 是一个会自己规划、调用工具、循环执行的主体；Skill 是它可加载的一份“操作手册”。Agent 可以选择加载哪个 Skill，但 Skill 本身不负责长期运行与调度。

把 Skill 当成“给 agent 的 SOP + 工具箱”，比当成“更长的提示词”更准确。

什么时候值得做成 Skill

同一套步骤每周重复、步骤里有固定脚本或模板、产出有明确验收标准、需要别人也能复现——这四种情况适合做成 Skill。

只写一次、没有固定步骤、不需要脚本的任务，写成 prompt 或清单就够了；不要为了“看起来高级”把一句话包成 Skill。
